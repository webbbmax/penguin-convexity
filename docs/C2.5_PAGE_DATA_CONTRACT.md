# 企鹅投研-凸性｜C2.5 页面与数据契约

状态：正式冻结  
适用版本：C2.5  
原则：页面只组合权威状态，不创建第二套任务真相。

## 1. 权威来源优先级

同一字段冲突时按下列顺序解释，不允许前端自行猜测：

1. Windows 计划任务当前定义与 `Get-ScheduledTaskInfo`。
2. 当前业务进程、单实例锁和未过期心跳。
3. C2.2/C2.4 现役作业状态、候选生产分片和数据库检查点。
4. 当前有效配置和暂停请求。
5. 已发布原子业务快照。
6. 历史运行记录。
7. 前端缓存或页面内状态仅用于显示，不能改变结论。

历史记录中出现 `running`，但缺少有效进程/锁或心跳过期时，页面必须显示“历史状态已过期”，不得显示当前运行。

## 2. 通用时间字段

| 字段 | 含义 | 禁止替代 |
|---|---|---|
| `observedAt` | 服务读取权威状态的时间 | 不能冒充业务数据时间 |
| `stateUpdatedAt` | 状态来源最后更新时间 | 不能冒充心跳 |
| `lastHeartbeatAt` | 活进程最后心跳 | 没有时不得合成 |
| `dataAsOf` | 业务数据对应时间 | 不能用页面构建时间代替 |
| `snapshotBuiltAt` | 快照生成时间 | 不能冒充数据对应时间 |
| `lastStartedAt` | 最近实际开始 | 计划时间不能替代 |
| `lastFinishedAt` | 最近终态时间 | 运行中必须为空或显示上一轮 |
| `nextDueAt` | 作业按配置应到期时间 | Windows 下一次检查时间不能替代 |
| `schedulerNextTriggerAt` | Windows 调度器下次唤醒 | 不能冒充具体作业必定运行 |

所有用户可见时间使用 Asia/Shanghai 显示，并保留机器 UTC 值供审计。

## 3. 通用任务对象 `ManagerTask`

每个任务必须返回：

```text
taskId, displayName, machineNames[], entryKind, lifecycleClass,
liveState, stateBasis[], capabilityBoundary, triggerModes[], schedule,
lastStartedAt, lastFinishedAt, nextDueAt, schedulerNextTriggerAt,
progress{kind,completed,total,percent,stage,message},
lastHeartbeatAt, checkpoint, chains[], sources[],
inputs[], outputs[], upstreamTaskIds[], downstreamTaskIds[],
affectedPages[], failure{code,summary,detail,affectedObjectCount,staleRisk},
controls[], disabledControls[], logs[], auditUrl, observedAt
```

规则：

- `progress.kind` 只能是 `determinate`、`indeterminate`、`not_applicable`。
- `total` 未知时必须为 `null`，不得写 0 后显示 0%。
- `percent` 只能由真实 `completed/total` 计算。
- `liveState` 与 `lifecycleClass` 分离。
- `stateBasis` 至少列出进程、锁、心跳、状态文件或 Windows 任务中的实际依据。
- 来源或链不适用使用 `not_applicable`，没有结果使用 `no_data`，不能混为失败。

## 4. 通用状态枚举

### 4.1 实时状态

`not_started`、`waiting`、`launching`、`running`、`pause_requested`、`safe_paused`、`partial`、`completed`、`failed`、`blocked`、`stale`、`disabled`、`unknown`。

### 4.2 生命周期分类

`scheduled_active`、`manual_on_demand`、`active_component`、`legacy_callable`、`dormant_compatibility`、`disabled`、`completed_one_off`、`startup_automatic`、`service_component`。

### 4.3 来源状态

继续使用 C2.4 七类：`success`、`no_data`、`quota_limited`、`source_failure`、`unsupported`、`configuration_missing`、`program_failure`。

## 5. 页面契约

### 5.1 管理者总览 `/workbench.html`

必须返回：

- `taskCountsByLifecycleClass` 和 `taskCountsByLiveState`。
- 唯一 Windows 调度器：机器名、中文角色、启用、运行、上次结果、下次触发。
- `screening`、`convexity_tracking`、候选生产、维护检查四个摘要。
- 最近完整成功、最新业务快照、页面读取时间。
- 六链 × 来源健康摘要。
- 当前规则版本、覆盖数量、即将到期覆盖。
- 最近异常、影响对象、待决策事项。
- 最近管理操作和下一批计划运行。

总览不得只列成功项，也不得用卡片替代详情入口。

### 5.2 全部任务 `/task-ledger.html`

必须返回完整 `ManagerTask[]`，支持按生命周期、实时状态、入口类型、链、来源、读写能力和风险筛选。默认不隐藏旧版、停用和失败项；允许管理者主动筛选。

页面同时显示：登记入口数、现场枚举入口数、遗漏数、多重登记数。遗漏数或多重登记数非 0 时显示红色阻断。

### 5.3 任务详情

稳定路由：

- `/new-token-update.html`：`c22.screening`。
- `/update-center.html`：`c22.convexity_tracking`。
- `/candidate-production.html`：日常候选与历史续跑两个队列。
- `/maintenance-jobs.html`：临时产物清理检查和服务启动校验。
- `/legacy-jobs.html`：C1.8、C2.1、Gate 0 和旧主干。
- `/on-demand-tools.html`：21 个任务目录及其他手动写入口。
- `/task-detail.html?taskId=`：任何任务的稳定通用深链；不能代替上述独立承载。

详情返回完整 `ManagerTask`，以及运行历史、来源/链分解、输入输出、控制预览入口和状态依据。

### 5.4 逐链与来源 `/chain-source-health.html`

字段：`chainId`、`sourceId`、`applicable`、`status`、`lastAttemptAt`、`lastSuccessAt`、`dataAsOf`、`lagSeconds`、`cursor`、`checkpoint`、`discovered`、`accepted`、`rejected`、`deduplicated`、`failed`、`affectedObjects`、`nextRetryAt`、`retryCapability`、`reasonCode`、`plainReason`。

全局来源失败不能自动污染无适用项目；聚合视图必须能下钻到原始范围。

### 5.5 规则透明 `/rule-transparency.html`

字段：`ruleId`、`plainName`、`plainDescription`、`baselineValue`、`effectiveValue`、`difference`、`unit`、`status`、`sourcePath`、`sourceSha256`、`approvedBy`、`approvedAt`、`effectiveFrom`、`effectiveUntil`、`scope`、`counts`、`passExample`、`nonPassExample`、`downstreamImpact`。

缺字段时使用结构化 `unavailable{reason,sourcePath}`，不得返回空字符串冒充有效值。

### 5.6 项目判定解释 `/decision-trace.html?assetId=`

字段：`assetId`、身份与 T0、证据列表、数据时间、逐规则输入、逐规则结果、等待/失败理由、有效覆盖、业务状态、快照 ID、前台可见性、排序字段、来源链接。

路径顺序固定为：输入证据 → 数据时间 → 规则检查 → 结果理由 → 当前状态 → 下游快照 → 前台显示。

### 5.7 数据快照 `/snapshot-handoffs.html`

每份快照返回：`snapshotId`、`schemaVersion`、`producerTaskId`、`builtAt`、`dataAsOf`、`atomic`、`complete`、`stale`、`objectCount`、`assetIdDigest`、`validation`、`consumerTaskIds`、`consumerPages`、`lastSuccessfulHandoff`、`lastFailedHandoff`。

生命周期状态与凸性跟踪状态必须使用不同字段。

### 5.8 运行记录与审计 `/run-audit.html`

运行记录：`runId`、`taskId`、`trigger`、开始/结束、终态、处理量、检查点、产物、错误和恢复关系。

管理审计：`auditId`、`actor`、`origin`、`requestedAt`、`taskId/ruleId`、`action`、`before`、`afterRequested`、`impactPreview`、`confirmationId`、`backendAccepted`、`linkedRunId`、`finalResult`、`rollbackOf`。

历史 C1.8/C2.1 记录必须带 `legacy=true` 和来源版本；状态过期必须带 `stale=true`。

## 6. 控制 API 契约

正式实现使用 `/api/c2.5/*` 作为管理者组合接口；它调用现有业务函数，不通过自发 HTTP 形成第二通道。

| 方法 | 路径 | 责任 |
|---|---|---|
| GET | `/api/c2.5/control-plane` | 总览组合快照 |
| GET | `/api/c2.5/tasks` | 全量任务账本与对账 |
| GET | `/api/c2.5/task?taskId=` | 单任务权威详情 |
| POST | `/api/c2.5/control/preview` | 生成影响预览与短时确认令牌 |
| POST | `/api/c2.5/control/execute` | 使用确认令牌执行一次操作 |
| GET | `/api/c2.5/chains-sources` | 逐链与来源状态 |
| GET | `/api/c2.5/rules` | 基线、有效值和覆盖 |
| GET | `/api/c2.5/decision-trace?assetId=` | 项目判定解释 |
| GET | `/api/c2.5/snapshots` | 快照与交接 |
| GET | `/api/c2.5/runs-audit` | 运行和审计 |

控制请求必须带 `requestId`，执行必须带未使用且未过期的 `confirmationToken`。重复请求不得重复启动任务。

## 7. 读写边界

- GET 组合接口只读 OS 状态、运行文件、日志、快照和数据库只读连接。
- 控制接口只能调用 `C2.5_CONTROL_CONTRACT.md` 明确允许的操作。
- 审计写入 `runtime/c2.5/management-audit.jsonl`；它不是任务状态源。
- 组合快照可写 `app/c2-5-admin-snapshot.js` 作为页面启动后备，但页面连接服务时必须用实时 API 覆盖，并显示快照时间。
- 不向 `data/convexity.db` 新增控制面表。
- 不向 `data/c2.1-pipeline.db` 写入管理审计或 UI 偏好。
- 用户 UI 偏好只保存在既有窗口/本地设置范围，不混入业务状态。

## 8. 陈旧判定

正式实现必须按每种任务的预期心跳和频率配置陈旧阈值，阈值写入源代码配置并在页面显示。最低规则：

- 声称 `running` 但进程/锁不存在：立即标记 `stale`。
- 声称 `running` 且心跳超过该任务允许间隔：标记 `stale`，显示最后依据。
- Windows 任务上次结果 `0x41301/267009` 只表示计划任务仍在运行，不证明内部业务步骤健康。
- Windows 下次触发不等于每个业务作业必定到期运行。

## 9. 空值与错误

- 未提供：`unavailable`。
- 不适用：`not_applicable`。
- 尚未运行：`not_started`。
- 真实没有结果：`no_data`。
- 数据读取失败：保留上一份完整数据并标记 `stale` 与错误。
- 页面不得把 `null`、空字符串、0、未知和不适用互相替换。

## 10. 版本边界

本契约不改变 C2.4 业务快照字段所有权。若实现发现必须改变第一关、第二关、公开资格、四路径、贝叶斯或前台数据契约，立即停止 C2.5 开发并请求重新冻结。
