# 企鹅投研-凸性｜C2.4 页面与数据契约

状态：正式冻结  
适用范围：候选初筛、凸性跟踪、公开快照、前台四页、项目详情和后台七组页面

## 1. 唯一连接键与截止时间

- 全链路只使用稳定 `assetId` 连接对象；不得按名称、Symbol、数组位置或页面顺序拼接。
- 多链同名项目按链和 `assetId` 分开保留。
- 每份快照必须有 `schemaVersion`、`buildId`、`generatedAt`、`dataCutoffAt`、`producer`、`isComplete` 和内容哈希。
- 页面只显示一份完整快照内的数量和明细，不得把不同截止时间的卡片、总数和列表拼在一起。
- 新快照生成失败时保留上一份完整快照；失败原因只进入后台。

## 2. 三份正式业务产物

### 2.1 候选初筛工作清单

唯一生产者：90 天候选初筛作业。

该作业同时保留两个不同对象：`firstGatePassedHistory` 是不可丢失的历史通过事实；`firstGateQueue` 只包含当前 0—90 天仍需交给第二关的工作对象。页面和接口不得用一个“第一关数量”混称二者。

每个对象至少发布：

`assetId`、`chainId`、`tokenAddress`、`poolId`、`assetDirection`、`t0`、`t0EvidenceIds`、`ageDays`、`firstGateState`、四项检查结果、`relationshipClass`、`firstGateCompletedAt`、`handoffBatchId`。

- `firstGateState=passed` 且当前日龄仍为 0—90 天时才进入 `firstGateQueue`；历史通过事实写入 `firstGatePassedHistory`。
- A/B/C/D 只是属性，不控制第一关通过。
- 来源未知、缺失和失败必须保留真实状态，不得写成 0 或安全。
- 第 91 天迁移后保留历史通过记录，但不得继续冒充 90 天当前候选。

### 2.2 凸性跟踪完整快照

唯一生产者：凸性跟踪作业。该快照必须包含全部当前跟踪对象，不能只包含公开项目或首页前 10。

每个对象至少发布：

`assetId`、`chainId`、`ageDays`、`lifecyclePool`、`continuedTrackingSince`、`trackingState`、`evaluationWindowId`、`evaluationCompletedAt`、`riskState`、`sellQuoteState`、`sellQuoteLossPct`、`projectEvidenceState`、`projectEvidenceBoundary`、四条路径状态、独立来源类型、贝叶斯五因子、后验总分、独立可信度、有效实测指标数、实际比较组、比较组样本量、严重异常、正常退出防抖计数、来源影响和证据 ID。

`lifecyclePool` 只允许：

- `new_0_90`
- `continued_91_plus`

`trackingState` 至少区分：等待公开底线、后台观察、等待来源重试、完整跟踪、停止主动跟踪。它不是前台公开状态。

### 2.3 机会中心公开快照

唯一生产者：凸性跟踪发布步骤；机会中心页面只读该快照。

每个对象至少发布：

`assetId`、`chainId`、`ageDays`、`lifecyclePool`、`continuedTrackingSince`、`relationshipClass`、`publicEligible=true`、`publicState`、`whyNow`、`keyEvidence`、`largestRisk`、`nextWatch`、`dataCutoffAt`、四路径摘要、项目证据边界、实际比较组、`bayesRankWithinChain`、`rankingAvailable`、重要变化摘要和详情引用。

`publicState` 只允许：

- `convexity_clue`
- `active_project`
- `observing`

公开快照不得包含 `publicEligible=false` 对象。待首轮、D 类、缺项目证据、风险未完成、报价不足和来源重试对象只保留在第二关后台快照。

## 3. 固定集合合同

每次构建必须逐 `assetId` 输出并验证：

1. `allOpportunities == publicSnapshot.items`。
2. `publicSnapshot.items ⊆ trackingSnapshot.items`。
3. 每个 90 天内跟踪对象都能追溯到当前 `firstGateQueue`；每个跟踪对象都能追溯到 `firstGatePassedHistory`。
4. 每个 `continued_91_plus` 对象都能追溯到 0—90 天期间的第一关通过、完整跟踪和至少一次公开底线通过记录。
5. `homeTop10(chain)` 是完整公开快照的只读派生切片，数量 `≤10`。
6. 同链第 11 名及以后仍存在于跟踪快照、公开快照和“全部机会”。
7. 无完整贝叶斯结果的公开对象仍存在于公开快照，只能 `rankingAvailable=false`。
8. 任一集合的总数必须等于其去重 `assetId` 数；重复资产 ID 为发布阻断。

构建器必须生成集合对账摘要：输入数、第一关通过数、跟踪数、公开数、各链公开数、两个生命周期池数量、三种公开状态数量、首页派生数、未排名公开数和集合差集清单。差集不为预期 0 时阻断发布。

## 4. 字段所有权

| 字段类别 | 唯一生产者 | 页面能做什么 | 页面不能做什么 |
|---|---|---|---|
| T0、日龄、链、方向、第一关状态 | 候选初筛 | 格式化和解释 | 重新推断 T0、改日龄或放行 |
| 生命周期池、持续跟踪起点 | 凸性跟踪迁移器 | 显示标签 | 按当前日龄自行迁移 |
| 风险、报价、项目证据、路径 | 凸性跟踪 | 摘要、展开证据 | 用缺失补 0、重判路径 |
| 贝叶斯因子、可信度、比较组、同链排名 | 凸性跟踪 | 显示相对排名原因 | 跨链比较或在浏览器重算 |
| 公开资格与三种公开状态 | 凸性跟踪发布步骤 | 筛选和展示 | 将待跟踪对象发布 |
| 首页每链前 10 | 前台快照派生器 | 显示完整切片 | 截断业务快照或停止第 11 名跟踪 |
| 重要变化 | 变化生产者 | 按链、池和时间筛选 | 把接口错误或价格流水写成重要变化 |
| 任务、来源、重试、额度、日志 | 各后台作业 | 在后台说明和操作 | 泄露到机会中心项目分类 |

## 5. 页面合同

### 5.1 机会首页

- 首屏显示公开总数、三状态数量和统一数据截止时间。
- 链选项来自正式链目录，固定顺序：Ethereum、Solana、Base、Arbitrum One、BNB Smart Chain、Robinhood Chain。
- 每链计数来自完整公开快照；0 也显示。
- 每次只查看一条链；首次选第一个有公开项目的链，之后恢复上次选择。
- 每条链两个生命周期池合计最多 10 张卡；不使用占位项目。
- 卡片固定显示：为什么现在关注、关键程序证据、最大风险/反证、下一观察项、数据截止时间、链、公开状态、真实日龄和生命周期池。

### 5.2 全部机会

- 数据集必须等于完整公开快照，不受首页前 10 影响。
- 20 条分页，不无限滚动。
- 筛选：全部链/六条单链、两个生命周期池、A/B/C、三种公开状态。
- 单链按同链贝叶斯顺序；全部链按最近重要变化和数据时间或按链分组，不计算跨链总榜。
- 90 天后项目单独列出并显示准确日龄。

### 5.3 重要变化

- 筛选：全部链/六条单链、两个生命周期池。
- 全部链只按变化发生时间排列。
- 每条只回答发生了什么、为什么影响判断、接下来观察什么。
- 任务日志、接口错误、普通价格流水和内部状态码不得进入。

### 5.4 我们如何判断

- 普通层解释三阶段、两池、六链、公开底线、三状态、四路径、同链排序、数据时间和程序上限。
- P50/P40、贝叶斯、来源独立性和公式放入可展开高级说明。

### 5.5 项目详情

- 首屏先显示为什么进入、状态理由和失效条件。
- 再展开市场、退出、供应、路径、贝叶斯方向、来源与历史。
- 无可靠数据的模块隐藏或明确不可用，不补模板、不补 0。
- 从首页、全部机会或重要变化返回时恢复入口、筛选、页码和滚动位置。
- HTTP/HTTPS 外部链接交给 Windows 默认浏览器；本地应用保持在原上下文。

## 6. 两个更新页面

### 6.1 90 天候选初筛

固定显示：已找到候选、已完成基础检查、已进入深度跟踪、等待继续或重试、本轮新增、最近完成时间和真实进度。

### 6.2 凸性跟踪

固定显示：收到初筛项目、已完成公开底线检查、已完成结构跟踪、已发布、已转入 90 天后持续跟踪、后台观察、等待来源重试和真实进度。

两页各自拥有立即更新、仅手动/自动频率、暂停新周期、继续断点、心跳、最近成功、下一次运行和按失败来源重试。设置和操作不得跨作业生效。

## 7. 数据状态

固定区分：`success`、`no_data`、`quota_limited`、`source_failure`、`unsupported`、`configuration_missing`、`program_failure`。

- `no_data` 和 `unsupported` 属于能力边界，不用红色，不提供无意义重试。
- 额度、连接、配置和程序失败进入“需要处理”，显示影响层、自动恢复能力和操作按钮。
- 来源失败不降低项目基本面分、不生成前台“数据受限”分类。
- 关键刷新失败时保留上次完整快照；从未完成公开底线的对象继续留后台。

## 8. 原子发布与恢复

- 两个作业独立断点、独立设置、独立运行状态，由唯一 Windows 调度器协调。
- 手动与自动共用同一作业入口和恢复语义。
- 数据写入、业务快照和页面快照按完成标记原子发布；中途文件不得成为当前快照。
- 连接失败按已冻结冷却规则重试，从已提交游标继续，不从头重扫。
- 后台隐藏运行，不创建黑框，不停止或重启与本次操作无关的进程。
