# C2.1 独立验收计划冻结候选稿

状态：等待用户确认；未冻结、未编码、未生成需求锁  
正式验收依据候选：`docs/C2.1_FORMAL_SCOPE_DRAFT.md`、页面数据契约、桌面设计、用语字典、规则配置和回归清单

## A. 模型、范围与版本边界

### A01 模型选择不构成门禁

使用什么模型由用户决定；验收不读取或审核模型元数据，不因模型名称阻断。需求冻结、开发自测、独立完整终验和发布阶段仍分别记录。

### A02 C2.0 保持冻结

C2.0 正式需求锁文件哈希不被 C2.1 修改；现有原始历史、评分、动作和 L0—L5不被覆盖。

### A03 独立性

运行时读取 RWA、旧整合项目和旧源目录的引用为 0。

## B. T0、对象与生命周期

### B01 真实 T0

部署、首次发现和数据库创建时间均不会冒充 T0。

### B02 90/91 天

第 90 天仍可见，第 91 天退出前台并保留历史。

### B03 A/B/C/D

A/B/C 可进入前台；C 显示关系未确认；D 前台数量为 0。

### B04 连续资产

迁移、包装、桥接、新池和新增交易所不错误重置 T0。

### B05 无年龄权重

年龄权重、年龄分、新鲜度分为 0；0—30 与 31—90 不因年龄自动形成质量排序。

## C. 宽硬门槛与产品证据

### C01 全部检查可追溯

每个硬门槛结果具有状态、原因、证据、来源和时间。

### C02 买卖事实

没有真实卖出记录的对象不能通过；历史卖出不被描述为未来保证。

### C03 硬风险

明确不可卖、冻结、黑名单、异常税费或身份冲突样本不进入前台。

### C04 GitHub 准入

官方、非空、未归档且具有提交记录的 GitHub 仓库可单独满足产品证据；身份不明、空仓库和归档仓库不能满足。

### C05 GitHub 边界文案

GitHub-only 项目全部显示“仅代码证据”及不证明部署、采用和投资价值的边界。

### C06 非 GitHub 路径

产品合约、结构化业务数据、已执行代币功能和链上产品使用可以独立形成产品证据。

### C07 无产品证据

只有代币、交易池、普通转账、社交或涨幅的对象前台为 0；后台原因具体。

## D. 真实历史与短窗口

### D01 回溯起点

所有观察历史从 T0 计算，`firstSeenAt` 只生成发现延迟。

### D02 被晚发现项目

发币第 10 天发现并成功回溯 10 天的样本显示 10 天历史，不显示 1 天。

### D03 未发生日期

发布不足 14 天的未来日期不计缺失、不计零分。

### D04 等窗口比较

0—2、3—6、7—13 天样本使用真实窗口和同发行日龄冻结基准，不使用 14 天分母。

### D05 回溯缺口

无法重建的日期显示 `backfill_incomplete`，不以收录后数据或插值填充。

## E. 五因子、可信度、强路径与五状态

### E01 分数不决定前台资格

存在低分但硬门槛通过项目的回归样本，仍可在“全部机会”查询。

### E02 分数不冒充线索

前台不存在“综合分达到某值所以是凸性线索”的文案或唯一判断路径。

### E03 缺失不写零

来源缺失、额度耗尽和历史不足不写 0，也不跨因子重分配权重。

### E04 状态互斥

每个前台项目恰好属于一个状态；优先顺序符合数据受限 > 凸性线索 > 活跃项目 > 新发观察 > 持续观察。

### E05 证据路径

凸性线索项目至少形成两条强路径，其中必须包括“交易与流动性形成”；第二条只能来自真实产品使用扩张、供应需求结构改善或已索引池活动超过供应修正估值变化。每条路径都有支持指标、反证、未知项和失效条件；综合分不是唯一支持项。

### E06 可复算

同一输入、同一规则和模型版本重复计算结果一致。

### E07 路径一固定规则

五个年龄段分别使用 2,000/2,000/3,000/3,000/5,000 美元流动性护栏；流动性同时达到同组 P60，三个需求指标至少两个达到 P60，买卖各不少于 1，100 美元标准卖出报价成功且损失不高于 10%。报价 `no_data/unsupported` 时路径为不可用，不补零。

### E08 路径四固定规则

逐池汇总只包括来源已索引且能返回 OHLCV 的池；未索引已发现池数量单列。历史供应与计量单位稳定后，`相对扩张≥同组P60` 且 `风险修正剩余>0` 才形成路径。页面和快照不存在“全球全池”声明。

### E09 可选路径真实缺失

固定样本中的产品使用确定映射为 0、供应需求历史改善可比为 0 时，两条路径均为 `unavailable`；测试证明没有先验、项目方文案、当前快照或零值补齐。

### E10 防抖

完整比较窗口形成后允许一次进入；正常退出需要两个新的连续完成评估窗口低于退出规则，同一窗口重复调度不累计。来源失败不算未通过；硬门槛失败、严重异常和第 91 天立即退出。

### E11 固定回归清单

`docs/C2.1_RULE_REGRESSION_MANIFEST_FREEZE_DRAFT.json` 中的文件哈希、49 个真实能力样本、六链/五年龄段分布、状态计数和15类边界结果全部复算一致。真实样本不替代正式全量运行，也不把“交集9”写成发布数量目标。

## F. 前台全量可见与分页

### F01 资格对账

`frontVisibleCount == hardGatePassedCount`；任一硬门槛通过项目静默遗漏会阻断快照发布。

### F02 首页非空完整性

硬门槛通过数大于 0 时，首页“今天先看”至少 1 个且不超过 8 个真实项目。

### F03 真实零状态

硬门槛通过数为 0 时显示各阻断数量，不使用模板项目。

### F04 全部默认

全部机会默认显示“全部”，不默认只显示形成线索。

### F05 五状态计数

全部、凸性线索、活跃项目、新发观察、持续观察、数据受限计数与数据对象对账。

### F06 分页

固定 20 条/页，明确页码和总页数；无限滚动行为为 0。

### F07 筛选返回

从第 2 页带筛选进入详情，返回后标签、筛选、排序、页码和滚动位置全部恢复。

## G. 接口额度与来源状态

### G01 原因分类

额度耗尽、限速、认证失败、来源中断、不支持、无数据、回溯不完整和程序错误可区分。

### G02 不污染项目分

额度耗尽不会把因子写 0或触发项目基本面下降，只影响数据状态与可信度。

### G03 前后台边界

前台显示影响、对象数和最后成功时间；后台显示接口、额度、重置、响应码、重试和明细。

### G04 自动恢复

模拟额度恢复后自动补采、复算并退出数据受限，不需要人工内容确认。

### G05 不改门槛

额度不足不会修改算法权重、硬风险、发布门槛或改用随机抽样。
