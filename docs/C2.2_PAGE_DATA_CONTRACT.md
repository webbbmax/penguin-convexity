# 企鹅投研-凸性｜C2.2 页面与数据契约

状态：正式冻结  
适用版本：C2.2

## 1. 三份原子契约

### 1.1 筛选候选快照

生产者：90 天新币筛选。至少包含：

```text
schemaVersion
buildId
generatedAt
sourceCutoffAt
ruleVersion
ruleConfigHash
assetId
projectId?
chainId
contractAddress
effectiveT0
ageDays
ageBand: age_0_30 | age_31_90
relationshipClass: A | B | C
hardGate
productEvidence
screeningChange
```

只有硬门槛通过的 A/B/C 对象进入发布清单。清单构建失败时继续使用上一份完整快照。

### 1.2 凸性跟踪快照

生产者：凸性跟踪。至少包含：

```text
schemaVersion
buildId
candidateBuildId
generatedAt
sourceCutoffAt
modelVersion
bayesSpecHash
assetId
trackingState
marketHistory
liquidityAndExit
addressAndSupply
productUsage
riskAndAnomalies
factorPosteriors
confidence
strongPaths
trackingChanges
lastCompleteTrackingAt
```

跟踪快照必须声明读取的 `candidateBuildId`。来源失败时不得用错误值覆盖上一份完整业务结果。

### 1.3 统一前台快照

生产者：统一组合前台生成器。至少包含：

```text
schemaVersion
buildId
candidateBuildId
trackingBuildId
generatedAt
sourceCutoffAt
coverageSummary
lifecycleCounts
trackingStateCounts
items
changes
```

组合生成器只按 `assetId` 合并。名称、Symbol、合约简称或数组顺序不得作为连接键。

## 2. 字段所有权

| 字段组 | 唯一生产者 |
|---|---|
| T0、日龄、A/B/C、宽硬门槛、产品证据资格 | 新币筛选 |
| 市场、成交、流动性、退出报价 | 凸性跟踪 |
| 地址、持仓、供应、产品使用和风险 | 凸性跟踪 |
| 四路径、贝叶斯后验、可信度、跟踪状态 | 凸性跟踪 |
| 页面排序、分组、普通语言组合 | 统一前台生成器 |

同一字段不得由两个快照互相覆盖。组合生成器可以格式化，但不能改变业务值或状态。

## 3. 生命周期与跟踪状态

生命周期字段：

```text
ageBand: age_0_30 | age_31_90
relationshipClass: A | B | C
```

跟踪状态：

```text
convexity_clue
active_project
observing
awaiting_first_tracking
```

规则：

- `convexity_clue` 仍由 C2.1 冻结强路径算法产生。
- `active_project` 仍由 C2.1 冻结弱线索算法产生。
- 完成有效跟踪但两者都不满足时为 `observing`。
- 没有首份完整跟踪记录时为 `awaiting_first_tracking`。
- `data_limited` 不再是前台项目状态；来源问题保存在后台作业与来源对象中。

## 4. 前台项目对象

```text
assetId
projectId?
canonicalName
symbol
chainId
effectiveT0
ageDays
ageBand
relationshipClass
hardGateSummary
productEvidenceSummary
trackingState
factorDirections
confidenceSummary
strongPathSummary
marketSummary
riskSummary
latestMaterialChange
dataCutoffAt
sortReason
detailHref
```

缺失可靠跟踪数据时，跟踪字段为 `null` 并附内部原因，前台省略该字段；禁止写 0、空字符串或推断值。

## 5. 项目详情对象

详情对象必须复用前台项目对象，并增加：

```text
identityAndT0
hardGateChecks[]
productEvidence[]
marketSeries[]
liquiditySeries[]
standardSellQuoteHistory[]
addressAndSupplyHistory[]
productUsageHistory[]
factorPosteriors[]
confidenceComponents
strongPaths[]
counterEvidence[]
riskAndAnomalies[]
materialChanges[]
evidenceRefs[]
sourceCutoffAt
```

每条判断必须能回到来源、观测时间和规则版本。前台不显示任务 ID、游标、额度账户、响应正文或密钥。

## 6. 重要变化

只有以下变化进入“重要变化”：

- T0、日龄段、A/B/C 或硬门槛变化。
- 产品证据升级或失效。
- 跟踪状态变化。
- 强路径形成、撤销或从不可用恢复。
- 因子后验方向或可信度发生可解释变化。
- 新硬风险、风险解除或第 91 天退出。

每条变化回答：发生了什么、之前是什么、现在是什么、为什么影响判断、数据到什么时候。普通行情流水不进入。

## 7. 排序

系统排序可使用强路径、贝叶斯后验、变化重要性、可信度和风险护栏，但必须输出 `sortReason`。排序不能改变硬门槛、跟踪状态或前台资格。

## 8. 后台作业契约

每个作业独立保存：

```text
jobCode: screening | convexity_tracking
state
trigger: manual | scheduled | resume | retry
frequency
paused
runId
stage
progress
lastHeartbeatAt
lastCompletedAt
checkpoint
sourceFailures[]
objectFailures[]
nextDueAt
```

六类底层状态继续严格区分：`no_data`、`quota_limited`、`source_failure`、`unsupported`、`configuration_missing`、`program_failure`。

## 9. 原子发布和失败保护

- 每份快照先写临时文件、完成结构和对账校验后原子替换。
- 新前台快照中的项目集合必须与最新完整候选清单一致；无迁移原因的静默缺项使构建失败。
- 跟踪快照落后不阻止新项目进入前台，但新项目只能显示“等待首轮跟踪”，不能继承同名项目数据。
- 任一快照构建失败都保留上一份完整文件。
- 页面始终显示业务数据截止时间，不把任务运行时间冒充数据时间。

## 10. 页面与分页

- 首页最多 8 个真实项目。
- 全部机会默认显示全部硬门槛通过项目，每页 20 条，不使用无限滚动。
- 筛选维度包含生命周期、A/B/C、链、产品证据和跟踪状态。
- 从筛选页进入详情再返回，恢复标签、筛选、排序、页码和滚动位置。
- 顶级前台导航仍为四项，不新增第五项。
