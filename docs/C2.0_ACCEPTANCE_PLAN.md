## A. 阅读优先级与首页

### A01 三层边界

前台只出现“现在必须看、值得继续看、保持观察”。自动测试证明三层不写回动作、评分、L0-L5或数据库。

### A02 首页数量

首页优先项目为 0 至 5 个；不允许超过 5，也不允许为了凑数放入 `summaryComplete=false` 或通用模板项目。

### A03 真实空状态

构造/使用没有合格项目的只读样例时，显示“本期没有需要优先阅读的新机会”；首页项目卡为 0，不使用“保持观察”补位。

### A04 当前行动诚实

普通建仓、极限试仓、只观察、反身性管理、失效/排除数量与现有权威结论对账。真实 0 继续显示 0，不改变门槛。

### A05 唯一项目

存在多个案例的项目只出现在前台一次；唯一展示案例选择符合“最新已发布结论 → 案例更新时间 → case_id”规则。后台仍保留全部案例。

### A06 无数值分

前台 DOM、前台快照和新构建代码中不存在综合分、阅读分、优先级分、信号分或用于排序的新数值字段。

### A07 排序可解释

首页和全部机会每个优先项目都有 1 至 3 条 `sortReasons`，可回指实际动作、影响维度、证据边界和时间；相同输入重复构建排序完全一致。

### A08 风险保护优先

同层出现改善与收紧时，可能收紧按冻结规则优先；失效/阻断风险不能被价格或成交量变化压到后面。

### A09 30 秒五问

在 1280×720、1440×900、1920×1080 和 125% 缩放中做计时真实阅读，首次进入者 30 秒内能回答 PRD 的五个问题。任一问题答不出即失败。

## B. 变化去重、事件链与数值口径

### B01 精确重复为 0

首页和重要变化中，同项目、同运行、同语义字段、相同起止值的重复显示数量为 0；证据数组已合并去重。

### B02 同轮项目聚合

同一项目同一轮多字段变化只显示一张项目事件卡，子变化可展开，不按字段平铺多张卡。

### B03 24 小时事件链

同项目同语义字段相邻不超过 24 小时的连续变化形成一链；超过 24 小时或不同字段不合并。

### B04 中间风险保留

构造或抽查包含中间动作、失效或阻断风险变化的链，展开后步骤完整，净变化没有抹掉中间风险。

### B05 影响标签

每条前台变化只使用“可能改善、可能收紧、尚不改变判断”。标签不写回动作；实际动作变化时正文与权威结论一致。

### B06 默认降噪

重要变化默认不显示 `尚不改变判断`；用户主动选择“全部变化”后可查看。每页最多 20 个项目事件链，无无限滚动。

### B07 单纯行情不升格

价格、成交量或流动性单独波动且交易/退出判断未变时，影响为“尚不改变判断”，不能进入首页“现在必须看”。

### B08 单位完整

所有前台可见精确数值都有单位、时间范围和比较基准；科学计数法数量为 0。口径不明的精确数值显示数量为 0，后台单位问题清单保留记录。

### B09 原始历史不丢失

变化合并前后，数据库 `opportunity_stage_history`、`tracking_task_runs`、原始事件和标准事件数量不因展示去重减少；所有显示链可回指原始步骤。

## C. 五段式项目摘要

### C01 五段齐全

所有首页项目具备当前动作、最强支持事实、最大阻断/风险、下一触发、失效条件与证据时间五段；`missingSummaryParts` 为空。

### C02 动作不重算

摘要动作直接等于现有权威动作；显示映射“已失去凸性 → 失效/排除”只发生在 UI，不修改数据库枚举。

### C03 支持事实可溯源

首页项目最强支持事实只能来自 `confirmed_fact` 或 `high_confidence_inference`，并能回到证据、来源、原始记录和时间。项目方陈述或未验证线索不能单独支撑首页。

### C04 阻断具体

抽查至少 30 个唯一项目，能够区分不同的阻断类别、缺失事实和行动影响；无上下文“最大风险：尚未确认”为 0。

### C05 触发与责任

首页和详情的下一触发包含具体事实、系统/人工责任和下次复查时间；无法形成时间时按字典显示明确限制，不猜测时间。

### C06 失效与时间

失效条件具体且证据时间可见；已明确过期的摘要不能 `summaryComplete=true`。

### C07 通用模板拦截

首页 `whyPriority`、支持事实、首要阻断和下一触发中，规范化后被 3 个及以上项目完全重复的通用模板数量为 0；被拦截项目进入后台模板问题清单。

### C08 资料不足诚实表达

摘要不完整的项目保留在全部机会，显示缺失段、责任和复查时间，不生成合成事实，不进入首页。

### C09 三分钟核验

从任一首页信号一次点击进入详情，3 分钟内可展开并核对最强支持事实、首要阻断和失效条件的来源与时间。

## D. 后台判断质量中心

### D01 页面归属

`decision-quality.html` 只登记为 `admin`，归入“模型与规则”的首个二级入口；后台一级栏目仍为 7，前台不加载该页面或后台快照。

### D02 七类完整

主体身份、可购买资产、价值捕获、最大可控亏损、交易与退出、点火条件、证据时效七类全部存在且定义与数据契约一致。

### D03 漏斗对账

每一类 `已闭环 + 待系统处理 + 待人工确认 = 当前唯一项目总数`。七类任一不等式时，本轮质量快照判为不可用并保留上次有效快照。

### D04 负面答案可闭环

至少抽查交易阻断、风险冲突等负面答案：信息明确且可溯源时属于已闭环，但项目仍受现有动作约束；不把“已闭环”写成“已通过”。

### D05 阻断排行

默认顺序按前台影响、影响项目数、等待时间、名称；不按技术任务数量。每行具备影响范围、责任、下一步、最近执行、复查时间和处理入口。

### D06 指标分子分母

七个质量指标都显示分子、分母、定义和生成时间。分母为 0 时值为 null 并显示“无法计算”，不得显示 0%。

### D07 闭环队列

支持质量维度、责任方、状态、项目搜索和 20 条/页分页；判断质量中心不新增研究写按钮，只链接现有安全处理页。

### D08 返回上下文

从质量队列进入至少三类处理页并返回，原筛选、页码和滚动位置全部恢复。

### D09 前台回溯

任抽 30 条完整摘要，后台可从项目摘要回到机器结论、证据、来源、原始记录和最近规则运行；孤立展示结论为 0。

## E. 双快照一致性与失败保护

### E01 同构建身份

前后台两份 C2.0 快照的 `buildId`、`generatedAt`、`sourceSnapshotAt` 和 `inputRunIds` 完全一致。

### E02 原子替换

模拟第二份临时快照写入或解析失败，两个活动快照均保持上次有效版本，临时文件被清理。

### E03 项目/案例对账

前台 `counts.projects` 等于数据库唯一项目数，`counts.cases` 等于候选案例数；后台 reconciliation 与其一致。

### E04 更新顺序

任何新增原始事件的测试流程都先完成 Event Schema v2 增量规范化，再重建现有快照，最后重建 C2.0 快照。原始、标准、可溯源事件不因 C2.0 产生断链。

### E05 失败沿用旧判断

模拟构建失败，前台明确显示上次有效时间和影响范围；后台显示失败步骤。旧数据不得标为本轮当前数据。

### E06 前台安全字段

前台快照中任务 ID、Watcher、游标、调度、重试、日志、模型提示、内部路径和凭据位置计数为 0。

## F. UI 与 UX

### F01 三级视觉权重

四种视口截图中，当前判断、优先信号、状态/时间形成清楚三级层级；不是同权卡片墙。

### F02 项目事件线

重要变化默认折叠、展开、键盘访问和焦点恢复通过；展开不导致页面跳回顶部。

### F03 五段式详情

详情首屏在 1440×900 中看到当前动作、最强支持、最大阻断、下一触发和失效/时间的标题及主要内容。

### F04 判断质量布局

后台覆盖条、阻断排行、质量指标和队列在 1280×720、1440×900、1920×1080 和 125% 缩放下无横向页面溢出。

### F05 状态独立设计

构建中、真实无信号、资料不足、过期、单位不明、部分完成、对账失败和构建失败各有独立文案；不统一为“暂无数据”。

### F06 可访问性

键盘可访问导航、筛选、分页、事件链、证据展开和处理链接；状态有文字/图标，正文与背景达到 WCAG AA。

### F07 上下文返回

首页、全部机会、重要变化进入详情并返回时，来源、筛选、页码和滚动位置全部恢复。

### F08 截图集

`docs/C2.0_DESIGN_SPEC.md` 列出的 17 类截图全部生成并由 Luna、Sol 分别检查；截图不得替代真实点击。

## G. 业务与工程回归

### G01 核心文件不变

五个核心文件与冻结基线 SHA-256 完全一致；任一变化即 P0 失败。

### G02 无数据库迁移

C2.0 不新增 SQLite 业务表、列或迁移；`storage/schema.sql` 不变。派生阅读层级、摘要和质量数据只存在于本地快照。

### G03 SQLite 完整

`integrity_check=ok`，外键异常 0。最终项目、案例、原始/标准事件、证据、溯源、阶段历史和跟踪执行数量现场记录，并解释与冻结参考的正常变化。

### G04 原始与标准连续

原始事件、标准事件和可溯源覆盖满足当前数据主干门槛；C2.0 不制造积压、开放断档或孤立展示结论。

### G05 独立性

活动运行目录到 RWA、旧整合项目和源项目的禁用运行时引用为 0；公共 API 共享边界不变。

### G06 全量自动测试

全部 `scripts/test_*.py` 退出码为 0；新增 C2.0 测试覆盖本计划 A-G 的机器可验证部分。不得只运行新测试。

### G07 路由与资源

活动 HTML 全部有唯一角色；预期至少 29 个角色页面、31 个本地页面/资源可访问，最终数量以实施后现场清单为准。静态文件存在不能替代 HTTP 200 与正确角色内容。

### G08 双角色真实路径

普通用户路径：启动 → 五问理解 → 全部机会筛选 → 详情核验 → 返回 → 重要变化事件链 → 方法说明。  
维护者路径：管理工作台 → 判断质量 → 过滤阻断 → 进入处理页 → 返回恢复 → 回溯前台结论。

### G09 桌面回归

桌面启动、8766、单实例、窗口记忆、关闭重开读取同一快照状态、冷启动、隐藏调度和其他入口保护继续通过。

### G10 业务数据只读终验

Sol 最终真实点击不触发更新、复核、重试、规则回放或业务状态写入。需要写操作的失败保护使用隔离副本或模拟状态验证。

### G11 版本号门禁

Luna 自测阶段后台唯一位置仍为“当前版本 C1.9”。只有 Sol 全部验收通过后才改为“当前版本 C2.0”；任意前台/详情可见版本号为 0，任意后台页面为 1。

## H. 放行规则

- A01-A09、B01-B09、C01-C09、D01-D09、E01-E06、F01-F08、G01-G11 必须全部通过。
