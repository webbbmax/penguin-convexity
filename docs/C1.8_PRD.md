## 1. 背景与当前事实

C1.7 已完成数据主干，但机会中心把研究结论、机器后台状态、待办任务和完整项目列表同时铺在一个长页面中。用户即使参与了全程建设，仍无法快速判断“现在能不能行动、系统正在做什么、是否需要自己处理”。

冻结本需求时的只读核对结果：

- 590 个机会案例中，可执行 0、只观察 589、失效/排除 1。
- 589 个项目跟踪任务已生成，但执行记录为 0；当时到期任务为 0。
- 当前所谓自动跟踪，实际是用户点击“一键全部更新”后，程序才执行到期任务，不是无人值守调度。
- 首要行动缺口分为：项目主体待核验 259、可购买资产待核验 156、市场与退出待闭环 158、凸性结构待闭环 16。
- 最近变化有 24 小时 142 条、7 天 1,200 条，当前页面没有显示上限。
- 590 条催化路径中，候选催化 13、研究闭环 0、行动闭环 0。
- Hubble 的首要可验证阻断是退出能力：本地市场快照流动性约 7,012.64 美元、24 小时成交额约 11.37 美元，2 万美元理论退出滑点 100%，超过当前 8% 门槛；首页只写“达到阻断级”，没有展示事实和门槛。

这些结果证明：C1.8 不是单纯改文案，而是决策首页、状态语义、自动调度和后台责任分离的联合重构。

## 2. 版本目标

用户打开软件后 30 秒内能够回答：

1. 当前有没有可以行动的项目？
2. 如果没有，究竟是条件不满足、数据不足，还是更新失败？
3. 最近发生了哪些真正影响研究判断的变化？
4. 系统接下来会自动做什么？有没有必须由我处理的事项？

## 3. 非目标

C1.8 不做以下事项：

- 不修改 L0-L5 定义。
- 不合并风险、剩余凸性、交易性、点火距离和动作阶段。
- 不修改普通建仓、极限试仓、只观察、反身性管理、失效/排除五种动作。
- 不改写凸性评分、排序权重或投资结论门槛。
- 不新增自动交易、钱包连接、下单或资金管理。
- 不把 RWA 或其他业务的脚本、数据、路由、任务、文案或状态接入本项目。
- 不以扩大数据源数量掩盖当前体验问题；新增来源须另行立项。

## 4. 用户与责任边界

### 4.1 普通用户

- 阅读当前结论、重要变化、催化路径和项目详情。
- 收藏或取消关注项目。
- 不承担身份核验、来源适配、催化发现、市场采集或数据闭环工作。

### 4.2 投资负责人

- 只处理会改变重大行动的确认：升级为普通建仓、极限试仓或反身性管理，以及停止跟踪/失效。
- 可确认采用、驳回并填写原因；驳回后由系统重新取证。
- 不需要打开终端、执行脚本或理解数据库。

### 4.3 凸性工作台内部操作

- 处理身份冲突、错误资产映射、来源访问受限、规则未适配和数据归属异常。
- 查看完整运行日志、来源健康、失败重试和历史审计。
- 内部操作状态不得直接作为普通用户的首页文案。

### 4.4 程序

- 自动采集、去重、身份交叉验证、市场与退出计算、催化发现、证据归属、到期复查和无变化留痕。
- 自动处理“继续跟踪”和“无变化”。
- 重大升级和停止结论必须进入人工确认，不自动交易。

## 5. 信息架构

### 5.1 解除单页长滚动冻结

C1.8 明确解除 C1.6-06“七类信息必须全部铺在同一个长页面并保持连续下拉”的展示冻结。七类业务语义继续保留，但调整为：

- 决策首页：一屏摘要，只展示最重要结果。
- 行动条件与缺口：独立详情。
- 重要变化：独立详情。
- 催化与交易闭环：独立详情。
- 跟踪进度：独立详情。
- 项目库：分页详情，项目类别作为筛选维度。

顶部产品导航仍只属于凸性机会中心、项目详情和凸性工作台，不新增其他业务入口。

### 5.2 决策首页四个模块

首页只保留：

1. 本轮行动结论。
2. 接近行动门槛的项目。
3. 重要变化。
4. 系统工作与需要我处理。

任一模块最多展示 5 个项目或 5 条记录，完整内容通过“查看全部”进入对应详情，不在首页继续展开。

## 6. 功能细化

### C18-F01 本轮行动结论

必须展示：

- 普通建仓、极限试仓、反身性管理、失效/排除数量。
- 本轮结论对应的数据时间、采集完成时间和页面生成时间。
- 最近一次更新结果、来源覆盖、失败来源、过期来源和到期任务执行情况。
- 当可执行数量为 0 时，必须说明属于哪一种零结果。

零结果状态固定为：

- `qualified_none`：覆盖和更新均达到发布门槛，但没有项目通过全部行动条件。
- `coverage_incomplete`：关键身份、资产、市场、退出或证据覆盖不足，暂不能把 0 当作市场结论。
- `stale`：数据超过规定时效，旧结论保留但显著标记过期。
- `update_failed`：关键任务失败，不能发布新的行动判断。
- `ready_with_actions`：至少一个项目通过普通建仓或极限试仓门槛。

禁止只显示“当前可执行 0”而不显示覆盖和更新时间。

### C18-F02 接近行动门槛

从只观察项目中提取最多 5 个最接近行动条件的项目，不把 589 个只观察项目全部铺开。

每个项目显示：

- 当前动作。
- 已满足的硬条件数量/总数。
- 只差的首要条件。
- 谁负责补齐。
- 下次自动检查时间。
- 如果条件满足，可能进入哪一种动作复核。

排序优先级固定为：缺口数量少 → 点火距离近 → 剩余凸性高 → 交易性较好 → 风险较可控。该排序只用于“接近行动门槛”展示，不改写现有投资评分。

### C18-F03 行动条件与缺口

栏目名称由“为什么还不能行动”改为“行动条件与缺口”。

每条缺口必须包含：

- 缺口名称。
- 当前事实。
- 行动门槛。
- 为什么影响行动。
- 负责人：系统、内部复核、用户确认或外部事实。
- 当前状态。
- 下一步动作。
- 下次检查时间。
- 相关证据入口。

首要缺口类别继续保留：项目主体、可购买资产、市场与退出、凸性结构。页面必须说明这些是项目分组，不是要求用户手动完成的四项任务。

### C18-F04 重要变化

“最近变化”改名为“重要变化”。

首页只显示最多 5 条，优先级为：

1. 动作升级或停止。
2. 新增或解除硬阻断。
3. 新催化得到可靠确认。
4. 交易性、风险或价值捕获发生实质变化。
5. 普通行情变化。

每条变化必须使用固定结构：

- 什么从 A 变成 B。
- 为什么重要。
- 是否改变当前动作。
- 证据来源和时间。
- 系统下一步。

同一项目在同一轮更新中的多项变化合并为一条。普通价格、成交额和市值波动默认折叠为“行情变化 N 条”，不得淹没行动级变化。

完整变化页每页 20 条，支持时间、影响等级、变化类型、项目和动作影响筛选。

### C18-F05 催化与交易闭环

把技术状态翻译为五步研究路径：

1. 发生了什么。
2. 为什么项目受益。
3. 哪个资产承接价值。
4. 当前能否买入和退出。
5. 还缺什么，以及系统何时再次检查。

每一步固定显示：已确认、系统正在检查、外部事实尚未发生、来源不可用、需要人工确认、已失效。

“催化事实待发现”必须改成明确责任语言，例如：

> 系统尚未发现 90 天内可溯源催化；下次自动检查：2026-08-03 08:00。

普通用户不需要自己发现催化。只有来源适配、身份冲突或证据归属问题进入凸性工作台。

### C18-F06 阻断原因可读化

“阻断级”不能单独作为原因。每个硬阻断必须展示：

- 触发字段。
- 当前值。
- 门槛值。
- 数据时间与来源。
- 对行动的直接影响。

Hubble 验收样例必须显示近似如下内容：

> 无法可靠退出：当前池子流动性约 7,013 美元，24 小时成交额约 11 美元；模拟退出 2 万美元滑点 100%，超过 8% 门槛，因此卖出路径被阻断。

如果存在多项阻断，首页只显示首要阻断和“另有 N 项”，详情页展示全部，不把通用失效条件拼成长句。

### C18-F07 真正的自动跟踪

建立本项目独立的无人值守调度，不依赖用户每天点击更新。

默认策略：

- 自动模式默认开启，但首次启用必须在软件中清楚展示并允许关闭。
- 每天 08:00（Asia/Shanghai）执行一次全量研究更新；用户可在界面修改时间。
- 每小时检查到期项目，只运行到期任务及其所需来源，不全量重复采集。
- 软件窗口关闭时仍由本项目独立 Windows 计划任务运行。
- 启动、暂停、修改时间、立即运行和失败重试全部在凸性工作台完成。
- API 配额、速率限制、外部来源失败和真实零结果必须分开。
- 调度、日志、游标、失败状态和原始数据均保存在本项目，不读取其他业务运行状态。

### C18-F08 自动任务状态

“尚未自动执行”拆成明确状态：

- `not_due`：尚未到期；显示下次时间。
- `queued`：已到期，等待调度。
- `running`：正在执行；显示开始时间和进度。
- `no_change`：已检查，没有足以改变结论的新事实。
- `completed`：已执行并产生结果。
- `partial`：部分来源未完成；显示缺失范围。
- `failed`：执行失败；显示原因和重试入口。
- `paused`：自动运行被用户暂停。
- `quota_delayed`：因额度保护延后；显示预计恢复时间。

每个状态必须同时显示负责人、下次动作和时间。不得把 `not_due` 表述成系统没有工作。

### C18-F09 系统工作与需要我处理

首页固定分成：

- 系统正在处理：下次运行、队列、最近成功、失败和新发现。
- 需要我处理：只显示重大结论确认和无法自动解决的冲突。

如果人工队列为空，必须明确显示“当前无需你操作”。

人工确认支持：

- 确认采用。
- 不采纳并填写原因。
- 查看触发变化、支持证据、反面证据和失效条件。
- 驳回后自动转为重新取证任务。

“继续跟踪”和“无变化”由系统自动处理，不进入人工队列。

### C18-F10 项目库与分页

- 首页不渲染完整项目库。
- 项目库每页 20 个，支持上一页、下一页和页码跳转。
- 支持项目名、代币、凸性来源搜索。
- 支持动作、L0-L5、生命周期类别、风险、剩余凸性、点火距离、交易性和首要缺口筛选。
- 返回详情后保留页码、筛选、搜索和滚动位置。
- 早期、OG、潜力项目作为生命周期筛选维度，不再占用首页长栏目。

### C18-F11 普通展示与工作台分离

机会中心只展示投资者需要理解的结论、依据、变化、风险、催化和下一步。

以下内容只进入凸性工作台：

- 来源适配和游标。
- API 配额与健康。
- 采集失败和重试。
- 身份冲突处置。
- 孤儿证据归属。
- 全量任务明细和技术日志。

大众展示不得出现要求用户理解程序内部状态的术语；需要保留的技术事实放入“查看数据依据”。

### C18-F12 更新可信度与异常保护

发布当前结论前必须计算：

- 关键来源完成率。
- 项目主体覆盖率。
- 可购买资产覆盖率。
- 市场与退出覆盖率。
- 催化与价值传导覆盖率。
- 到期任务执行率。
- 数据新鲜度。

任何关键链路失败时，继续保留上次有效结论，但显著标记“旧结论”和失败范围；不得用旧数据冒充本轮成功，也不得把来源静默写成市场无变化。

## 7. 自动跟踪流程

1. Windows 独立计划任务唤醒凸性调度器。
2. 调度器读取本项目配置和到期队列。
3. 只采集本轮所需来源，并执行配额保护、去重和失败重试。
4. 新数据写入原始事件、标准事件、证据和溯源。
5. 执行到期项目任务，形成继续、升级、停止或暂无法判断。
6. 继续和无变化自动回写；升级和停止进入人工确认。
7. 重建页面快照并更新“上次/下次运行”。
8. 失败保留上次有效数据，生成可重试记录和清楚提示。

## 8. 文案规则

禁止孤立使用：

- 待核验
- 待闭环
- 待发现
- 阻断级
- 尚未自动执行
- 暂无内容

必须改成“状态 + 原因 + 负责人 + 下一步 + 时间”。

示例：

- 不合格：`可购买资产待核验`
- 合格：`系统尚未确认哪个代币承接项目价值；将在 8 月 3 日 08:00 重新核对官方文档和登记合约。你无需处理。`

## 9. 数据与安全边界

- C1.8 实施前必须创建独立基线备份和哈希清单。
- 正式数据库仍为 `data/convexity.db`。
- 不删除或覆盖 C1.7 历史、原始事件、证据、溯源、任务执行和状态变化。
- 调度测试优先使用隔离数据库；最终业务数据验收保持只读。
- API 密钥不得进入代码、文档、快照、测试输出或日志。
- 不建立到 RWA、旧整合项目或源项目的运行时引用。

## 10. 发布验收摘要

C1.8 只有同时满足以下条件才可发布：

- 首页首屏 30 秒可理解测试通过。
- 首页每个模块不超过 5 条。
- 完整列表每页 20 条，状态记忆通过。
- 五类零结果和九类自动任务状态均通过测试。
- Hubble 阻断原因显示具体值和门槛。
- 软件关闭状态下真实计划任务能够执行隔离验收任务。
- 到期任务产生执行记录；未到期任务不被误标为失败。
- 升级/停止进入人工确认；继续/无变化自动处理。
- 全量 Python、全部 C1.8 路由、SQLite、桌面和真实点击测试通过。
- 旧 29 条路由回归通过；新增路由以 C1.8 验收清单为准。
- 不改变评分、动作和数据历史，不耦合其他业务。
- 最终由 Sol 按 `docs/C1.8_ACCEPTANCE_PLAN.md` 独立验收通过。

## 11. 冻结与变更控制

- Luna 只能实现本文件已有需求，不得新增功能或调整投资规则。
- 实现中发现矛盾、不可行或需要改变用户决策的事项，必须停止并记录为待用户决策，不得自行选择。
- 任何需求修改都必须：用户明确同意 → 修改三份冻结文档 → 更新需求锁哈希 → 记录 `docs/DECISIONS.md`。
- Sol 发现需求未实现或实现越界时，必须判定阻断并交回 Luna，不得降低验收标准放行。
