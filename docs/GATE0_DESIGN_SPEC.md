# Gate 0 后台运行与进度设计规范

状态：已冻结

## 1. 实现结构

Luna 按以下文件职责实现，不自行更换架构：

| 文件 | 职责 |
|---|---|
| `scripts/gate0_dex_factory_backfill.py` | 保留现有协议解码；补充分片级输入输出和恢复接口 |
| `scripts/gate0_backfill_background.py` | 计划、单实例锁、检查点恢复、重试、状态聚合、最终校验和完成退出 |
| `scripts/install_gate0_backfill_task.ps1` | 只创建/更新独立任务 `PenguinConvexity-Gate0-Backfill` |
| `scripts/build_gate0_backfill_progress.py` | 从机器状态生成固定进度 HTML 与 artifact |
| `scripts/test_gate0_backfill_recovery.py` | 中断、恢复、重复、损坏、额度与状态契约测试 |

现有预检与报告脚本只做兼容性修复，不合并进后台扫描器。

## 2. 后台生命周期

```text
准备计划 → 小范围验收通过 → 安装独立恢复任务 → 启动一次
     ↓
读取锁与检查点 → 领取未完成分片 → 原子保存 → 更新进度页
     ↓
额度等待/来源重试/重启恢复 → 仅继续缺口
     ↓
全部分片完成 → 全局校验 → completed → 停止网络请求
```

- 任务计划程序只负责恢复未完成工作，不负责重复启动新的 90 天运行。
- 进程发现已有有效锁和活跃心跳时立即退出。
- 心跳超过冻结超时才允许接管；接管必须增加 `recoveryCount` 并保留旧锁审计。
- 完成后任务再次被触发只能读取 `completed` 并退出，网络请求数必须为 0。

## 3. 重试策略

- `quota_limited`：读取可用重置时间；没有重置时间时指数退避并设置上限，不消耗其他分片已完成结果。
- `source_failure`：有限重试、退避、必要时动态缩小当前区间；不得扩大范围或重跑已完成分片。
- `configuration_missing`、`unsupported`、`program_failure`：不无限重试；进入明确阻断状态。
- 相同失败达到冻结重试上限后，运行保持可恢复并显示受影响分片，不删除结果。

## 4. 进度页

固定页面按普通用户阅读顺序展示：

1. **当前结论**：正在运行、额度等待、需要修复或已经完成。
2. **扫描进度**：固定窗口、分片完成数、覆盖权重和最后心跳。
3. **六链进度**：每条链的协议支持数、分片、事件、状态和缺口。
4. **当前工作**：协议、区间、请求与最近检查点。
5. **恢复与异常**：恢复次数、失败类别、自动处理方式和是否影响完成。
6. **边界说明**：支持范围内回扫，不等于全市场或全局 T0。

页面每 30 秒自动刷新。状态不只依赖颜色；必须同时有文字和时间。若心跳超过 10 分钟，页面显示“进程可能已停止，等待独立任务自动恢复”，不能继续显示绿色运行中。

## 5. 进度计算

- 已知扫描范围使用区块/slot 覆盖权重，不使用发现项目数作为分母。
- 动态拆分后子分片权重之和必须等于父分片。
- 协议结构覆盖显示 `已支持/已观察/不支持` 三个计数，不与扫描覆盖率混合。
- ETA 需要至少 5 个连续完成分片且最近速率波动不超过 30%；否则隐藏具体时间。

## 6. UI 与 UX 验收场景

- 正常运行且有明确进度。
- 额度等待但已完成结果不丢失。
- 来源失败正在自动重试。
- 电脑/进程中断后恢复次数增加且进度不倒退。
- 存在不支持协议时仍明确显示覆盖边界。
- 已完成且再次触发不发起请求。
- 状态文件陈旧时显示可能停止，不显示正常运行。
