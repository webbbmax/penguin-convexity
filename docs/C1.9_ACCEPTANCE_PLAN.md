# C1.9 独立验收计划

状态：已冻结；Luna 用于开发自测，Sol 用于独立终验与发布  
目标：确保前后台真正分离，而不是只换颜色和标题

## A. 普通用户前台验收

### A01 30 秒理解测试

首次使用者不看说明，在首页 30 秒内能回答：

1. 当前有没有可行动机会；
2. 如果不能行动，最主要原因是什么；
3. 最近有什么真正影响判断的变化。

三题任一答不出即不通过。

### A02 前台无后台语言

前台不得出现：任务 ID、来源适配、Watcher、孤儿证据、游标、重试、调度配置、运行日志、负责人队列、模型验收、规则回放。允许在“查看依据”中展示面向用户的来源名称和数据时间。

### A03 前台无后台控件

未来大众构建不含运行、暂停、恢复、重试、保存调度时间等管理操作。本地桌面版只能通过明确的“管理工作台”入口进入后台。

### A04 页面归属

机会首页、全部机会、重要变化和前台项目详情使用前台导航与页脚；不得加载 `workbench-nav.js`，不得显示“凸性工作台 C1.7/C1.8”。

### A05 项目详情上下文

“项目详情”不在顶级导航。至少从首页机会、重要变化和全部机会三处进入详情；返回后分别恢复来源页面、筛选、页码和滚动位置。

### A06 列表可控

首页每块不超过 6 条；长列表明确分页。重要变化默认不显示“分层未变”和“比较基线”；没有重要变化时显示真实空状态。

### A07 用户语言

抽查至少 20 个前台状态，普通用户无需理解程序、数据库或任务系统即可读懂“是什么、为什么重要、下一步会怎样”。

### A08 前台无可见版本号

机会首页、全部机会、重要变化、“我们如何判断”和前台项目详情的可见文本中，M1.0、C1.7、C1.8、C1.9 等版本号计数必须全部为 0。内部接口字段不计入可见界面。

## B. 后台工作台验收

### B01 30 秒运行判断

维护者进入工作台 30 秒内能回答：

1. 系统现在正常、运行中、部分完成、失败还是可能卡住；
2. 当前任务运行到哪个阶段；
3. 已完成多少、失败多少；
4. 最近心跳是什么时间；
5. 下一步需要做什么。

### B02 长任务持续进度

使用只读/模拟状态验收等待、运行中、外部来源等待、可能卡住、部分完成、成功和失败。运行中至少显示阶段、计数、已运行时间和最近心跳；总量未知时不得显示伪造百分比。

### B03 状态持久性

任务运行中切换栏目、刷新更新中心、关闭并重新打开桌面软件，均能读取同一任务状态，不重复发起任务。

### B04 失败聚合

相同来源或相同原因的失败必须聚合；页面先显示影响范围和处理建议，再允许展开逐项目和原始日志。

### B05 工作台信息架构

所有现有后台页面必须归入七个一级栏目之一；不存在无归属页面，也不在顶部同时平铺八个主导航和近二十个同权工具。

### B06 操作边界

运行、暂停、恢复、重试和设置只存在后台。每个写操作显示作用范围；测试环境以模拟或隔离数据验证，不在只读验收中触发真实更新。

### B07 版本号唯一位置

任意后台页面只在共享浅色左侧栏底部看到一次“当前版本 C1.9”。页面标题、顶部、正文、卡片和页脚不得重复；侧栏收起后只能通过该位置的悬浮说明查看，不得复制到顶部。

### B08 七阶段真实映射

全量更新的七个用户阶段必须映射到现有 18 个更新组件和最后的页面快照重建。自动化测试至少证明每个组件只归入一个用户阶段，阶段顺序稳定，遥测失败不会改变该组件的业务结果。

## C. UI 与交互验收

### C01 浅色视觉

前台和后台均不使用大面积深色左栏。后台浅色导航选中态、前台浅色顶部导航、南极蓝品牌色和现有 Logo/口号同时保留。

### C02 单一导航

任何页面只显示一套主导航；桌面外壳不再与 iframe 页面重复头部、导航和页面边框。

### C03 信息强弱

截图检查 1280×720、1440×900、1920×1080 和 Windows 125% 缩放。主结论、主任务和失败状态必须优先可见；端口、来源数量和技术说明不得抢占首屏注意力。版本号仅在后台左栏底部弱化显示。

### C04 可访问性

键盘可访问主导航、筛选、分页和详情返回；状态不只靠颜色；正文、辅助文字和禁用态达到可读对比度。

### C05 加载与异常状态

分别验证：首次加载、后台重建、真实零结果、数据过期、更新失败、部分完成、网络来源等待和页面读取失败。不得统一显示“暂无数据”或无限加载。

### C06 视觉截图集

至少人工检查：前台正常/数据不完整、全部机会筛选分页、重要变化零结果、项目详情返回、工作台概览、全量更新运行中、外部来源等待、部分完成/失败聚合和后台唯一版本号十类截图。

## D. 业务与工程回归

### D01 冻结业务规则不变

对比 C1.8 基线：L0-L5、风险、剩余凸性、交易性、点火距离、评分、五种动作和项目生命周期规则无变化。

### D02 数据完整性

SQLite `integrity_check=ok`、外键检查无异常；项目、机会案例、原始事件、标准事件、证据和溯源数量的变化只能来自正常运行，不能由 UI 重构产生。

### D03 独立性

不新增到旧整合项目、源项目或 RWA 的运行时引用；公共 API 共享边界不变。

### D04 桌面能力

桌面启动、单实例、窗口记忆、冷启动、无窗口调度和旧入口保护继续通过。

### D05 自动化与真实点击

全量 Python、全部本地路由、前台真实路径、后台真实路径、详情返回记忆和长任务状态模拟全部通过。最终真实点击保持业务数据只读。

### D06 唯一路由角色

所有活动 HTML 页面都登记为 `front`、`admin`、`context-detail` 或 `host-only`，且只能登记一个角色。角色表页面总数与活动页面总数一致，无孤立页面。

### D07 前后台代码边界

前台不加载 `workbench-nav.js`、管理操作或后台页脚；后台不加载前台导航。桌面宿主只负责窗口和页面切换，不显示第三套可见导航、重复品牌尾缀或版本号。

### D08 遥测不影响更新

分别模拟运行状态写入成功、写入失败和页面断开。三种情况下现有更新组件的执行、数据库提交和快照重建语义保持一致；遥测失败只记录后台警告，不改变采集结果或研究结论。

### D09 未来大众发布边界

发布清单测试能排除 `admin` 页面和管理入口；本地桌面版保留右上角“管理工作台”，但普通用户不进入后台也能完成全部前台阅读路径。

## E. 双角色真实路径

### E01 普通用户路径

启动桌面入口 → 在机会首页理解当前判断 → 筛选全部机会 → 进入项目详情 → 返回并恢复上下文 → 查看重要变化 → 查看“我们如何判断”。全程不得出现后台术语、管理操作或可见版本号。

### E02 维护者路径

从前台右上角进入管理工作台 → 在 30 秒内判断系统状态 → 查看全量更新进度 → 定位聚合失败 → 返回机会中心。只读终验不得触发真实更新或修改业务数据。

### E03 桌面路径

验证启动、窗口位置记忆、重复启动单实例、关闭重开读取同一运行状态和本地 8766 端口。桌面快捷方式及旧入口保护保持不变。

## F. 放行规则

- P0 的 A01-A08、B01-B08、C01-C06、D01-D09、E01-E03 必须全部通过。
- 可见版本号必须满足：任意前台/详情页面为 0，任意后台页面为 1。
- Sol 先在一个任务内完成规划、设计和需求冻结，并在结束时提醒用户切换到 Luna。
- Luna 必须在一个任务内完成全部普通实现和开发自测，不得拆成多个 Luna 实现任务；完成后提醒用户切回 Sol。
- Sol 可修复冻结范围内的缺陷，并重新执行独立终验。
- 只有 Sol 全部通过后才能更新正式验收清单和发布状态。
- 两次模型切换均使用 `docs/MODEL_HANDOFF_PROTOCOL.md` 的固定提示；无法确认当前模型名称时，先提醒用户在 Codex 界面核对。
