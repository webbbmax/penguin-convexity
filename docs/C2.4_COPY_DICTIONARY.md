# 企鹅投研-凸性｜C2.4 用语字典

状态：正式冻结。页面出现同义旧词时，以本文件为准。

## 1. 主链固定用语

| 机器值/旧词 | 前台或后台固定写法 | 必须说明 |
|---|---|---|
| 90天新币筛选 | 90 天候选初筛 | 第一关，只判断是否值得继续检查 |
| firstGatePassed | 已进入深度跟踪 | 不是公开机会，不表示值得买入 |
| convexity tracking | 凸性跟踪 | 第二关，检查风险、退出、证据和结构 |
| publicEligible | 已达到公开底线 | 完成第二关并达到公开展示条件 |
| new_0_90 | 90 天内 | 只表示当前生命周期池 |
| continued_91_plus | 90 天后持续跟踪 | 曾在 90 天内完成两关，年龄不代表质量 |
| ageDays | 已公开流通第 N 天 | 由可核验 T0 和数据截止时间计算 |

禁止用“第一关机会”“初筛优质项目”“第 91 天淘汰项目”等容易把流程或年龄误解为投资结论的表达。

## 2. 三种公开状态

| 机器值 | 固定写法 | 大白话定义 |
|---|---|---|
| convexity_clue | 凸性线索 | 达到公开底线并形成至少两条独立强证据路径 |
| active_project | 活跃项目 | 达到公开底线，尚非凸性线索，但已有强路径或可核验真实活动 |
| observing | 观察中 | 已完成深度检查并达到公开底线，当前结构证据仍不强 |

“等待首轮跟踪”“数据受限”“来源失败”不得作为前台项目状态。它们只能在后台说明处理进度或来源状态。

## 3. 四条路径

| 机器值 | 固定写法 |
|---|---|
| trade_demand_formation | 交易需求形成 |
| liquidity_exit_quality | 流动性与退出质量 |
| supply_holder_improvement | 供应与持币结构改善 |
| indexed_pool_activity_vs_supply_adjusted_valuation | 已索引池活动跑赢供应调整估值 |

路径状态只写“已形成 / 尚未形成 / 当前不可用”。来源失败、缺失、不支持和单位不可比必须写“当前不可用”，不能写“未形成”或 0。

## 4. 首页与列表

- “今天先看”改为“按链看重点”。
- “同链前 10”必须配说明：“仅决定首页展示顺序，不限制跟踪和全部机会收录。”
- 单链排名写“同链相对排名”；全部链模式不显示总榜或跨链名次。
- 无完整贝叶斯结果写“尚无可复算排名”，不能写 0 分。
- 链内无项目写“本链目前没有完成第二关并达到公开底线的项目”。
- 全部机会无结果写“当前筛选条件下暂无符合公开底线的项目”。

## 5. 项目卡固定问题

1. 为什么现在进入关注。
2. 最关键的程序证据是什么。
3. 最大风险或反证是什么。
4. 接下来观察什么变化。
5. 数据截止到什么时候。

不得用“值得买入、稳赚、低估、百倍、胜率、目标价、建议仓位”替代上述内容。

## 6. 项目证据边界

- GitHub 单独构成证据时固定显示：“仅代码证据；不证明产品部署、用户采用或投资价值。”
- 缺项目证据固定写：“目前没有找到可核验并能归属到该资产的项目证据，暂不公开。”
- D 类固定写：“目前只有代币或交易池事实，项目主体尚未确认。”
- C 类固定写：“项目关系尚未完全确认；当前结论仅基于可归属证据。”

不得把缺证据自动写成“纯 Meme、骗局、项目不存在”或“资料不足所以项目差”。

## 7. 报价与风险

- `≤15%`：“100 美元标准卖出报价达到公开底线。”
- `>15% 且 <20%`：“当前退出成本偏高，只在后台观察。”
- `≥20%`：“当前标准报价出现严重退出异常，已撤下公开展示。”
- 报价缺失：“本轮没有取得可用卖出报价，等待后续重试；未按 0 处理。”

报价旁固定边界：“100 美元报价不代表其他金额、未来时点或极端行情一定可以退出。”

## 8. 更新中心

| 技术状态 | 用户可见写法 | 颜色/操作 |
|---|---|---|
| success | 最近一次已完成 | 绿色，无需处理 |
| no_data | 本轮没有返回可用数据 | 灰色，通常无需处理 |
| unsupported | 当前接口不支持 | 灰色，说明能力边界 |
| normal_zero | 本轮正常没有新增 | 灰色，不是错误 |
| quota_limited | 接口额度暂时用完，等待冷却 | 橙色；有明确条件时可重试 |
| source_failure | 来源连接失败，正在按断点重试 | 橙/红；显示影响和单项重试 |
| configuration_missing | 当前来源缺少必要配置 | 红色；显示配置项和影响 |
| program_failure | 更新程序未完成 | 红色；显示失败阶段和恢复入口 |

“需要处理”只统计额度、连接、配置和程序问题。能力边界必须与需要处理分开，不得用红色总卡混在一起。

两个更新页固定名称：

- 更新中心 → 90 天候选初筛
- 更新中心 → 凸性跟踪

固定操作词：立即更新、暂停新周期、继续上次未完成、只更新这个来源、仅手动、每小时、每 3 小时、每 6 小时、每 12 小时、每天。

## 9. 程序上限固定说明

前台高级说明必须包含：

“程序只根据已接入来源返回且能够复算的数据形成研究线索。公开底线、路径、贝叶斯和排名都不证明项目安全、低估、值得买入或未来上涨；来源缺失时程序不会凭空补齐。”
