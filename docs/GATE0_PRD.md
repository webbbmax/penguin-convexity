# 企鹅投研-凸性｜Gate 0 可恢复数据预检 PRD

状态：已冻结，等待 Luna 整版实现  
冻结时间：2026-08-08（Asia/Shanghai）  
适用范围：C2.1 前置 Gate 0；不等于冻结 C2.1 产品需求

## 1. 目标

Gate 0 本轮只解决一个问题：把已经存在的数据预检和 90 天历史回扫改造成**可恢复、可观察、与模型任务解耦**的独立后台工作流，并在支持范围内形成可由 Sol 独立验收的数据证据。

完成后，用户只需启动一次：

- Luna 完成常规编码、自测和小范围恢复演练后启动后台任务；
- Python 进程独立运行数小时或更久，Sol/Luna 对话均可结束；
- 断网、额度限制、进程退出或电脑重启后自动从已完成位置恢复；
- 用户从固定进度页查看状态，不需要反复回复“继续”；
- 完成后等待 Sol 终验、修复和放行，不退回 Luna 形成循环。

## 2. 本轮保护的既有成果

以下成果是实现基线，不允许 Luna 因个人偏好重写：

1. 现有 T0 边界：池创建事件只是 `covered_dex_lower_bound_not_global_t0`，不得冒充全局 T0。
2. 已登记的 18 个 EVM DEX 标签创建事件结构及其链上字段语义。
3. Solana 7/7 个观察 DEX 标签、13/13 种创建指令及其确定性解码语义。
4. 已接受 29 天 Solana 运行 `dex-backfill-20260805T0630474393727Z` 及其验证结果。
5. `no_data`、`quota_limited`、`source_failure`、`unsupported`、`configuration_missing`、`program_failure` 六类失败边界。
6. 实时稳定性 14 个不同自然日只作并行证据，不是项目观察期，不阻塞历史回扫、Gate 0 结论或 C2.1 冻结判断。

完整哈希见 `docs/GATE0_BASELINE_MANIFEST.json`。

## 3. 冻结实现范围

### 3.1 可恢复扫描

- 长任务必须先固定 `windowStart`、`windowEnd`、网络、协议结构、配置哈希和扫描计划。
- 每个扫描分片独立写入，完成后生成行数、范围、哈希和状态清单。
- 已完成分片不可覆盖；恢复时只运行缺失、失败或校验不通过的分片。
- 任何预计超过 15 分钟的任务，在启动前必须具备分片、原子检查点、可恢复游标、单实例锁和进度文件。
- 检查点至少在每个来源分页或扫描小区间成功后更新；不得等整条链完成才保存。
- 不得重新执行已经接受且与目标窗口、结构哈希重叠的 29 天数据；需要扫描目标窗口中更早和更新的缺口。
- 未完成 90 天运行的 `.tmp` 文件只保留审计，不作为检查点或正式结果。

### 3.2 独立后台运行

- 全量扫描由本机 Python 进程执行，不调用任何模型。
- 使用全新独立任务名 `PenguinConvexity-Gate0-Backfill`；不得修改 `PenguinConvexity-C1.8-Scheduler`。
- 后台任务在登录后及固定恢复间隔检查未完成状态；已完成时不得继续发送网络请求。
- 同一时刻只允许一个 Gate 0 回扫实例。
- Luna 启动后台任务并写入运行状态后立即结束模型任务，不持续轮询。

### 3.3 进度可见

固定入口：`reports/gate0-backfill-progress/report.html`。

进度页必须自动刷新并显示：

- 当前阶段与状态：准备、运行、额度等待、自动重试、暂停、完成、失败；
- 固定窗口、已完成/总分片、按链和协议的覆盖范围；
- 当前分片、请求数、事件数、候选代币数和最近心跳；
- 最近检查点、恢复次数、失败分类和受影响范围；
- 只有具备稳定速率时才显示预计剩余时间，否则显示“暂无法估算”；
- 协议结构覆盖与历史扫描进度分开，不用一个虚假总百分比掩盖不支持的协议。

### 3.4 支持范围边界

- 本轮历史回扫只对 `schema-registry.json` 中已经验证的 18 个 EVM 标签和已经验证的 13 种 Solana 创建指令承诺确定性解码。
- Ethereum 4、Base 8、Arbitrum 6 个尚无确定性结构的观察标签固定记录为 `unsupported`，Luna 不负责猜测或发明协议语义。
- Gate 0 通过表示“冻结支持范围内完成”，不表示全市场、全部 DEX 或全局 T0 完整。
- 是否在后续扩大协议范围，由 Sol 根据最终覆盖贡献和产品价值另行提出，不得在 Luna 实现中临场扩展。

## 4. 运行顺序

1. Luna 先补齐自动测试和报告测试缺陷。
2. Luna 实现分片、检查点、恢复、状态文件、进度页和独立后台启动。
3. 使用模拟来源与小范围真实数据完成中断恢复、重复启动、额度等待和损坏分片演练。
4. 所有开发验收通过后，Luna 只启动一次完整后台任务并结束对话任务。
5. Python 独立完成目标窗口、合并与最终机器校验。
6. 用户切换 Sol；Sol 按冻结验收计划独立复验，直接修复冻结范围问题并重新验收。

## 6. 程序能力边界

本轮程序能够保证任务可恢复、支持范围可审计、进度可见和结果可复算；不能保证上游永不失败、免费额度永不变化、未接入协议不漏项，也不能把池创建时间证明为代币全局首次公开流通时间。
