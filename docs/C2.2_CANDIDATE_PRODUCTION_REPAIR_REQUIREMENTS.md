# C2.2 候选生产化覆盖修复：正式需求

状态：正式冻结  
内部标识：`c2.2-candidate-production-repair-v1`  
产品版本：继续显示 C2.2，不新增用户可见版本号  
实施状态：等待用户另行授权

## 1. 修复目标

修复“4,590,214 个事件衍生候选中，4,585,726 个长期停留在 `discovered`，只有 161 个真正执行硬门槛”的生产化覆盖缺陷。全部候选必须获得可复算的本地基础扫描去向；符合宽条件的资产进入后台凸性跟踪，只有身份和产品证据闭环的 A/B/C 项目进入公开前台。

## 2. 固定四层漏斗

### L1 本地基础扫描

覆盖全部候选，不调用外部接口、不随机抽样、不设置热门项目上限。程序只可依据确定性地址、事件、时间和现有主库关系排除：重复、无效事件、未来时间、第 91 天、已知稳定/报价/包装/桥接/LP 资产、已知旧资产连续关系和可复现身份冲突。不得按名称、Symbol、简介、热度或 Meme 关键词排除。

### L2 公开市场确认

按链和地址批量确认公开池、资产方向、至少 1 笔买入和至少 1 笔卖出。不设置固定流动性、成交额、市值、FDV、TVL 或综合分门槛。市场未形成、未索引和来源失败必须分开保存；第 90 天前可以重新进入。

### L3 后台凸性跟踪资格

同时满足以下条件即可进入后台跟踪：接入范围内可复现 T0、第 0—90 天、公开池和资产方向一致、买入与卖出各不少于 1、没有已确认硬交易阻断。身份、产品、安全、供应或历史缺失保持待补全，不阻止后台跟踪、不写零。

D 类和身份待确认资产可以进入后台跟踪；贝叶斯缺失因子保持 `unavailable`，不得重分配权重，分数不得单独形成凸性线索。

### L4 公开机会前台资格

公开前台继续要求资产身份一致、项目映射可复现、至少一类合格产品证据、A/B/C 分类和无已确认硬阻断。D 类和身份待确认资产不得进入公开机会首页、全部机会、重要变化或公开项目详情；以后证据闭环后可以自动升级为 C。

## 3. 双队列和执行方式

- 使用现有 `PenguinConvexity-C1.8-Scheduler`，不得新增第二个长期调度器。
- 隐藏 Python 工作进程执行；同一时间只有一个候选生产化写入者，正式黑框为 0。
- 高优先级队列处理日常新增，低优先级队列处理历史积压；按批次交替，双方均不得饿死。
- 历史队列在六链之间轮转，处理优先级只代表时效，不形成质量权重。
- 分片完成并原子提交后即可逐批交给凸性跟踪，不等待全部历史完成。
- 关闭 Codex 或产品窗口不终止已启动工作；关机、休眠或进程中断后从最后原子断点恢复。

## 4. 无市场对象复查频率

| 日龄 | 复查间隔 |
|---|---:|
| 0—2 天 | 6 小时 |
| 3—7 天 | 24 小时 |
| 8—30 天 | 72 小时 |
| 31—90 天 | 7 天 |

频率只控制接口成本和时效，不进入评分、排序、状态或凸性算法。手动更新只处理到期对象和明确失败范围，不清空全部冷却、不从头运行历史候选。

## 5. 页面和控制

“90 天新币筛选”页面保留日常作业控制，并新增独立区域“历史候选基础扫描”。历史扫描、日常筛选、凸性跟踪必须分别显示作用范围和进度，不能合并成一个状态。

历史区域必须显示：已处理/总数、百分比、链、分片、队列、各去向数量、市场确认数、跟踪资格数、最近断点、心跳、运行时间、暂停/继续/失败范围重试，以及“不重新扫描 Gate 0 区块链历史”。只有形成稳定速度后才能显示 ETA 和可信度。

## 6. 接口与错误边界

接口按本地归并、批量市场、身份、产品、风险、深度凸性输入的顺序逐层调用。不能把全部候选同时发送给全部接口。单次请求使用有界重试；仍失败时保存 `no_data`、`quota_limited`、`source_failure`、`unsupported`、`configuration_missing` 或 `program_failure` 及下一重试时间。来源失败不改变项目基本事实，不冒充项目风险。

## 7. 数据和恢复边界

- 复用 Gate 0 已验收结果，不重新扫描 90 天区块链历史。
- 候选、状态、队列、分片、游标、来源健康和跟踪资格只写 `data/c2.1-pipeline.db`。
- 页面只读取原子快照，不读取正在写入的数据库。
- 正式迁移前备份并记录哈希、结构、核心数量、完整性和外键结果。
- 测试和桌面点击使用副本，不污染正式数据库、暂停、频率、任务和调度状态。

## 8. 明确不改变

不改变贝叶斯因子权重、P60/P70、美元护栏、标准卖出报价护栏、四条强路径、凸性线索定义、公开 A/B/C 身份要求、第 90/91 天边界和零人工项目复核定位；不新增链、DEX、付费 API、移动端、第二个调度器、大模型业务数据或自动交易。

## 9. 程序上限

程序只能在接入范围内形成可复算去向和证据，不能证明全市场无遗漏、全球真实 T0、所有身份关系、真实用户、完全排除 Meme/骗局/刷量、未来一定可卖出、项目值得投资或价格会上涨。

## 10. 发布门禁

只有独立验收完整通过，才能更新发布清单和状态。正式冻结不等于实施授权；没有用户另行明确开始开发，不得修改产品代码、迁移数据库或启动历史扫描。
