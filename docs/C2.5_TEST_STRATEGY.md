# 企鹅投研-凸性｜C2.5 测试策略

状态：正式冻结

## 1. 原则

C2.5 触及任务控制、状态组合、调度配置和全产品 UI，属于高风险版本。测试顺序固定为：任务登记与单一通道 → 控制与规则正确性 → 数据/快照 → 真实桌面 → 边缘兼容。Tier 0 或 Tier 1 失败立即停止，不能用页面数量或低优先级通过数抵消。

开发自测不写正式数据库、不点击正式产品中的写按钮。控制测试使用小型固定夹具、隔离运行目录和模拟 Windows 任务定义；真实正式桌面只读验收。

## 2. Tier 0：管理者控制权核心

1. 独立枚举 Windows 任务、隐藏脚本、生产 POST API、恢复入口和 21 个 `TASK_DEFINITIONS`。
2. 与 `C2.5_TASK_INVENTORY.json` 按稳定 `taskId` 对账：遗漏 0、重复 0。
3. 证明只有一个现役 Windows 调度器、一个 C2.2/C2.4 编排器和一套运行锁。
4. 两个现役主作业、两个候选队列和维护检查均有权威状态来源。
5. 旧 C1.8/C2.1、Gate 0 和手动 API 全部可见且分类正确。
6. 控制预览、确认令牌、幂等请求和权威回读正确。
7. 重复提交、令牌过期、状态漂移和已有运行锁均阻断第二次写入。
8. 安全暂停未到检查点前不显示完成。
9. 任务状态、业务数据时间和页面读取时间分离。
10. 历史 `running` 无有效进程/锁或心跳时显示陈旧。

任何一项失败，停止后续实现验收。

## 3. Tier 1：规则与控制边界

- 冻结基线、当前有效规则、活动试行和历史版本解析。
- 15%、20%、10% 报价条件和活动覆盖无空值。
- 有效规则解析器与实际代码逐项对账。
- 基线与有效规则用同一只读输入重放，集合差异可复算。
- 项目判定按 `assetId` 回到证据、数据时间、规则和快照。
- Gate 0 无启用/运行；历史队列无从头运行；旧版无误导现役按钮。
- 频率只允许 1/3/6/12/24 小时，不改变 Windows 15 分钟检查定义。
- 暂停一个作业不暂停另一作业或 Windows 调度器。
- 审计不包含密钥、令牌正文或敏感响应。

## 4. Tier 2：数据与继承

- 两个正式数据库只读 `quick_check` 与外键检查。
- `assetId` 交接、生命周期与跟踪状态分离。
- 原子快照完整性、生产者、消费者、对象数和数据时间。
- 29 个既有路由逐项返回正确内容。
- 普通用户前台不出现任务、调度、日志或管理控件。
- 管理工作台不读取 RWA 资产。
- 真实零、无适用、来源失败和程序失败不混写。
- 不用控制面快照替代现役业务状态。

## 5. Tier 3：真实桌面 UI/UX

- WPF 冷启动、重复启动单实例、窗口恢复和外链隔离。
- 1180×760、1440×900 或最大化。
- Windows 100%、125%、150% DPI；不是浏览器缩放替代。
- 八类信息域导航、详情进入返回、筛选/页码/滚动恢复。
- 按钮正常、悬停、按下、焦点、加载、禁用和失败。
- 瞬时、短时、确定进度、未知进度、暂停、部分成功和失败。
- 左右键、悬停、滚轮、文本复制、Tab、Shift+Tab、Enter、Space、Esc。
- 最小化、最大化/还原、关闭、拖动、缩放和贴靠符合 Windows。
- 视觉使用企鹅/南极蓝，未模拟 macOS 窗口或复制 Apple 资源。
- 图表具有精确表格、口径、时间和非颜色等价信息。

视觉验收必须检查真实截图/录屏，不接受只看 DOM、CSS 或自动测试结果。

## 6. Tier 4：边缘与恢复

- 无 Windows 任务权限、任务不存在、服务离线、状态文件损坏、日志缺失。
- 心跳陈旧、PID 复用、锁陈旧、Windows 任务返回 267009。
- 来源额度受限、部分来源失败、未知总量、总量变化。
- 审计追加失败时高影响操作如何阻断或明确降级。
- 页面后备快照陈旧、实时 API 恢复、网络短暂断开。
- 长文本、长机器 ID、无样本规则、空任务历史。
- 减少动画、键盘-only 和高对比度检查。

## 7. 固定夹具

至少建立：

- 一组现役正常任务、一组运行中、一组暂停请求、一组失败和一组陈旧状态。
- 一个 Windows 任务机器名与中文角色不同的夹具。
- 一个活动规则覆盖改变基线结果的真实样本和一个不改变结果的样本。
- 已知总量、未知总量和总量为真实零的三种进度。
- 同一 `requestId` 重复执行、过期令牌、状态漂移和运行锁冲突。
- 29 路由清单和 21 任务目录清单。

固定夹具必须是小型、去敏、可重复样本，不复制正式数据库。

## 8. 测试环境

- 开发在 D0 授权的独立 worktree 中进行。
- 隔离状态、日志和小型数据库夹具放入登记的 `runtime/temp-artifacts/<C2.5任务>`，结束后按策略封存。
- 正式 `data`、`runtime`、Windows 调度器和用户设置只读。
- 需要验证控制结果时使用依赖注入的假 Windows 任务和隔离运行器；不在正式环境试按运行、暂停或改频率。

## 9. 回归扩展

默认不重跑 Gate 0、459 万历史或全部历史网络请求。若实现触及共享核心、业务数据库迁移、实际调度器安装、C# 容器或原子快照核心，必须扩大相应回归并重新建立固定候选。

## 10. 报告格式

每项记录：要求 ID、测试 ID、预期、实际、证据、提交哈希、数据/状态时间、风险级别和结果。核心失败单独列出，不用总通过数掩盖。
