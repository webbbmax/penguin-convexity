# C2.4 Robinhood 与 Solana 核心链路修复记录

日期：2026-08-13（Asia/Shanghai）

性质：C2.4 发布后核心缺陷修复；不修改 C2.4 冻结需求，不重跑 Gate 0 或 459 万历史底座。

## 结论

“Robinhood 为 0、Solana 只有 1”不是候选发现层的真实结果。修复前诊断快照的第一关实际拥有 Robinhood 3,207 条、Solana 10,393 条；项目主要在首轮基础跟踪、旧主干调度和首页排名三个环节丢失或被延迟。

最新真实续跑后的原子公开快照为 51 个项目：Robinhood 30、Solana 19、Ethereum 1、Base 1。首页按链展示 Robinhood 10、Solana 10、Ethereum 1、Base 1；只有 1 个零实测项目继续保留在“全部机会”但不制造首页排名。

这些数量证明链路已经能把真实对象交给前台，不证明 50 个项目都具备投资价值。当前首轮队列仍未完成，公开集合会随真实基础跟踪继续变化。

## 已确认根因

1. **全池结构重任务放错位置。** 首轮每 25 个对象都会同步执行全池成交、OHLCV 和历史供应重建，一批曾耗时约 10 分钟。该层不是公开底线，却阻塞了 21,235 条基础队列。
2. **旧主干在队列中途重复插队。** 候选推进后仍运行继承的整套主干更新，导致当前核心队列被无关工作拖慢。
3. **一个局部来源失败会终止整轮。** 一批 25 条只要有 1 条可重试失败，整轮立即停止，直到下一次 15 分钟调度才继续。
4. **首页把有效贝叶斯结果全部误删。** C2.2 规定缺失指标保留中性先验；首页却错误要求五个因子全部已有实测。当前 49 个项目已有 8—10 个真实指标，但因产品使用增长因子暂未实测而全部被排除。
5. **Robinhood 缺少专用身份与报价路径。** 通用项目网站和通用 EVM 报价不足以处理 Robinhood Stock Tokens，导致真实资产不能稳定形成 B 类身份与卖出报价。
6. **历史百分比异常仍在影响公开。** 已取消的卖出损失、流动性下降、供应精度和跨来源价格偏差曾继续作为阻断条件；现只保留原始观测，不再作为本轮公开门槛。
7. **批内网络等待不受整轮时限约束。** 自动首轮曾为单个网站连续等待约 3 分钟。现在自动首轮采用 8 秒单次超时、最多两次尝试；失败按对象保存后继续。用户主动点击“只更新这个来源”仍保留原有耐心重试策略。

## 修复内容

- 首轮基础跟踪只完成市场、项目归属、显性硬交易阻断、当前供应和 100 美元只读卖出报价；全池结构与历史供应改为首轮完成后的独立可恢复层。
- 只要首轮队列仍有剩余，就先发布断点快照并返回，不运行旧主干。
- 旧主干只在首轮队列完成后运行；同一自然日完成一次后，后续结构增强续跑不再重复执行。
- 少量来源失败单独保留重试记录，本轮继续推进新对象；只有整批全部失败才停止，避免上游整体故障时反复撞接口。
- 自动首轮的单个网络对象改为短超时和两次尝试，不允许一个项目网站吞掉整轮时间预算；单项来源重试不受该快速策略影响。
- “完整贝叶斯结果”按冻结算法解释为：五因子后验均可复算且至少有一个真实指标。五因子全为中性先验、实测数为 0 的对象仍不参与首页排名。
- Robinhood 使用官方资产登记按链 ID 4663 和合约地址精确映射为 B 类“老项目新资产”；报价默认使用 Robinhood 官方公共 RPC，并根据 Uniswap V2/V3/V4 池结构执行只读报价，不签名、不发交易。
- Solana 继续使用 Jupiter 只读报价；首轮队列按链轮转，不把 10,393 条 Solana 对象永远排在其他链后面。

## “旧主干”实际更新什么

继承任务代码为 `c2_2_convexity_tracking_refresh`，只包含五类工作：

1. 证据链接健康；
2. 已归属正式项目的持续证据；
3. 主库中的市场、流动性、公开风险和退出事实；
4. Event Schema v2 数据主干；
5. 已有项目跟踪记录。

它不再发布旧机器评分、旧机器结论或旧催化交易路径。功能保留是为了兼容既有主干，但现在不能在 21,235 条首轮队列完成前插队。

## 全部隐藏任务盘点

现场只发现两个本项目 Windows 任务：

- `PenguinConvexity-C1.8-Scheduler`：唯一启用任务，每 15 分钟隐藏唤醒一次，只检查两个用户可控作业是否到期；作业新周期均为每 24 小时。它还每天最多一次清理已登记且到期的 `runtime/temp-artifacts` 临时产物。
- `PenguinConvexity-Gate0-Backfill`：已禁用，不会运行。

未发现本项目 Windows 服务、注册表开机启动项、Startup 启动文件或第二个业务调度器。桌面本地 HTTP 服务只负责页面读取，不采集数据。

459 万候选生产任务已经完成，当前没有全量扫描进程；它的历史状态文件仍保留用于审计，不代表后台还在继续扫描。

## 验证

- 定点 Python 测试：60/60 通过（规则、快照、调度、网络重试和候选跟踪修复）。
- 追加的运行控制回归：孤立失败不会终止新候选推进；整批失败仍会停止。
- JavaScript 语法检查通过。
- 原子公开快照构建 ID：`c24-public-7a8055698135dd41`。
- 当前快照：第一关 20,765、跟踪集合 20,765、首轮完成 3,907、来源待重试 20、公开 51、首页 22、未排名公开 1。
- 最新自动续跑从既有断点完成 900 条、36 批，约 11 分钟后正常退出，Windows 任务返回码 0；同等一轮的处理量比前一轮 525 条提高约 71%。与修复前“约 10 分钟只完成 25 条”的重结构批次相比，实测吞吐约提高 34 倍。
- `data/c2.1-pipeline.db` 只读 `quick_check=ok`，外键异常 0。
- 集合差集：`publicNotTracked`、`newTrackedNotQueued`、`trackedNotFirstGateHistory`、`continuedMissingHistory` 均为空。

## 当前边界和剩余风险

- 当前公开数量来自尚未完成的首轮队列，只能视为阶段性真实结果，不能视为 90 天全市场最终覆盖。
- Robinhood 的“官方登记”只证明资产登记、链和合约关系；不证明投资价值或全部合约安全。
- 100 美元报价只是当前时点只读模拟，不保证其他金额、未来时点或极端行情一定退出。
- Solana 已恢复项目数量，但当前前十并不自动等于知名项目或高质量项目。项目归属证据、数据覆盖和贝叶斯证据仍需随队列积累。
- Base 已从 0 恢复到 1；Arbitrum、BNB 当前公开仍为 0，不能宣称六链已经全部解决。完成首轮队列后，应按“项目证据交集、报价成功、确认硬阻断”三类逐链复核，而不是先猜测提高门槛或降低门槛。
- 即使首轮队列全部完成，现有适配器也不保证自动覆盖现实中所有优质项目。下一项产品级修复应是扩充可程序核验的项目证据来源和逐链标准报价适配器；这属于数据能力扩展，不能用放宽贝叶斯分数伪装解决。
