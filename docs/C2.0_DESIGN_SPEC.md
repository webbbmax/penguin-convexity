# C2.0 UI 与交互设计规格

状态：已冻结，属于 C2.0 需求锁  
范围：信号重要度、项目事件链、五段式摘要、判断质量中心和双角色上下文；不重做 C1.9 前后台架构。

## 1. 设计目标

1. 用户第一眼看到“当前判断”，第二眼看到“为什么现在值得看”，第三层才进入证据。
2. 重要程度必须由位置、字号、留白和信息密度共同表达，不只靠颜色或标签。
3. 优先展示宁缺毋滥；不足 5 个不补齐，真实空结果是完整设计状态。
4. 一张卡片只表达一个项目的一条当前判断，不把多个字段变化拆成同权卡片。
5. 后台先显示影响和处理顺序，再显示技术任务与原始日志。

## 2. 继承的视觉系统

沿用 C1.9 的 Logo、口号“洞见共识之外的价值”、浅色南极蓝体系、字体和 8px 间距系统。不得借 C2.0 重做品牌或回到大面积深色导航。

| 用途 | 固定值/边界 |
|---|---|
| 品牌主色 | `#0288C8` |
| 主文字 | `#102A3A` |
| 次文字 | `#587080` |
| 页面背景 | `#F5F9FB` |
| 卡片背景 | `#FFFFFF` |
| 分隔线 | `#DCE7EC` |
| 选中背景 | `#E8F5FB` |
| 成功/改善 | `#16866A`，必须配文字 |
| 警告/待确认 | `#A96812`，必须配原因 |
| 失败/收紧 | `#C34755`，只用于真实风险、失败或收紧 |

正文不低于 14/22，辅助信息不低于 12/18；数值使用 `Inter`/`Segoe UI` 并统一千分位。状态不能只靠颜色表达。

## 3. 机会首页

### 3.1 信息层级

```text
┌ Logo  机会首页  全部机会  重要变化  我们如何判断       管理工作台 ┐
├──────────────────────────────────────────────────────────┤
│ 数据提示（仅在过期、部分完成或沿用旧判断时出现）              │
│ 当前判断                                                     │
│ 是否可行动 · 主要限制 · 判断时间 · 下次复查                    │
├──────────────────────────────────────────────────────────┤
│ 现在必须看 / 值得继续看（合计最多 5 个）                        │
│ [项目 · 新事实与影响 · 首要阻断 · 下一触发 · 证据时间]          │
├──────────────────────────────────────────────────────────┤
│ 最近重要变化（最多 3 个项目事件链） │ 当前前三类主要阻断          │
└──────────────────────────────────────────────────────────┘
```

视觉权重：

- 一级：当前判断，首屏最高字号和最大留白，不使用大面积高饱和背景。
- 二级：优先信号，卡片首行是项目名、具体新事实和影响标签。
- 三级：数据时间、证据时间、状态说明和“查看全部”。

首页不得继续显示等权的项目卡片墙。当前没有合格优先信号时，优先区只显示一张真实空状态，不用“保持观察”项目填满。

### 3.2 优先信号卡

固定顺序：

1. 项目名与阅读层级；
2. 本次具体新事实或当前可行动事实；
3. `可能改善` / `可能收紧` / `尚不改变判断`；
4. 首要阻断；
5. 下一触发和证据时间。

首页卡片不完整展示五段式摘要；点击整卡一次进入详情。卡片不得重复显示两次动作标签，不显示分数、任务进度或技术字段。

## 4. 全部机会

- 保留项目搜索、现有维度筛选、重置和 20 条/页分页。
- 新增“阅读顺序”筛选：现在必须看、值得继续看、保持观察。
- 默认排序使用冻结字典序；每行提供“为什么排在这里”折叠说明，列出 1 至 3 条普通语言理由。
- 不显示综合分、阅读分、优先级分或无解释的热度排序。
- 项目摘要不完整时，在列表中显示“资料不足，暂不进入优先展示”和具体缺失段，不使用空卡片。

## 5. 重要变化

### 5.1 默认视图

- 默认只显示 `可能改善` 与 `可能收紧`，每页 20 个项目事件链。
- 同一项目同一轮的多字段变化为一张事件卡；同一字段 24 小时连续变化为一条可展开时间线。
- 卡片主层：项目、净变化、影响、为什么重要、事件时间、证据时间。
- “尚不改变判断”只在用户主动选择“全部变化”后显示。

### 5.2 时间线

```text
Across                                      尚不改变判断
24 小时成交额：700 万美元 → 922 万美元
比较范围：过去 24 小时；数据时间：16:00
为什么暂不重要：当前交易与退出判断未变化，单纯成交波动不改变动作。
[展开 3 个步骤] [查看项目]
```

展开层按时间升序显示每一步；中间动作、失效或阻断风险变化使用显著文字和图标，不得被折叠隐藏。证据来源和 URL 在二级展开，不在卡片首行堆叠。

### 5.3 数值

- 美元金额使用千分位和适当单位：`922 万美元` 或 `9,220,230 美元`，不得显示 `9.22023e+06`。
- 百分比保留最多两位小数并显示方向。
- 每个数字旁或同一语义行必须能看到单位、时间范围和比较基准。
- 口径不清时显示“口径尚未确认”，不显示原始精确值。

## 6. 项目详情

### 6.1 首屏五段式摘要

```text
[返回重要变化 · 第 2 页]
项目名称                                  当前动作：只观察
证据时间 2026-08-03 15:36 · 下次复查 2026-08-04 08:00

当前最强支持事实      …
当前最大阻断/风险     …
下一触发条件          …
失效条件              …
```

- 当前动作与其他四段形成清楚层级，不把五段做成五张同权彩色卡。
- 每段最多先显示 2 至 3 行；可展开查看证据、反面证据、来源和时间。
- 摘要不完整时，缺失段显示具体原因；整项不会进入首页优先展示。
- 详情仍不出现全量项目下拉框和顶级导航入口。

### 6.2 渐进展开

首屏后依次为：最近事件链 → 催化与传导 → 风险与退出 → 支持/反面证据 → 历史判断。页面最多两级展开；原始记录进入证据抽屉或后台详情。

返回按钮必须根据来源显示“返回机会首页”“返回全部机会 · 第 N 页”或“返回重要变化 · 第 N 页”，并恢复筛选、页码和滚动位置。

## 7. 判断质量中心

### 7.1 页面结构

```text
┌ 后台左栏 ┬ 判断质量                                  返回机会中心 ┐
│ 七栏目   ├──────────────────────────────────────────┤
│ 模型与规则│ 数据状态 / 生成时间 / 项目对账                         │
│ ·判断质量│ 七类覆盖漏斗                                           │
│          │ 共性阻断排行                                           │
│          │ 质量指标                                               │
│          │ 闭环队列（筛选、分页、进入处理页）                      │
│ 当前版本 │                                                        │
└──────────┴──────────────────────────────────────────────────────┘
```

“当前版本”在 Luna 实现阶段继续为 C1.9；Sol 发布后才变更为 C2.0。页面标题、正文和卡片不重复版本号。

### 7.2 七类覆盖漏斗

- 每一行代表一个判断维度，使用三段水平聚合条展示已闭环、待系统处理、待人工确认。
- 同时显示三个精确数量和总项目数；鼠标或键盘聚焦可查看判定定义。
- 不使用经典上宽下窄图暗示项目逐层被淘汰；七行是并列质量维度，不是转换漏斗。
- 点击某段直接过滤闭环队列，并显示当前筛选条件。

### 7.3 共性阻断排行

使用可排序表格，默认按冻结优先规则。列：阻断、前台影响、影响项目、责任方、最近执行、下次复查、状态、处理入口。

首屏显示前 10 项，其余分页。失败原因先显示普通语言摘要，原始错误折叠。相同阻断聚合，不平铺数百项目。

### 7.4 质量指标

指标使用紧凑统计条或表格，不使用七张同权大卡。每项同时显示分子、分母、定义和生成时间；值为 `null` 时显示“无法计算”。

### 7.5 闭环队列

- 默认按“对前台有影响、已过期/到期、失败/部分完成、等待最久”排序。
- 支持质量维度、责任方、状态和项目搜索；20 条/页。
- 每行只有“前往处理”一个主操作，链接到已有后台页面；不在判断质量中心新增绕过审核的写操作。
- 从处理页返回后恢复质量筛选、页码和滚动位置。

## 8. 交互状态

前台和后台都必须独立设计：

| 状态 | 前台 | 后台 |
|---|---|---|
| 构建中 | 显示正在更新和上次有效判断，不空白 | 显示阶段、心跳和上次有效指标 |
| 真实无信号 | 本期没有需要优先阅读的新机会 | 首页有效信号 0/5，状态正常 |
| 资料不足 | 说明缺失段与下次复查 | 进入闭环队列 |
| 数据过期 | 标出证据时间和影响范围 | 过期证据指标和影响项目 |
| 单位不明 | 隐藏精确数字，显示口径未确认 | 单位问题清单 |
| 部分完成 | 沿用成功数据并标范围 | 分子分母标记受影响 |
| 对账失败 | 沿用上次有效判断并明确失败 | 本轮指标不可用、上次有效数据保留 |
| 构建失败 | 不把旧数据写成当前 | 显示失败步骤与安全处理建议 |

禁止统一使用“暂无数据”或无限加载。

## 9. 响应式与可访问性

- 1280×720：当前判断和至少一个优先信号首屏可见；后台漏斗和阻断标题可见。
- 1440×900：首页完整显示当前判断、优先信号首行和两个辅助区；后台显示漏斗与排行前数行。
- 1920×1080：内容最大宽度保持，不把卡片无限拉宽。
- Windows 125%：无横向页面溢出，固定导航不遮挡内容。
- 键盘可访问导航、阅读层级筛选、分页、事件链展开、证据展开和处理链接。
- 焦点样式清楚；改善/收紧/资料不足均有文字和图标，不只靠绿/红/黄。
- 动画遵守 `prefers-reduced-motion`；事件链展开不改变用户滚动锚点。

## 10. 必需截图集

Luna 自测和 Sol 终验都至少检查：

1. 首页有 1 至 5 个有效信号；
2. 首页真实 0 个优先信号；
3. 首页数据过期/沿用上次有效判断；
4. 全部机会阅读层级筛选与排序理由；
5. 重要变化项目事件链折叠；
6. 重要变化事件链展开与中间风险步骤；
7. 数值单位正常和口径不明两种状态；
8. 项目详情完整五段式摘要；
9. 项目详情资料不足状态；
10. 判断质量七类覆盖条；
11. 共性阻断排行与闭环队列；
12. 判断质量对账失败/保留上次有效数据；
13. 1280×720；
14. 1440×900；
15. 1920×1080；
16. Windows 125% 缩放；
17. 后台唯一版本号位置。

## 11. 禁止的设计捷径

- 不通过给现有卡片换颜色来声称完成 UI 进化。
- 不通过增加一个数值分数来解决排序解释。
- 不把 5 个名额做成固定骨架并用通用文案填满。
- 不把原始变化逐条删掉来实现前台降噪。
- 不把后台质量指标、负责人或任务语言复制到前台。
- 不新增第三套导航、第二个后台壳或独立“项目详情”顶级入口。
