# C2.0 前后台用语字典

状态：已冻结，属于 C2.0 需求锁  
目标：前台解释“为什么先看、什么会改变判断”，后台准确表达“哪里影响质量、由谁处理”。

## 1. 固定名称

| 位置 | 固定用语 |
|---|---|
| 前台产品 | 凸性机会中心 |
| 前台导航 | 机会首页、全部机会、重要变化、我们如何判断 |
| 后台产品 | 凸性工作台 |
| 后台新页面 | 判断质量 |
| 后台一级归属 | 模型与规则 |
| 本地管理入口 | 管理工作台 |
| 后台返回 | 返回机会中心 |

不得新增“信号中心”“决策评分中心”“AI 机会榜”等会暗示新投资体系的产品名称。

## 2. 阅读层级

| 内部值 | 前台固定用语 | 含义 |
|---|---|---|
| `must_read` | 现在必须看 | 当前可行动，或新事实可能改变动作、失效、阻断风险或交易与退出判断 |
| `worth_following` | 值得继续看 | 有项目专属进展和下一触发，但尚未跨越行动门槛 |
| `observe` | 保持观察 | 没有需要优先阅读的新事实，继续留在全部机会 |

页面必须同时说明：`阅读顺序只决定先看什么，不是投资动作、评分、仓位或 L0-L5。`

## 3. 影响标签

| 内部值 | 前台固定用语 |
|---|---|
| `improve` | 可能改善 |
| `tighten` | 可能收紧 |
| `no_change` | 尚不改变判断 |

禁止使用“利好”“利空”“看多”“看空”替代上述标签；事实变化与价格方向不能自动等同。

## 4. 五段式摘要标题

1. 当前动作
2. 当前最强支持事实
3. 当前最大阻断或最大风险
4. 下一触发条件
5. 失效条件与证据时间

数据库或旧页面值“已失去凸性”只在显示层翻译为“失效/排除”，不得修改底层枚举或把它变成第六种动作。

## 5. 前台固定状态文案

### 5.1 无优先信号

`本期没有需要优先阅读的新机会。当前行动门槛保持不变，系统会按计划继续检查。`

### 5.2 资料不足

`资料不足，暂不进入优先展示。当前缺少：{missingParts}。系统将在 {nextReviewAt} 继续检查。`

没有下次时间时：

`资料不足，暂不进入优先展示。当前缺少：{missingParts}。后台尚未形成可确认的复查时间。`

### 5.3 当前没有可行动机会

`当前没有满足行动条件的机会。影响项目最多的限制是 {topReason}；本期 {signalSummary}。`

### 5.4 变化改善

`{factChange}。这可能改善 {affectedDimension}，但尚不自动改变当前动作。`

若动作已经由现有规则改变：

`{factChange}。现有规则已把当前动作由 {fromAction} 调整为 {toAction}。`

### 5.5 变化收紧

`{factChange}。这可能收紧 {affectedDimension}；请先核对风险、退出或失效条件。`

### 5.6 暂不改变判断

`{factChange}。当前 {affectedDimension} 和动作没有变化，因此暂不改变判断。`

### 5.7 口径不明

`该数值的单位或比较基准尚未确认，暂不显示精确值。`

### 5.8 沿用上次有效判断

`本轮判断质量快照未完整生成，以下沿用 {lastValidAt} 的有效判断，并标出受影响范围。`

## 6. 项目专属文案合格条件

`whyPriority`、最强支持事实、首要阻断和下一触发必须至少包含以下之一：

- 可核验的项目、资产、合约、来源或事件名称；
- 明确的价值捕获或退出关系；
- 带单位和时间范围的事实；
- 具体的风险类别、缺失事实和对行动的影响；
- 明确的下次事件、时间窗口或复查条件。

下列文本不能单独作为项目专属理由：

- 事实仍在积累；
- 风险与交易条件仍需继续确认；
- 代币价值捕获路径尚未核验；
- 最大风险：尚未确认；
- 资料待完善；
- 继续观察；
- 等待进一步发展；
- 本次为横向变化。

这些状态可作为补充，但必须与项目具体事实、影响和下一触发共同出现。

## 7. 后台判断质量固定用语

| 内部值/概念 | 后台固定用语 |
|---|---|
| `closed` | 已闭环 |
| `system_pending` | 待系统处理 |
| `human_pending` | 待人工确认 |
| 项目专属摘要覆盖 | 项目专属摘要覆盖率 |
| 重复模板 | 通用模板占比 |
| 事件合并 | 变化合并率 |
| 单位问题 | 前台缺少单位数量 |
| stale evidence | 过期证据影响项目数 |
| home signals | 首页有效信号数量 |
| traceability | 前台摘要可溯源率 |

每个后台质量问题先写：`影响什么 → 影响多少项目 → 谁处理 → 下一步 → 何时复查`，再展开技术字段和日志。

## 8. 后台状态模板

### 正常

`本轮判断质量快照已完成：{projectsTotal} 个项目已对账，首页有效信号 {homeSignals}/5。`

### 对账失败

`本轮项目或漏斗数量未能对账，当前指标不可用。上次有效结果保留；请先检查 {failedStep}。`

### 部分输入过期

`有 {affectedProjects} 个项目的摘要使用了过期或待刷新的证据。前台已标出时间，闭环队列将由 {ownerSummary} 继续处理。`

### 通用模板过多

`有 {affectedProjects} 个项目仍缺少项目专属解释；这些项目不会进入首页优先展示。`

### 当前无需操作

`当前无需人工操作。系统将按 {nextReviewAt} 的计划继续检查。`

## 9. 前台禁止词

除 C1.9 已禁止的任务 ID、Watcher、游标、调度、重试、日志、模型和版本术语外，前台主层新增禁止：

- 综合分、阅读分、优先级分、信号分；
- AI 推荐、模型认为值得买、胜率、预期收益；
- 质量漏斗、闭环队列、责任人、系统任务数；
- 失败任务数量、数据表、字段映射、去重键；
- C2.0 或其他业务版本号。

“我们如何判断”可以解释不存在新分数，但不得把内部规则文件、任务或后台指标列给普通用户。

## 10. 数字文案

- 美元：`922 万美元`、`9,220,230 美元`；同一组件内格式统一。
- 百分比：`上升 30.99%`、`下降 4.2%`；不使用裸 `+30.99`。
- 时间范围：`过去 24 小时`、`最近 7 天`，不能只写“近期”。
- 比较基准：`与上一轮 15:00 检查相比`，不能只写“发生变化”。
- 禁止科学计数法和无单位数值。

## 11. 版本号

- Luna 实现和开发自测期间：后台唯一位置仍显示 `当前版本 C1.9`。
- Sol 最终发布后：后台唯一位置改为 `当前版本 C2.0`。
- 前台、项目详情、桌面宿主、Logo、页眉、页脚和普通栏目始终不显示版本号。
