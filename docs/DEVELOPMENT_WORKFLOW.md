# 企鹅投研-凸性｜日常开发流程

## 用户只需要记住的三步

```text
讨论并确认大白话冻结稿
        ↓
开发实现 + 开发自测（只产出固定候选）
        ↓
独立终验 + 明确授权后发布
```

模型由用户决定。三步分开是为了固定责任和代码对象，不是模型门禁。

## 1. 规划与冻结

1. 先用大白话写清：解决什么、不解决什么、页面/数据/规则边界、程序上限、继承项、验收路径和回滚方式。
2. 用户确认后生成需求锁，记录正式文件路径、大小、SHA-256 和继承依赖。
3. 冻结只允许规划；用户没有另行说“开始开发”前，不得改代码、数据库、作业或正式入口。

## 2. 开发与自测

1. 正式 `main` 必须干净；每个写任务在 `F:\codex项目\企鹅投研\凸性-worktrees\<任务名>` 建独立 `codex/<任务名>` 分支。
2. 工作区不得复制正式数据库、凭据、运行状态或桌面用户数据。
3. 先建立“要求 → 实现 → 测试 → 证据”追踪表；Tier 0 主链路缺一项即停止。
4. 先写复现测试，再做最小修改；不顺手重构、不增加未冻结功能。
5. 测试按风险扩展：改动点 → 直接依赖 → 继承合同 → 真实主路径。边缘通过数不能抵消核心失败。
6. 自测通过后提交固定候选；开发任务不得自行合并、打正式标签或发布。

开发开始门禁示例：

```powershell
python scripts\d0_gate.py --config runtime\d0\development-gate-input.json
```

## 3. 独立终验

1. 终验开始先记录候选提交；后续验收和发布必须是同一提交，修复后则形成新候选并重验受影响范围。
2. 不相信开发报告本身；从需求锁、独立预期、固定样本和真实桌面路径重新验。
3. 顺序固定：Tier 0 集合/交接/发布结果 → 规则和恢复 → 真实桌面 → 边缘功能。
4. 真实点击默认只读，不触发正式更新、复核或数据写入。
5. D0 或触及共享核心、数据库、调度、桌面容器、发布时，必须完成相应回滚演练。

终验开始门禁示例：

```powershell
python scripts\d0_gate.py --config runtime\d0\acceptance-gate-input.json
```

## 4. 发布

1. 必须有用户明确发布授权。
2. 候选提交、终验提交、发布提交必须一致；正式 `main` 干净。
3. 重新执行密钥与数据边界扫描，确认没有数据库、日志、缓存、运行状态、凭据或临时副本。
4. 真实桌面验收通过后，记录正式标签、提交、核心文件哈希、远端提交和回滚点。
5. 发布失败只回滚代码和入口，不覆盖正式数据库，不改变用户暂停/频率设置。

## 5. 热修复

小型修复也要写清复现、影响边界和成功标准。若只影响单页面文案，可缩短回归；若触及核心链路、规则、数据库、调度、桌面容器或发布，仍必须独立终验。热修复不得借机改变冻结范围。

## 6. 后台与长任务

- 所有后台任务必须在交付说明中写明：任务名、作用、自动/手动方式、当前状态、进度位置、停止/恢复方式和失败影响。
- 预计超过 15 分钟的任务必须由独立程序维持，模型任务可以结束；是否持续监测由用户决定。
- 未具备单实例锁、分片、断点、原子检查点、可恢复游标、可见进度、心跳、错误分类、重试上限和终态时，不得启动长全量任务。
- 已完成范围不得因为重连、监测或换任务而从头重跑。

## 7. 临时文件与磁盘

大体积临时产物只放 `runtime/temp-artifacts/<任务>` 并登记；正常或失败结束都封存，默认 24 小时后按安全策略清理。任何自动清理都不得越过该目录，不得触碰 `data`、`backups`、正式 Gate 0、发布程序或运行状态。

## 8. 真相与冲突处理

优先级为：用户最新明确决定 → 当前需求锁 → `CURRENT_STATE.md` 与 `PRODUCT_BASELINE.md` → `STATUS.md` → `HISTORY_INDEX.md` 指向的历史记录。出现范围歧义、密钥风险、正式数据可能被写、候选漂移、核心集合不一致、桌面入口不匹配或回滚点缺失时，立即停止当前阶段并报告证据。
