# 企鹅投研-凸性｜D0独立验收计划

## 1. 验收原则

D0 是工程治理重置，不是业务版本。验收只证明版本、工作区、测试和发布流程可识别、可阻断、可恢复；不证明六链结果、筛选门槛或投资判断正确。

验收必须独立读取 D0 需求锁，不相信实现报告；不得为了通过而修改冻结文件。

## 2. A组：冻结与范围

- A01：三份 D0 正式文件与需求锁哈希一致。
- A02：D0 阶段为“已冻结、等待另行执行授权”。
- A03：当前用户可见产品版本仍为 C2.4。
- A04：产品代码、数据库、调度器、快捷方式和用户设置未因冻结动作改变。
- A05：C2.5、六链修复、规则调整和 UI 改造均未进入 D0。

## 3. B组：现状清单与保护

- B01：冻结时 154 个 Git 状态项都有原始路径记录。
- B02：每项只属于正式源码、正式文档、生成临时、运行数据、敏感配置、未知保留之一。
- B03：未知文件删除数为 0。
- B04：不存在 `git reset --hard`、整目录覆盖或未登记批量删除。
- B05：数据库、备份、Gate 0、运行状态和现役后台资产不进入清理目标。

## 4. C组：密钥与公开仓库

- C01：正式源码提交前完成受控密钥扫描。
- C02：已知 API Key、Secret、Token、数据库和日志不在待提交清单。
- C03：`.gitignore` 与公开边界测试覆盖数据库、运行状态、缓存、日志、桌面用户数据和临时副本。
- C04：高置信密钥命中为 0；疑似命中必须人工按文件用途确认后才能继续。
- C05：未通过 C01-C04 时，GitHub 推送被门禁阻断。

## 5. D组：C2.4重建基线

- D01：重建提交明确标注 `reconstructed-baseline`，不伪造原发布日期历史。
- D02：正式源码与文档均可由提交恢复。
- D03：运行数据库和大体积运行产物没有进入提交。
- D04：`main` 合并后工作区干净。
- D05：正式标签指向唯一提交，提交、标签和核心文件哈希均已记录。
- D06：公开推送后的远端提交与本地提交一致。
- D07：已知业务问题单独列出，基线不被描述为业务全正确。

## 6. E组：当前真相与历史保留

- E01：`CURRENT_STATE.md` 不超过约 100 行并能回答当前版本、提交、标签、任务、已知问题和下一授权。
- E02：`PRODUCT_BASELINE.md` 登记当前主干继承能力和零批准删除边界。
- E03：`DEVELOPMENT_WORKFLOW.md` 包含规划、开发、终验、发布和热修复。
- E04：旧 `AGENTS.md` 原文已保全，逐条规则都有新位置或明确保留。
- E05：历史文档未删除，历史索引可以定位。
- E06：当前真相文件与历史记录发生冲突时，优先级规则明确。

## 7. F组：门禁程序

- F01：脏 `main` 时开发开始门禁失败。
- F02：缺少冻结稿或需求锁哈希不匹配时失败。
- F03：开发不在允许分支或工作区时失败。
- F04：Tier 0 失败时终验和发布失败。
- F05：终验提交与发布提交不同时失败。
- F06：缺少桌面验收、回滚点或用户发布授权时失败。
- F07：密钥、数据库或运行数据进入待提交清单时失败。
- F08：全部条件正确时门禁成功。

## 8. G组：工作区与回滚

- G01：开发工作区位于冻结路径，正式数据库副本数没有因此增加。
- G02：开发工作区不能改写正式运行状态。
- G03：不同写任务使用独立 worktree，不同时写同一目录。
- G04：合并前后提交关系可追溯。
- G05：完成一次代码级回滚演练，不写正式业务数据、不改变用户暂停设置。
- G06：回滚后重新回到 C2.4 重建基线并保持 Git 干净。

## 9. H组：正式产品不受损

- H01：桌面快捷方式真实冷启动成功。
- H02：健康接口返回 C2.4，重复启动仍为单实例。
- H03：机会首页、全部机会、重要变化、我们如何判断和管理工作台只读可达。
- H04：D0 前后不因 D0 脚本写入两个业务数据库。
- H05：唯一 Windows 调度器、现役后台任务和用户暂停/频率设置未被停止、重启或改写。
- H06：没有重跑 Gate 0、459 万或 90 天历史扫描。

## 10. 测试范围与时间

D0 默认执行门禁自测、Git/密钥边界、目标文档哈希、真实桌面只读冒烟和受影响恢复演练。不默认重跑全部历史 Python 套件、完整 90 天任务或全量数据扫描。若发现共享启动器、服务核心或发布脚本发生跨边界变化，再按影响扩大测试并说明原因。

## 11. 发布阻断

以下任一情况阻断 D0 完成：

- 任一现状项未分类或未知文件被删除；
- 密钥、数据库或运行数据进入公开提交；
- `main` 不干净；
- C2.4 正式入口与重建提交无法对应；
- 门禁反向测试未能阻断；
- 正式桌面或现役后台任务受损；
- 回滚点缺失；
- D0 被用于修改产品业务或开始 C2.5。

## 12. 正式证据

执行完成后至少生成：

- D0 现状分类清单
- C2.4 重建基线清单
- 密钥和公开仓库边界报告
- 开发门禁测试报告
- 工作区与回滚演练报告
- D0 独立验收报告
- D0 完成清单

只有全部阻断项为 0，才能把 D0 标记为完成。D0 完成仍不自动授权下一产品版本。
