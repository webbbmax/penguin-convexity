# C1.9 Luna 一次性实现交接

状态：需求已冻结，等待 Luna；产品代码尚未开始  
实施职责：Luna 负责全部常规编码与开发自测；Sol 负责最终独立验收、缺陷修复与发布。

## 1. 开始门禁

Luna 开始前必须按顺序完整读取：

1. `AGENTS.md`
2. `docs/C1.9_PHASE.json`
3. `docs/C1.9_REQUIREMENTS_LOCK.json`
4. `docs/C1.9_PRD.md`
5. `docs/C1.9_PAGE_INVENTORY.md`
6. `docs/C1.9_DESIGN_SPEC.md`
7. `docs/C1.9_COPY_DICTIONARY.md`
8. `docs/C1.9_ACCEPTANCE_PLAN.md`
9. `docs/STATUS.md`
10. `docs/PROJECT_MEMORY.md`
11. `docs/DECISIONS.md`
12. `docs/RUNBOOK.md`

逐文件重新计算 SHA-256，并按需求锁的规范重算需求集哈希。任一文件不一致时停止，不得凭报告或记忆继续实现。

## 2. 单任务要求

- 在同一个 Luna 任务中持续完成 C1.9 全部常规编码和开发自测，不拆成多次 Luna 实现任务。
- 不向用户逐步索取已冻结的 UI、栏目、文案或交互选择；这些选择已经由 Sol 收口。
- 若发现需求互相矛盾、必须扩大范围或需要改变业务结论，停止实现并说明阻断，不自行修改产品设计。
- Luna 不做最终放行，不更新最终验收清单为通过，不宣布发布。

## 3. 实施顺序

### C1.9-00 基线与恢复保护

- 在修改产品代码前创建 `docs/C1.9_BASELINE_MANIFEST.json`，记录当前活动产品文件 SHA-256、活动页面/路由数量、测试数量、数据库逻辑数量和 SQLite 检查结果。
- 使用 SQLite 在线备份方式保存一致的开发前数据库副本，保存在本项目 `backups/c1.9-pre-implementation-<timestamp>/`；不得直接复制正在写入的数据库冒充一致备份。
- 备份活动前端、桌面壳、服务和测试文件或生成可恢复哈希清单；不得写入旧项目或其他业务目录。

### C1.9-01 独立前台壳、后台壳与设计令牌

- 桌面宿主只保留窗口与页面切换职责，不显示第三套可见导航、重复品牌尾缀或版本号。
- 建立浅色前台顶部导航和浅色后台左侧导航；共用冻结的颜色、字体、间距、按钮和状态令牌。
- 可见版本号只由后台共享壳在左侧栏底部渲染一次。

### C1.9-02 前台机会中心

- 实现机会首页、全部机会、重要变化、“我们如何判断”四个入口。
- 首页每块有明确数量上限；全部机会和变化使用分页，不使用无限滚动。
- 前台删除后台职责、后台术语、管理控件和可见版本号；不改变底层判断、动作和数据事实。

### C1.9-03 上下文项目详情

- 删除顶级“项目详情”导航和全量项目下拉框。
- 支持从首页、全部机会和重要变化进入；返回恢复来源、搜索、筛选、页码与滚动位置。
- 保留事实、项目方陈述与系统推断区分，证据与技术依据默认折叠。

### C1.9-04 后台工作台重组

- 所有现有管理页面归入冻结的七个一级栏目；建立机器可校验的页面角色表。
- 工作台概览首屏只显示系统状态、当前任务、待处理事项和最近结果，并只给一个主操作。
- 写操作、来源、证据、异常、重试、调度、日志和模型工具只存在后台。

### C1.9-05 长任务遥测与进度

- 将现有 18 个技术组件和页面快照重建映射为冻结的七个用户阶段。
- 保存阶段、真实计数、心跳、当前项目/来源、成功/失败/等待、开始时间与耗时；总量未知时不伪造百分比或 ETA。
- 区分正常运行、外部等待、可能卡住、部分完成和失败；相同失败按原因或来源聚合。
- 遥测状态写入失败不得改变采集、数据库提交、快照或研究结论；页面断开不得中止任务。

### C1.9-06 统一交互状态与可访问性

- 分别实现加载、真实零结果、数据过期、部分完成、更新失败、来源等待和可能卡住。
- 完成 1280×720、1440×900、1920×1080 与 Windows 125% 缩放适配和键盘访问。
- 生成冻结设计规格要求的十类验收截图。

### C1.9-07 开发自测与交回 Sol

- 执行 `docs/C1.9_ACCEPTANCE_PLAN.md` 中 A01-A08、B01-B08、C01-C06、D01-D09、E01-E03 的开发自测。
- 执行全量 Python、全部路由/资源、SQLite 完整性和外键、前后台真实点击、桌面启动/单实例/窗口记忆、运行状态持久性测试。
- 业务数据真实点击验收保持只读；不要为测试触发生产全量更新、复核或回写。
- 生成 `docs/C1.9_LUNA_IMPLEMENTATION_REPORT.md` 和 `docs/C1.9_LUNA_SELF_TEST.md`，准确列明通过、失败、未测和已知风险。
- 把 `docs/C1.9_PHASE.json` 改为 `luna_self_test_complete_waiting_sol`，然后停止继续执行。

## 4. 冻结范围的 P0

- 前台和后台是两套清楚的产品表面，不复用导航、页脚、管理控件和责任语言。
- 项目详情只从上下文进入并原路返回。
- 前台入口固定为四个；后台一级栏目固定为七个。
- 版本号规则固定为：前台 0、项目详情 0、任意后台页面 1。
- 全量更新运行中可看见七阶段、真实进度、心跳和失败范围。
- UI 为浅色、现代、层级清晰；保留 Logo、口号和南极蓝。

## 5. 禁区

- 不修改评分、动作、L0-L5、风险、剩余凸性、交易性、点火距离或生命周期规则。
- 不新增信源、Watcher、核心数据能力、自动交易或新的投资逻辑。
- 不写入或引用 RWA、旧整合项目、源项目；不改变公共 API 资源共享边界。
- 不用空白、合成或猜测数据覆盖历史证据与溯源。
- 不删除或覆盖桌面旧入口，不改变默认端口 8766 和独立单实例边界。

## 6. Luna 完成后的短口令交接

Luna 完成后只需告诉用户：

> Luna 已完成 C1.9 全部常规编码和开发自测，但尚未最终发布。请切换回 Sol，然后回复：“已切换 Sol，开始终验修复发布”。

用户无需复制实现报告或长提示。Sol 收到短口令后必须自行读取本项目阶段文件、需求锁、实现报告、自测报告和验收计划。
