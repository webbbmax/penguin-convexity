# C2.2 T0—新币第一关正式交接纠错发布

发布日期：2026-08-12（Asia/Shanghai）

## 大白话结论

用户指出的问题成立。上一轮虽然阻止了不合格对象进入凸性跟踪，却没有把历史底座确认出的约 1.5 万个对象完整、显式地交给新币第一关，因此页面仍显示旧的 T0 数字，无法证明历史底座真正经过了第一关。

本次把唯一正式链路固定为：

`历史底座或日常新增 → 公开市场确认 → 同步真实 T0 → 写入新币第一关显式队列 → 身份、A/B/C/D、产品证据、风险和宽硬门槛 → 只有通过的 A/B/C 进入凸性跟踪与前台`

历史底座不再直接进入凸性跟踪；“已存在一条旧评估”也不再自动等于完成第一关。

## 根因

1. 历史市场扫描的 T0 保存在候选生产记录中，但没有完整同步回新币筛选的候选记录，因此页面 T0 总数长期停留在旧值。
2. 第一关积压曾通过“缺少游标”临时推断，没有一张可对账的正式交接表，无法证明约 1.5 万个对象是否逐个移交。
3. 旧资格批次、旧评估和凸性跟踪记录的语义曾被混用，导致页面只能看到最终通过数，看不到“进入第一关、已完成、待处理”的完整漏斗。

## 修复内容

- 新增 `candidate_first_gate_queue` 显式队列；每个市场确认对象必须有唯一候选 ID、来源队列、状态、重试信息和完成时间。
- 市场确认时原子同步候选记录的真实 T0，并立即写入第一关队列。
- 对既有历史数据执行一次可恢复交接回填：只复用能证明使用当前规则且输入未过期的旧评估，其余对象保留为待处理，不伪造完成。
- 后台工作进程优先按每批 250 条消化第一关积压，完成后原子重建 C2.1/C2.2 快照，再从既有历史分片断点继续。
- C2.1 前台、C2.2 前台和凸性跟踪读取端都强制要求第一关队列状态为 `completed`；没有完成第一关的对象不能绕过。
- 更新中心把“T0 已核验总数、已进入第一关、第一关已完成、第一关待处理、通过硬门槛、当前前台”分开显示，并单列历史底座与日常新增交接量。
