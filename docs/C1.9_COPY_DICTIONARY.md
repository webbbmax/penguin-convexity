# C1.9 前后台用语字典

状态：已冻结，属于 C1.9 需求锁  
目标：普通用户先读懂判断，维护者再看到系统术语；同一概念不在前后台使用同一段后台文案。

## 1. 前台固定名称

| 位置 | 固定用语 |
|---|---|
| 产品首页 | 凸性机会中心 |
| 导航 1 | 机会首页 |
| 导航 2 | 全部机会 |
| 导航 3 | 重要变化 |
| 导航 4 | 我们如何判断 |
| 当前结论 | 当前判断 |
| 接近行动项目 | 离行动最近 |
| 不能行动的原因 | 当前主要限制 |
| 管理入口 | 管理工作台 |
| 后台返回 | 返回机会中心 |

“为什么还不能行动”不再作为栏目名；只允许在具体项目的解释句中自然使用。

## 2. 状态翻译

| 后台/技术表达 | 前台表达 |
|---|---|
| 项目主体待核验 | 尚未确认项目与官方主体的关系 |
| 可购买资产待核验 | 尚未确认应该通过哪个资产参与 |
| 市场与退出待闭环 | 目前无法确认能以可接受成本买入和卖出 |
| 价值传导待闭环 | 尚未证明事件会把价值传导给该资产 |
| 催化待发现 | 暂未发现可能改变判断的明确事件 |
| 待自动执行 | 系统将在下次检查时继续确认 |
| 调度尚未运行 | 系统尚未完成本轮检查 |
| 规则重算 | 系统重新评估后 |
| 分层未变 | 没有影响当前判断的新变化（前台默认不展示） |
| 任务失败 | 本轮检查未完成；以下是否沿用上次判断必须明确说明 |
| 部分完成 | 部分数据本轮未完成，已成功部分仍然保留 |
| 数据过期 | 数据已超过正常更新时间，当前判断可能滞后 |

## 3. 前台禁止出现的主层术语

以下词不得出现在前台导航、栏目标题、机会卡片、普通空状态和首层详情中：

- 任务 ID、负责人队列、来源适配、游标、Watcher、孤儿证据；
- 调度、重试、运行日志、后台作业、事件主干、规则回放；
- 模型验收、金标准校准、四层筛选、机器项目档案；
- 待闭环、待核验、待发现、尚未自动执行；
- M1.0、C1.7、C1.8、C1.9 等版本标签。

证据折叠层可以展示来源名称、抓取时间、事实/项目方陈述/系统推断和数据限制，但仍不得展示凭据、内部路径或密钥。

## 4. 后台语言规则

- 后台可保留准确技术名，但主标题先用普通语言，技术名作为次级说明。例如“来源接入（Adapter）”。
- 每个失败先写影响和处理建议，再写错误码和原始日志。
- “成功”必须说明成功范围；“失败”必须说明已成功数据是否保留。
- “自动跟踪”旁固定说明：由程序按计划执行；只有升级、停止或人工纠错才需要维护者确认。
- “当前无需操作”是合法且优先的后台结论，不得为了显得繁忙制造人工待办。

## 5. 长任务文案模板

### 正常运行

`正在进行第 {stageIndex}/{stageTotal} 阶段：{stageName}。最近活动 {heartbeatAge} 前。`

### 等待外部来源

`正在等待 {sourceName} 返回数据，已等待 {waitDuration}。超过 {timeoutRule} 后系统会记录为失败并继续处理其他项目。`

### 可能卡住

`已经 {heartbeatAge} 没有新进度，任务可能卡住。已完成的数据仍保留，请先查看当前阶段和日志。`

### 部分完成

`本轮已完成 {successCount} 项，{failedCount} 项未完成。成功数据已保留，失败项可单独重试。`

### 失败

`本轮更新未完成。影响范围：{impactSummary}。上次有效判断时间：{lastValidAt}。`

## 6. 前台信息模板

### 当前没有可行动机会

`当前没有满足行动条件的机会。主要限制是 {topReason}。系统会在 {nextCheck} 继续检查。`

### 没有重要变化

`最近 7 天没有发现足以改变当前判断的重要变化。最后检查时间：{checkedAt}。`

### 数据不完整

`本轮部分数据未完成，以下沿用 {lastValidAt} 的有效判断，并标出受影响项目。`

## 7. 版本号文案

唯一允许的界面文案是后台左侧栏底部的：`当前版本 C1.9`。

不得使用“C1.9 机会中心”“C1.9 项目详情”“工作台 C1.9”“M1.0 独立版”等页面标题或品牌尾缀。
