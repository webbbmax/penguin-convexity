# 企鹅投研-凸性｜C2.5 规则透明与治理契约

状态：正式冻结  
本文件只解释和治理规则版本，不修改 C2.4 规则。

## 1. 四层规则

1. 冻结基线：正式需求锁中的规则。
2. 当前有效规则：运行代码在本次评估真正执行的条件。
3. 临时覆盖：经批准且当前生效的试行或紧急覆盖。
4. 历史版本：过去规则、覆盖、结束原因和验证结果。

四层必须并排可比较，不能只显示“当前规则”。

## 2. 当前正式来源

- 冻结基线：`docs/C2.4_RULE_CONFIG.json`，规则版本 `c2.4-rules-v1`。
- 冻结依据：`docs/C2.4_REQUIREMENTS_LOCK.json`。
- 当前活动试行：`docs/C2.4_RULE_RELAXATION_TRIAL_20260813.json`，状态 `user_authorized_active_trial`。
- 运行实现：C2.4 规则解析与快照构建代码；实现阶段必须对账代码有效值与两份文件。

## 3. 已知基线与活动覆盖

### 3.1 冻结基线

- 100 美元标准卖出报价损失不高于 15% 才通过公开基线。
- 卖出报价损失达到 20% 属于严重立即退出条件。
- 流动性与退出质量强路径要求报价损失不高于 10%。
- 风险来源成功、无硬阻断或严重异常属于公开基线。
- 其他百分比、单位稳定和跨来源异常条件按 C2.4 规则配置执行。

### 3.2 当前活动试行

- 100 美元标准卖出报价成功即可；损失比例只记录。
- 风险来源缺失不冒充安全，也不直接淘汰。
- 确认冻结、黑名单、蜜罐或无法卖出等硬阻断仍立即停止。
- 项目证据、稳定身份与 A/B/C 关系仍是公开必要条件。
- 试行列出的六组百分比/单位门槛不作为当前门槛，但原始字段继续保存。

页面必须明确：试行可能增加召回，不等于安全、质量或投资价值提高。

## 4. 规则对象

每条规则必须提供：

```text
ruleId, plainName, plainDescription, domain, stage, baseline,
effective, difference, unit, status, sourcePath, sourceSha256,
approvedBy, approvedAt, effectiveFrom, effectiveUntil,
scope, inputs, missingPolicy, outputs, downstreamImpact,
counts, passExample, nonPassExample, history
```

`baseline`、`effective` 和 `difference` 不得互相覆盖。未知必须返回原因。

## 5. 有效规则解析

实现必须使用一个确定性解析器：冻结基线 → 验证覆盖文件状态和哈希 → 只应用已批准活动覆盖 → 输出完整有效规则和差异。前端不得自行合并 JSON。

解析失败时：

- 不把覆盖部分默认为 0 或 false。
- 页面显示“有效规则无法确认”。
- 高影响规则操作全部禁用。
- 现役任务是否继续按当前代码运行由既有任务安全策略决定，控制面不私自选择。

## 6. 影响统计

每条规则按同一截止时间提供：进入、通过、等待、失败、撤下、不适用数量及 `assetId` 集合摘要。基线重放与有效规则重放必须使用同一输入快照，才能展示差异。

低样本或真实零照实显示，不用模板样本补足。

## 7. 项目级解释

按 `assetId` 显示：

1. 身份、T0、链、合约和方向。
2. 原始证据及观察时间。
3. 每条规则输入和数据状态。
4. 冻结基线结果。
5. 活动覆盖是否改变结果。
6. 当前有效结果和大白话理由。
7. 下游生命周期、公开状态、排序和快照。

综合贝叶斯分只能解释排序、变化和校准，不能单独解释凸性线索或公开资格。

## 8. 规则变更流程

1. 管理者建立草案，写原因、目标、范围和结束条件。
2. 系统生成基线与拟议值差异。
3. 固定历史样本和当前只读样本分别重放。
4. 展示集合差异、数量、代表样本和反面样本。
5. 展示任务、快照、前台和回滚影响。
6. 管理者批准或拒绝。
7. 批准后生成独立版本化覆盖文件和审计。
8. 由下一次合法运行读取，不绕过锁和原子发布。
9. 到期、撤销或回滚保留历史。

触及第一关、第二关、四路径、贝叶斯、动作、L0-L5 或其他冻结产品体系时，界面只能生成“需要新版本冻结”的草案，不能直接批准生效。

## 9. 回滚

- 回滚目标必须是明确基线或历史覆盖版本。
- 回滚前显示受影响 `assetId` 集合、任务和快照。
- 回滚不删除在覆盖期间收集的原始证据和历史结果。
- 回滚通过合法运行重新计算和发布，不直接改写旧快照。
- 回滚记录包含操作者、原因、前后版本和关联运行 ID。

## 10. 禁止项

- 不提供无保护的生产阈值滑块。
- 不允许前端直接修改冻结 JSON。
- 不用英文机器码代替大白话。
- 不留空阈值或空单位。
- 不用当前通过数量判断规则正确。
- 不用大模型补证据、生成业务值或自动调参。
- 不把社交热度、价格上涨或低市值变成规则证据。

## 11. 验收

- 冻结基线与活动试行均能完整解析。
- 15%、20%、报价成功覆盖及被停用门槛无空值。
- 代码有效值与页面有效值逐项一致。
- 任一 `assetId` 可追到证据、规则、覆盖和快照。
- 基线/有效重放使用同一输入并输出集合差异。
- 无批准、过期、哈希不符和格式错误覆盖均不能静默生效。
- 规则回滚不删除历史证据。
