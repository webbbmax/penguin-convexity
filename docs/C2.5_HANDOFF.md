# 企鹅投研-凸性｜C2.5 实现交接

状态：正式冻结，等待用户另行授权开发。

## 1. 开始前

只有用户明确回复 `开始 C2.5 整版开发` 后才能执行：

1. 核验 `C2.5_REQUIREMENTS_LOCK.json` 全部哈希。
2. 核验 C2.4、C2.3、C2.2、D0 继承依赖。
3. 确认正式 `main` 无未解释改动；C2.6 并行文件不纳入 C2.5。
4. 在 `F:\codex项目\企鹅投研\凸性-worktrees` 建立独立 `codex/c2-5-manager-control-plane` worktree。
5. 建立要求 → 实现 → 测试 → 证据追踪表。

未获授权时不得创建 worktree、修改代码、数据库、运行状态、任务或桌面入口。

## 2. 实现顺序

1. 冻结清单解析与现场任务枚举器。
2. 权威状态组合、陈旧判定和时间口径。
3. 只读管理总览、任务账本和独立详情。
4. 规则有效值解析、项目判定和快照交接。
5. 预览/确认/幂等/审计控制层。
6. 仅接入已批准现役控制。
7. 整体设计令牌、基础控件和页面视觉对齐。
8. 隔离自测、真实桌面只读验收准备和固定候选。

Tier 0 任务对账未通过前，不进入控制按钮和视觉润色。

## 3. 允许修改

- C2.5 新页面、样式、脚本、只读组合 API、控制适配器和测试。
- 现有管理页为承载 C2.5 所需的精准适配。
- 项目内 `runtime/c2.5` 审计和组合快照实现。
- 为现有安全控制补统一预览、幂等和审计包装。
- 设计令牌和基础控件统一所需的样式修改。

每项必须追溯到冻结要求。

## 4. 禁止修改

- C2.4 第一关、第二关、四路径、贝叶斯、公开状态、L0-L5、风险和动作。
- 两个正式数据库结构或历史数据，除非重新冻结。
- Windows 现役任务定义、15 分钟检查、任务名或第二调度器。
- Gate 0、459 万历史范围和已完成分片。
- RWA 项目任何资产。
- C2.3 桌面容器业务边界和第二 C# 通道。
- 未批准删除的 29 路由或旧兼容资产。
- Apple 专属资源、macOS 窗口模拟和不符合 Windows 的输入行为。

## 5. 状态实现要求

- 页面不维护自己的运行状态真相。
- 进程、锁、心跳、Windows 任务、配置、检查点和快照依据一并返回。
- 陈旧规则由后端执行，前端只显示。
- 管理组合快照是只读派生和启动后备，不是权威状态。
- 审计是追加记录，不控制任务状态。

## 6. 控制实现要求

- 所有高影响操作先预览再执行。
- 一次性确认令牌、状态版本和 `requestId` 幂等。
- 现役函数直接调用，不通过服务自发 HTTP 绕一圈。
- 复用现有运行锁、暂停请求和检查点。
- 没有安全合同的旧任务只显示，不新接直接控制。
- 后端结果回读后更新页面；禁止乐观成功。

## 7. 设计实现要求

- 先生成唯一令牌表和基础控件状态样张，再铺页面。
- 保留企鹅、口号和南极蓝。
- Apple 原则用于视觉层级与反馈；Windows 用于窗口和输入。
- 前后台共享基础组件但不共享壳和权限。
- 视觉终验用真实截图和录屏，不用 CSS 检查替代。

## 8. 测试与数据

- 控制自测只用小型固定夹具和隔离 runtime。
- 不复制正式数据库进 worktree。
- 正式桌面验收默认只读，不点击运行、暂停、改频率或规则。
- 若需要受控写验收，必须使用隔离任务适配器并证明正式状态哈希未变。
- 临时产物登记在正式策略允许的任务目录，任务结束封存。

## 9. 开发交付

开发任务必须交付：

- 实现提交完整哈希。
- 要求追踪表。
- 任务枚举对账结果。
- 规则有效值对账结果。
- 控制反向测试。
- 29 路由继承结果。
- 基础控件状态样张和真实桌面截图。
- 两库只读完整性与正式资产未写证明。
- 临时产物状态。
- 已知问题、回滚点和独立终验入口。

开发任务不得自行合并 main、打正式标签、切换正式入口或发布。
