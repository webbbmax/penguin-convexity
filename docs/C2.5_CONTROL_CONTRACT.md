# 企鹅投研-凸性｜C2.5 管理控制契约

状态：正式冻结

## 1. 核心约束

管理操作必须复用当前唯一调度器、业务编排器、运行锁、检查点和状态来源。C2.5 只增加受保护的管理入口，不增加第二调度器、第二任务状态或第二业务写通道。

## 2. 操作级别

| 级别 | 示例 | 是否确认 |
|---|---|---|
| 只读 | 查看、筛选、复制、打开日志 | 否 |
| 低影响 | 刷新管理组合状态 | 否 |
| 高影响 | 立即运行、暂停、恢复、改频率、来源/分片重试 | 必须预览与确认 |
| 禁止 | 强杀进程、启用 Gate 0、重跑 459 万、直接改冻结规则 | C2.5 不提供 |

## 3. 两阶段控制

### 3.1 预览

请求：`requestId`、`taskId`、`action`、`parameters`。  
响应：当前状态、拟改变值、读写对象、冲突任务、前台影响、预计恢复方式、是否允许、拒绝原因、一次性 `confirmationToken`、过期时间。

### 3.2 执行

请求必须带原 `requestId`、未使用且未过期的 `confirmationToken`。后端再次读取真实状态；状态漂移时拒绝，要求重新预览。成功接受返回 `auditId`、`backendStatus`、`runId` 或暂停请求状态。

同一 `requestId` 具有幂等性，不得重复启动任务。

## 4. 现役作业能力

### 4.1 `c22.screening`

允许：立即运行、从检查点恢复、安全暂停当前运行、暂停/恢复后续周期、频率 1/3/6/12/24 小时、底层登记来源重试、查看日志和影响。

约束：使用现有 C2.2 编排器；筛选需要与候选生产安全交接；已有写入锁时拒绝第二写入者。

### 4.2 `c22.convexity_tracking`

允许项同筛选；来源重试只限现有支持的来源。进度和部分完成必须使用当前跟踪检查点。

约束：不能跳过筛选输入、稳定 `assetId` 或快照对账；不能直接调用旧主干绕过当前编排。

### 4.3 候选生产日常队列

允许：查看、从现有分片恢复、安全暂停、取消暂停、重试明确失败分片。

约束：不允许选择任意历史范围，不允许重建已完成分片，不允许并发写采集库。

### 4.4 已授权历史队列

已完成时分类为 `completed_one_off`。只有数据库存在未完成/失败分片且原授权仍有效时，才能提供“从检查点恢复”或“重试所选分片”；不能提供“从头运行”。

### 4.5 临时产物保留检查

允许：查看登记和到期阻断；可在影响预览后运行一次现有 `sweep --min-interval-hours 24` 检查。它只能按冻结策略处理 `runtime/temp-artifacts` 已登记直属子目录。

## 5. 旧版和停用入口

### Gate 0

只读显示任务定义、停用状态和历史结果；禁止启用、恢复或运行。

### C1.8 与 C2.1

显示实际 API、脚本、配置、读写对象、是否仍可执行和与现役主干关系。C2.5 默认不提供运行或改配置按钮，因为这些入口未完成现役安全合同；也不删除现有入口。未来处置必须另行批准。

### 21 个 `TASK_DEFINITIONS`

`c2_2_convexity_tracking_refresh` 作为现役内部组件由凸性跟踪包装器调用，不提供绕过包装器的直接运行按钮。其余任务按任务清单显示；未逐项完成锁、检查点、影响和回滚合同的，只显示既有可执行事实，不在 C2.5 新控制面直接触发。

## 6. 安全暂停

- 记录暂停请求和目标任务。
- 当前步骤继续到合法原子边界。
- 保存已完成结果、检查点和心跳。
- 进入 `safe_paused` 后才显示暂停完成。
- 超时仍显示 `pause_requested`，不得谎称已暂停。
- 强制杀进程不属于普通管理能力。

## 7. 自动周期暂停

暂停后续周期只改变对应现役作业的 `paused` 配置，不停 Windows 唯一调度器，不影响另一现役作业，不改变候选生产原授权。恢复时重新计算作业到期时间并显示。

## 8. 修改频率

- 只允许 1、3、6、12、24 小时。
- 预览显示来源额度、任务重叠和下次到期变化。
- 不改变 Windows 每 15 分钟检查任务的触发定义。
- 配置写入成功后从权威配置回读。

## 9. 重试

- 来源重试必须指定任务和已登记 `sourceId`。
- 分片重试必须指定存在的 `partitionId`。
- 对象重试只有底层有稳定对象检查点时可用。
- 重试保留成功结果，不从头重跑完成范围。
- 不支持局部重试时按钮禁用并说明。

## 10. 失败和并发

- 已有运行锁：返回 409/`already_running`，不启动第二写入者。
- 状态陈旧：禁止高影响操作，先要求恢复状态一致性。
- 快照校验失败：保留上一份完整快照，禁止发布不完整结果。
- 后端异常：页面状态不乐观变化，记录失败审计。
- 单个来源失败不自动升级为全局失败；影响范围单独返回。

## 11. 审计

每次预览和执行写入追加式记录：操作者、来源、请求 ID、令牌 ID 摘要、任务/规则、前值、拟议值、影响、后端接受、运行 ID、终态和回滚。不得记录密钥、完整令牌或敏感响应正文。

## 12. 回滚

- 任务频率/暂停：回滚到审计记录中的前值并重新回读。
- 运行启动：不能“撤销已经发生的事实”；只能安全暂停后续步骤。
- 规则覆盖：按规则透明合同回滚至明确版本。
- 数据与快照：遵循现有原子快照和备份规则，控制面不得直接覆盖数据库。

## 13. 验收反向测试

必须证明：重复提交不重复启动、过期令牌拒绝、状态漂移拒绝、无锁绕过失败、Gate 0 无运行按钮、旧 C1.8/C2.1 无误导控制、未知总量无假百分比、暂停未到安全点不显示完成、失败操作有审计且状态未假变。
