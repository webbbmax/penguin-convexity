# 企鹅投研-凸性｜C2.1 冻结稿

状态：**等待用户确认；当前尚未冻结、尚未编码、尚未生成需求锁**  
版本名称：C2.1「90 天新发项目自动筛选与可解释前台」  
适用终端：现有 Windows 桌面产品  
整理日期：2026-08-10（Asia/Shanghai）

## 1. 用户需要确认的一句话

> C2.1把Gate 0已经发现的90天候选母池生产化，自动核验T0、项目关系、买卖、产品证据和显性风险；全部通过宽硬门槛的A/B/C项目进入前台，再分为凸性线索、活跃项目、新发观察、持续观察和数据受限。系统不做人工逐项目复核，不输出投资动作，也不开发移动端。

## 2. 本版本交付什么

1. 复用Gate 0已完成的六链登记协议90天结果，并从最后游标做日常增量，不重新跑已经接受的90天区间。
2. 对接入范围内全部候选执行确定性基础扫描；只对达到明确前置条件的对象执行高成本深采，不随机抽样、不只追热门项目。
3. 建立目前查到的最早公开流通证据T0，区分A新项目新币、B老项目新资产、C项目关系未确认、D只有代币。
4. 全部通过宽硬门槛的A/B/C对象进入前台；D类只留后台。综合分、强路径和14天历史都不控制前台资格。
5. 用四条确定性强证据路径形成“凸性线索”，用P70活动、代码、产品使用或流动性持续形成“活跃项目”。
6. 手动立即更新和可选自动更新使用同一隐藏、单实例、可恢复流水线；前台始终读取上一次完整快照。
7. 改造现有四个前台导航、项目详情和相关后台管理页面；不增加第五个前台顶级栏目。

## 3. 程序最多能做到什么

- 在六链已登记协议和已接入来源范围持续发现候选，并明确显示接入范围和可能漏项。
- 保存可复现T0证据，发现更早证据时向前修正。
- 自动识别明确的旧币新池、包装、桥接、迁移和重复关系。
- 检查历史买卖、当前标准卖出报价、流动性、成交、公开合约权限和已知硬风险。
- 读取已索引池OHLCV、历史供应、产品时间序列和可获得的持仓历史，按冻结公式形成路径。
- 在来源失败、额度耗尽、关机或进程中止后，从已提交游标恢复。

## 4. 程序仍然不能做到什么

- 证明覆盖全市场、全链或全球所有DEX池。
- 证明T0一定是全球真实首次流通。
- 完全排除伪装GitHub的Meme、骗局、刷量、女巫、关联钱包或未公开控制关系。
- 保证未来可以卖出、不会抽池、没有未知后门。
- 证明项目靠谱、市场低估、未来成功或上涨。
- 输出建仓、仓位、买卖点、收益概率或自动交易。

## 5. 前台资格：宽硬门槛

对象必须同时满足：

1. T0为接入范围内已核验公开流通证据，当前第0—90天。
2. 分类为A、B或C。
3. 代币、网络、交易池和资产方向一致。
4. 已观察到真实公众买入和真实公众卖出。
5. 没有已确认卖出失败、冻结、黑名单、流动性归零、资产身份冲突等硬阻断。
6. 至少具有一类合格产品证据：官方非空代码仓库、已部署产品合约、结构化业务数据、已执行代币功能或可复现链上产品使用。

固定成交额、市值、TVL、综合分、满14天和五因子齐全都不是前台硬门槛。GitHub单独通过时必须显示“仅代码证据；不证明产品部署、用户采用或投资价值”。

## 6. 五种互斥状态

优先级固定为：

1. 数据受限：关键数据暂时不能更新，保留上次完整记录并显示时间。
2. 凸性线索：形成至少两条强路径，其中交易与流动性为必选。
3. 活跃项目：没有形成凸性线索，但存在冻结的真实活动证据。
4. 新发观察：真实历史不足14天，尚未形成强/弱线索。
5. 持续观察：真实历史已满14天，尚未形成强/弱线索。

14天不是等待期，不影响前台资格；未来日期不计零、不计缺失。

## 7. 四条强证据路径

### 路径一：交易与流动性形成（凸性线索必选）

- 流动性达到同链同日龄P60，并达到年龄护栏：0—6天2,000美元、7—30天3,000美元、31—90天5,000美元。
- 成交额、交易笔数、成交额/流动性三项至少两项达到P60。
- 观察到买入和卖出各不少于1笔。
- 100美元标准卖出报价成功，估算损失不高于10%。
- 报价缺失或不支持时路径不可用，不补零；项目仍可在前台其他状态中显示。

### 路径二：真实产品使用扩张（有数据才启用）

- 产品身份和指标映射确定，两个等长窗口定义一致。
- 当前值不少于5、比前期至少增加3、增幅不少于20%。
- 价格、社交、Star和项目方宣布不能构成本路径。

### 路径三：供应与需求结构改善（有历史才启用）

- 前十地址占比下降至少5个百分点，或持仓HHI下降至少10%，或总供应减少至少0.5%。
- 同期交易活动不低于同组P50，供应单位前后一致。
- 只有当前快照或供应保持不变不能形成路径。

### 路径四：已索引池活动超过供应修正估值变化

- 只汇总来源已索引且可返回OHLCV的池；未索引已发现池显示数量并降低可信度，不补零、不自动淘汰。
- 历史供应成功且单位稳定。
- 成交活跃相对供应修正估值的扩张达到同日龄P60。
- 成交活跃变化必须大于估值变化的绝对值。
- 不允许使用“全球全池”或“全市场成交”表述。

首版现实可用的主要组合是路径一＋路径四；路径二和路径三只有真实历史存在时才参与。

## 8. 进入、退出与异常

- 所需前后真实窗口形成后，一次完整评估即可进入，不要求再等固定天数。
- 正常退出需要两个新的连续完成窗口低于退出规则；退出使用同组P50，相同窗口重复运行不累计。
- 来源失败、额度受限和配置缺失不算一次未通过，转为数据受限并保留上次完整结果。
- 第91天、硬门槛失败、已确认卖出失败/冻结/黑名单立即退出。
- 流动性在可比窗口下降80%、100美元卖出损失达到20%或供应单位改变，立即撤下凸性线索并重新计算资格。
- 最大池成交占比和池HHI只提示集中度，不能单独认定刷量或淘汰项目。

## 9. 动态评分与可信度

- 五因子权重保持D25%、L25%、S20%、G15%、Q15%。
- 分数只用于后台排序、变化和后续校准，前台不显示“多少分等于凸性线索”。
- 同链同日龄P60/P70优先使用30天滚动真实对象；样本不足时按冻结后备基线。
- 缺失字段不写0、不跨因子重新分配权重。
- 可信度独立计算：字段覆盖35%、数据时效25%、真实历史20%、跨来源一致性20%。
- C2.1不能宣称算法已经越来越准；时间外校准属于C2.2。

## 10. 更新与恢复

- 后台提供立即更新、仅手动、每小时、每3小时、每6小时、每12小时、每天和暂停。
- 发布时原样继承当时用户启停与频率，不擅自改变。
- 手动和自动写同一个 `data/c2.1-pipeline.db`；`data/convexity.db` 首版只读。
- 单写入者、事务先提交再推进游标、前台原子读取完整快照。
- 单次请求5/15/60秒重试3次；仍失败后保存断点并按冷却计划恢复，不无限快速重连。
- 正式桌面路径黑框为0；关闭产品或Codex后任务继续；关机后在下一次Windows登录时恢复。
- 不创建第二个长期调度器，不恢复一次性Gate 0任务，不重跑已完成90天区间。

## 11. 页面与桌面范围

- 前台仍为机会首页、全部机会、重要变化、我们如何判断；项目详情不是顶级导航。
- 首页最多8个真实项目；全部机会默认“全部”、五状态标签、20条分页。
- 重要变化必须解释前后变化、影响原因和数据时间，不做普通行情流水。
- 后台继续使用七个一级栏目，管理更新、来源、规则、进度和失败。
- C2.1只支持Windows桌面产品。验收1180×760和1440×900/最大化；不开发手机、平板、移动端响应式布局或移动发布包。

用户明确回复“按冻结稿冻结C2.1”后才执行：

1. 把八份候选文件转换为无`DRAFT`后缀的正式文件，内容不得临场改变。
2. 计算SHA-256并生成 `docs/C2.1_REQUIREMENTS_LOCK.json`。
3. 生成 `docs/C2.1_PHASE.json`，阶段记为需求已冻结、等待实现。
4. 更新项目状态、记忆、决策和运行手册中的C2.1阶段。
5. 再开始冻结范围内的C2.1产品开发。

当前任何候选文件都不构成产品实现授权。
