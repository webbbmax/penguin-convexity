# 企鹅投研-凸性｜C2.3 风险分层测试策略

状态：正式冻结

## 1. 原则

测试范围由实际改动和故障传播范围决定。测试时间长、用例数量多和反复全量运行不能替代真实用户路径。每次测试必须说明：改了什么、可能影响什么、为什么选择这些测试、什么条件会扩大范围。

## 2. 开发反馈层

| 改动类型 | 默认测试 | 扩大条件 |
|---|---|---|
| 文档或用语 | 编码、结构、链接、需求锁哈希 | 正式契约含义改变 |
| 单页局部样式/交互 | JS语法、该页交互、相关路由、真实渲染 | 修改共享样式或公共脚本 |
| 公共页面壳/导航/API | 所有直接消费者和现役路由冒烟 | 契约或共同快照变化 |
| .NET容器 | .NET单元、启动协议、健康冒烟、正式快捷方式路径 | 影响Python服务协议、调度或数据库 |
| 业务规则/数据库/调度 | 改动模块、迁移、直接下游回归 | 共享核心变化或影响边界不明 |

- 快速反馈目标：5分钟内。
- 受影响回归目标：20分钟内。
- 超过目标先拆分定位并说明必要性，不得每次小修改都启动数小时测试。

## 3. 缺陷修复层

1. 先建立稳定复现缺陷的自动测试或真实操作路径。
2. 修复后先跑复现项，再跑受影响组件和直接下游。
3. 局部失败不从头反复运行无关测试。
4. 只有共享核心、数据库迁移、调度或影响边界不明时才升级全量回归。
5. 发布前只执行一次与最终改动范围相符的完整验收。

## 4. C2.3 独立终验范围

必须覆盖：

- 正式快捷方式冷启动、热启动、重复启动唤醒。
- WPF窗口位置、大小、最大化、多显示器恢复。
- Chrome和普通Edge同时使用时的进程、窗口和配置隔离。
- 容器自有服务与外部已运行服务的所有权边界。
- 后台候选生产、新币筛选、凸性跟踪和调度不受启动、关闭、崩溃、修复影响。
- WebView2缺失、Python缺失、端口冲突、健康失败、页面异常五类故障。
- 1180×760、1440×900、最大化真实页面可用性。
- 现役页面和接口快速冒烟、业务冻结资产哈希、数据库只读完整性。
- 旧启动器回滚和正式快捷方式恢复。

不默认运行全部历史Python测试。若业务代码、规则、数据库结构、共同快照、调度器和共享写入链的实现前后哈希一致，则以契约和冒烟证明继承。任何意外差异都会触发对应回归扩大。

## 5. 长任务

- Gate 0、候选生产、全量第三方采集、长期观察和数据库压缩不是测试。
- 不为C2.3验收重复启动、暂停或等待这些任务完成。
- 预计超过20分钟的测试必须独立运行、显示进度、设置超时并保存结果。
- 模型不在对话中无期限等待来维持测试。
- 正在运行的后台任务只核验原PID或可恢复接替PID、runId、断点和进度连续性。

## 6. 质量底线

缩短时间不能靠跳过真实桌面路径、忽略失败、只看静态文件或降低发布标准。优先删除无关回归，不能删除与改动风险直接相关的证据。
