## 返回 Luna 的精确修复清单

1. **修复并实装 Windows 计划任务。** 任务必须以本项目独立名称安装成功，不覆盖其他软件；在隔离数据库/快照下完成“关闭窗口 → 到点唤醒 → 执行 → 状态落库”的真实测试。若普通用户权限不足，安装流程必须给出清楚、可执行的授权提示，不能把未安装显示为运行正常。
2. **改为实时选择到期项目。** 每小时检查必须从本项目数据库按当前时间计算到期任务及所需来源，不能依赖上一次生成的静态页面快照；补充“时间推进后从 0 变为到期”的回归测试。
3. **修复调度安全入口。** `-RunOnce -DryRun` 必须真正传递 dry-run，且只能操作隔离目标；补充不会写入正式数据库的测试。处理崩溃后遗留锁，避免永久阻塞合法调度，同时保持重复运行互斥。
4. **补齐九种任务状态。** `未到期、排队、运行、无变化、完成、部分完成、失败、暂停、额度延后` 必须逐一保留并显示各自的负责人、真实原因、下一步和时间；失败/额度/暂停不得复用“未到检查时间”；下次时间不得停留在过去。
5. **修正行动缺口的事实映射。** 每个缺口使用对应项目、对应类别、对应门槛的事实；通过门槛的数据不得固定输出“被阻断”。Hubble 卡片必须显示项目名，并把约 7,013 流动性、11 成交额、100% 理论滑点、8% 门槛和“首要阻断为退出能力”放在同一个可识别详情中。
6. **补齐重要变化筛选。** 在每页 20 条基础上，按冻结要求提供时间、影响级别、变化类型、项目、动作影响筛选；保持同项目同轮合并和普通行情噪声折叠。
7. **收敛催化路径。** “系统尚未发现”必须显示下次自动检查时间；完整项目列表增加分页、搜索或等效的有限渲染，不能一次展示 590 个入口。
8. **解除项目库长页面。** 点击项目库后只呈现项目库所需内容；不要同时复活首页四模块和旧七段。保留已经通过的每页 20 条、搜索、筛选、排序、详情返回和状态记忆。
9. **补齐 C1.8 开发前项目文件基线。** 记录冻结范围内项目文件的路径、大小和 SHA-256，并与开发前数据库和 27 个活动快照基线关联；不得重写或伪造开发前文件。
10. 修复后只更新 Luna 实现说明和自测证据，把阶段恢复为 `luna_self_test_complete_waiting_sol`；不得自行宣布 Sol 终验通过，不得改动冻结需求、评分、动作、L0-L5 或跨业务边界。
