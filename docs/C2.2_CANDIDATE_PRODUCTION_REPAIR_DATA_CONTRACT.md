# C2.2 候选生产化覆盖修复：数据与页面契约

状态：正式冻结

## 1. 对象和稳定主键

候选对象继续使用 `candidateId`；跨筛选和跟踪使用稳定 `assetId`。只有身份闭环时才允许生成或引用 `projectId`。不得用名称或 Symbol 拼接身份。

## 2. 本地基础扫描状态

```text
local_pass
known_continuation
known_quote_or_wrapped_asset
outside_90_days
invalid_event_or_identity_conflict
local_pending
```

每条状态必须包含：`candidateId`、`state`、`reasonCode`、`plainReason`、`evidenceRefs`、`checkedAt`、`ruleVersion`。

## 3. 市场确认状态

```text
market_confirmed
waiting_for_trades
market_not_indexed
market_identity_conflict
source_pending
```

每条必须包含：链、合约、池、资产方向、来源、观察时间、买入、卖出、来源状态、下一复查时间和证据定位。缺失不得写成 0。

## 4. 后台跟踪资格

```text
trackingEligible: true | false
trackingReasonCode
t0Status
effectiveT0
ageDays
marketState
hardBlockState: confirmed | not_confirmed | pending
identityState
productEvidenceState
riskDataState
qualificationBatchId
qualifiedAt
```

`trackingEligible=true` 不等于 `frontEligible=true`。D 类或身份待确认对象的 `projectId` 必须为空，公开快照不得引用。

## 5. 公开资格

```text
frontEligible: true | false
relationshipClass: A | B | C | D
identityConsistent
qualifyingProductEvidence
confirmedHardBlock
frontReasonCode
```

固定约束：`frontEligible=true` 必须同时满足 A/B/C、身份一致、产品证据合格且无已确认硬阻断；D 类前台数量必须为 0。

## 6. 分片和队列状态

```text
queue: daily_incremental | historical_backlog
chainId
partitionId
inputStart
inputEnd
inputHash
state: pending | running | retrying | paused | completed | failed
processedCount
totalCount
lastCommittedCursor
lastCheckpointAt
lastHeartbeatAt
nextRetryAt
sourceState
qualificationBatchIds[]
```

分片检查点必须原子提交；正式发布只能读取 `completed` 分片形成的资格批次。

## 7. 漏斗统计契约

后台必须分别显示并对账：

```text
importedCandidateCount
localScannedCount
localPendingCount
localExcludedCountByReason
marketRequestedCount
marketConfirmedCount
waitingForTradesCount
marketNotIndexedCount
trackingEligibleCount
trackingPendingIdentityCount
trackingClassDCount
hardGateEvaluatedCount
frontEligibleCount
```

禁止用 `importedCandidateCount` 直接连接 `frontEligibleCount` 而省略实际扫描和评估分母。

## 8. 更新中心页面契约

### 日常作业“90 天新币筛选”

显示新增、本地完成、市场确认、等待交易、进入跟踪、公开新增、来源失败和单项重试。

### 历史区域“历史候选基础扫描”

显示总进度、链、分片、队列、各去向、断点、心跳、运行时间、暂停、继续和失败范围重试。ETA 只有在至少五个稳定分片后显示，并同时显示可信度。

两个区域分别保存设置和状态，但共用一个隐藏、单实例、可恢复写入流水线。历史故障不得把日常筛选或凸性跟踪标成失败。

## 9. 快照发布

- 分片资格批次原子提交；半份批次不可见。
- 新快照构建失败时继续使用上一份完整快照。
- 公开快照不包含 D 类和身份待确认对象。
- 后台跟踪可以读取已完成资格批次，不等待全部历史队列完成。
- 任一已确认公开资格项目静默遗漏时拒绝发布。
