# 企鹅投研-凸性｜C2.3 .NET 桌面容器迁移大白话冻结讨论稿

状态：**用户已确认；正式权威以 `docs/C2.3_REQUIREMENTS_LOCK.json` 为准**  
建议版本名称：C2.3「稳定桌面容器与浏览器隔离」  
整理日期：2026-08-12（Asia/Shanghai）
用户授权原文：`冻结吧`

## 1. 一句话目标

C2.3 不重做产品、不改研究能力，只把当前“PowerShell 调起普通 Edge 窗口”的桌面入口，替换为企鹅投研自己管理的 `.NET＋WebView2` 软件窗口，解决桌面入口不稳定、普通浏览器互相影响、窗口识别脆弱和技术错误难理解的问题。

## 2. 用户最终得到什么

- 桌面仍然只有一个正式入口“企鹅投研-凸性”，双击后打开独立软件窗口。
- 不再把普通 Edge 或 Chrome 窗口当作软件窗口，也不再枚举、识别、关闭或复用用户正在浏览网页的窗口。
- 用户同时使用 Chrome、Edge 浏览网页，不影响企鹅投研；企鹅投研也不读取浏览器账号、历史、Cookie、插件和个人配置。
- 软件启动、重复打开、最小化、最大化、关闭、重新打开和窗口位置恢复，由自己的 `.NET` 容器管理。
- 软件和后台更新继续隐藏运行，不出现 PowerShell、Python 或命令行黑框。
- 启动失败时不再只显示技术异常，而是明确说明失败位置、影响和可以执行的操作。

## 3. 这不是另做一个新产品

C2.3 必须完整继承当前 C2.2 主干：

- 前台四个栏目、项目详情和返回状态全部继承。
- 后台七个栏目、两个独立更新页面、手动更新、自动频率、暂停、进度、错误归属和单项重试全部继承。
- 新币筛选、凸性跟踪、贝叶斯、强路径、T0、A/B/C/D、风险、交易性和所有数值门槛全部不变。
- `data/convexity.db`、`data/c2.1-pipeline.db`、原子快照、游标、断点和历史数据全部不迁移、不改表、不清理。
- 唯一 Windows 调度器和正在运行的候选生产任务保持独立，不新建第二个长期调度器。
- 现有 HTML、CSS、JavaScript 页面和 `127.0.0.1:8766` 本地 HTTP 接口继续作为 C2.3 桌面版主干，因为这是当前已经运行和测试过的业务路径，迁移桌面容器时不重写它可以减少新增故障面。

本版本批准替换的只有“桌面容器和启动生命周期”，不批准删除或改写任何业务功能。

## 4. 固定技术边界

- 桌面容器使用 `.NET 10 LTS＋WPF＋WebView2`。
- 发布为 Windows x64 自带 `.NET` 运行环境的程序；用户不需要另外安装 `.NET`。
- WebView2 使用微软维护并自动安全更新的 Evergreen Runtime。
- WebView2 使用本项目自己的用户数据目录，不与 Chrome、普通 Edge 或其他软件共享。
- C# 负责窗口、单实例、服务健康检查、启动进度、错误提示和恢复入口；可以为重启本地服务、打开日志、修复运行环境等桌面专属操作提供原生能力。
- C# 不计算业务分数、不访问第三方 API、不直接写两套业务数据库，也不成为页面业务数据的第二来源。
- 页面业务数据仍通过本地 HTTP 接口读取。保留这条路径的理由是它在当前桌面产品中已经形成单一数据来源和完整测试，不是为了迁就未来网页版。
- 不为业务取数再建立一套 C# 桥接；否则同一页面会出现 HTTP 与 C# 两条业务通道，错误处理、权限、缓存和测试都更复杂。桌面专属的窗口、进程、日志和运行环境操作不受此限制。

本版本只选择当前 Windows 桌面版风险最低、改动最小、最容易完整验收的实现。未来网页版是否复用这些页面和接口，留到网页版立项时重新决定，不构成 C2.3 的设计约束或验收目标。

## 5. 启动流程

用户双击正式快捷方式后：

1. `.NET` 容器立即显示企鹅投研窗口和启动进度。
2. 检查 `8766` 端口是否是本项目服务，不是本项目时不得强制终止其他程序。
3. 服务已健康时直接加载现有桌面首页。
4. 服务未启动时，容器在后台隐藏启动当前 Python 本地服务，并显示“正在启动本地服务”。
5. 服务就绪后加载 `desktop/index.html`，由现有页面进入凸性机会中心。
6. 在限定时间内仍未就绪时进入可操作的故障页，不显示空白窗口，也不无限转圈。

后台候选扫描、新币筛选和凸性跟踪不归桌面窗口所有。关闭、重开或更新桌面容器，不得停止、重启或从头运行这些后台任务。

## 6. 单实例和窗口记忆

- 第一次双击创建软件窗口。
- 再次双击只唤醒并置前已有窗口，不创建第二个窗口和第二个本地服务。
- 保存正常窗口的位置、大小和最大化状态；关闭重开后恢复。
- 显示器断开、分辨率变化或保存位置已在屏幕外时，自动回到当前主屏可见区域。
- 软件不得依靠窗口标题搜索普通 Edge 进程，也不得关闭名称相似的浏览器窗口。

## 7. 浏览器隔离与页面安全

- WebView2 数据目录固定放在本项目运行目录中，并与普通浏览器配置完全分离。
- 软件页面只允许在容器内访问本项目 `127.0.0.1:8766` 内容。
- 用户主动点击的外部网址交给 Windows 默认浏览器打开，不在软件中形成通用上网窗口。
- 非用户触发的外部跳转和弹窗默认阻止，并在日志中记录原因。
- 清理 WebView2 缓存不得删除业务数据库、快照、更新设置或后台断点。

## 8. 用户能看懂的故障处理

启动故障至少分为以下五类：

1. **WebView2 运行环境缺失或损坏**：说明它是软件显示页面所需组件，提供“安装或修复 WebView2”和“重新检测”。
2. **Python 本地服务无法启动**：说明页面暂时不能读取本地数据，提供“重试启动”和日志位置；不把它写成项目数据受限。
3. **8766 端口被其他程序占用**：明确提示端口冲突，不自动结束未知进程。
4. **本项目服务启动但健康检查失败**：显示失败阶段、最近一次可用时间、重试和打开日志入口。
5. **页面渲染进程异常**：保留当前后台任务，自动尝试恢复页面；失败后提供重新加载，不重启全量任务。

错误提示不得直接显示 `Null`、堆栈、原始 JSON 或只有开发人员能理解的异常。技术详情默认折叠，供维护时查看。

## 9. 启动速度与可见进度

- 本地服务已经健康时：3 秒内显示软件窗口，5 秒内显示可操作页面。
- 冷启动时：3 秒内必须出现软件窗口和当前启动阶段；30 秒内加载首页，或进入明确的故障页。
- 重复双击时：2 秒内唤醒已有窗口。
- 等待期间显示“检查本地服务、启动本地服务、加载产品页面”三个大白话阶段，不使用无期限空白页。

这些是发布验收目标；若本机磁盘或数据库维护造成超时，必须显示真实阶段，不能伪装为已经完成。

## 10. 安装与运行环境

- 开发构建环境固定并记录 `.NET 10 SDK` 和 WebView2 SDK 版本，任何机器可按同一命令重建。
- 正式程序自带所需 `.NET` 运行文件，避免用户电脑只有旧版或没有 `.NET` 时打不开。
- WebView2 启动前执行版本检测；缺失时使用微软官方 Evergreen 安装/修复流程。
- 安装或修复 WebView2 需要网络、系统权限或被安全软件阻止时，必须说明真实原因，并提供官方离线安装说明。
- 本版本只交付 Windows x64 桌面版，不开发移动端、macOS 或 Linux。

## 11. 旧入口和回滚

- 开发和终验期间保留当前 PowerShell＋Edge 启动脚本，但不建立第二个用户可见的正式桌面入口。
- C2.3 正式发布时，原“企鹅投研-凸性”快捷方式改为指向新的 `.NET` 程序，名称和图标不变。
- 旧脚本至少保留一个版本作为紧急回滚资产，默认不再使用。
- 若新容器终验不通过，只恢复快捷方式指向，不回滚或覆盖 C2.2 页面、数据库、快照和后台任务。
- 未获得用户后续明确批准，不删除旧启动脚本和回滚说明。

## 12. 真实桌面验收

发布前必须从正式快捷方式完成以下真实操作，不能只用无头浏览器或代码测试替代：

1. 本地服务关闭时冷启动，进入真实机会首页。
2. 本地服务已运行时热启动，不重复启动服务。
3. 连续多次双击只有一个软件窗口，并能唤醒已有窗口。
4. 关闭重开恢复窗口大小、位置、最大化状态和当前页面上下文。
5. Chrome 和普通 Edge 在打开网页、登录账号和安装插件的状态下，企鹅投研启动、运行、关闭均不改变其窗口、标签页、进程和配置。
6. 关闭企鹅投研后，正在运行的后台扫描 PID、分片、断点和进度继续正常变化；重新打开只读取现状，不重启任务。
7. 模拟 WebView2 缺失、Python 缺失、端口冲突、服务超时和页面进程异常，五类提示及恢复按钮全部可用。
8. 1180×760、1440×900、最大化和多显示器恢复通过，无整页横向溢出和关键操作遮挡。
9. 前台、详情、后台、两个更新页面及全部现役路由真实打开，业务内容与 C2.2 发布基线一致。
10. 容器验收不得触发手动更新、全量扫描、规则修改或业务数据库写入；运行中采集库的正常变化必须能归因于既有后台扫描，而不是桌面容器。
11. 新增 `.NET` 测试、桌面容器受影响测试、现役页面与接口快速冒烟全部通过；未修改的 Python 业务代码、页面资源和 C2.2 冻结资产以实现前后哈希一致证明继承，不机械重跑全部历史测试。
12. 软件窗口、WebView2子进程和容器自行启动的本地服务退出行为均与设计一致，无黑框、孤儿窗口和误杀普通浏览器。

## 13. 按风险决定测试范围

测试的目标是尽早发现真实错误，不以运行时间、用例数量或重复执行全量测试证明质量。C2.3 以及后续版本默认遵守以下边界：

### 13.1 开发中的快速反馈

- 文档或用语修改：只做结构、链接、编码和需求锁检查，不启动产品全量测试。
- 单一页面的局部样式或交互修改：运行该页面的语法、受影响交互、真实渲染和相关路由测试，不运行无关数据库和采集测试。
- 公共页面壳、导航或共享接口修改：扩大到所有依赖该公共组件的页面，但不自动扩大到未受影响的采集、评分和调度模块。
- 桌面容器修改：优先运行 `.NET` 单元测试、启动协议测试、健康接口冒烟和真实快捷方式路径；业务文件哈希未变时，不重复运行全部 Python 业务测试。
- 业务规则、数据库结构、共同快照、调度器或共享写入链被修改时，才运行对应模块及其下游回归；只有影响边界无法可靠划定或修改了全局公共核心时，才升级为全量回归。

开发中的快速测试目标为 5 分钟内给出结果，受影响回归原则上控制在 20 分钟内。超过目标时必须先说明原因并拆分定位，不能每改一处就启动数小时测试。

### 13.2 缺陷修复

- 先建立能够稳定复现该缺陷的测试或真实操作路径，再实施修复。
- 修复后先重跑复现测试，再跑受影响组件和直接下游回归。
- 只有修复触及共享核心、数据库迁移、调度或无法证明影响边界时，才重新执行全量回归。
- 同一完整测试集不因一个局部失败从头反复运行；先把失败项定点修复并验证，最终发布前再执行一次相应范围的完整验收。

### 13.3 发布前独立终验

- 每个版本仍必须有一轮不相信实现报告的独立终验，但范围由实际改动风险决定，不默认等于所有历史测试。
- 终验必须覆盖本版本改变的功能、直接依赖、明确继承项、回滚和至少一条真实用户主路径。
- C2.3 的最高风险是正式快捷方式、冷/热启动、单实例、浏览器隔离、后台任务独立、窗口恢复和五类故障提示，因此真实桌面验收优先级高于重复运行未改动的评分或采集测试。
- 未改动资产通过冻结哈希、接口契约、数据库只读检查和现役路由快速冒烟证明继承；发现哈希差异或契约差异时，才扩大测试范围。
- 终验发现缺陷后，先定点修复和重验；若修复未跨越影响边界，无需再次从头执行全部无关测试。

### 13.4 长任务边界

- Gate 0 回扫、候选生产、第三方全量采集、长期观察和数据库压缩不是“软件测试”，不得为了验收重复启动或等待其跑完。
- 预计超过 20 分钟的测试必须能够单独运行、显示进度、设置超时并保存结果；不得用模型在对话中无期限等待来维持测试。
- 正在运行的后台生产任务只检查 PID、任务 ID、断点和进度未被本版本干扰，不重复执行其工作量。
- 测试时间缩短不能靠跳过真实用户路径、忽略失败或降低发布标准；应通过准确划定影响范围、减少无关回归和提高真实桌面测试质量实现。

## 14. 程序上限

- WebView2 迁移可以消除普通 Edge `--app` 窗口复用、标题识别和进程误判问题，但不能保证微软运行时、Windows、安全软件或硬件永远不发生故障。
- 它只改善桌面入口和窗口生命周期，不修复第三方 API 失败、数据缺失、候选扫描速度、数据库膨胀和业务规则问题。
- 后端仍是 Python 和本地 HTTP 服务，不会因为外壳改成 `.NET` 就变成纯 C# 软件。
- 本版本不为未来网页版牺牲桌面稳定性，也不承诺未来网页版可以零修改复用当前桌面实现。
- 第一次缺少 WebView2 且电脑离线时无法在线安装，只能使用官方离线安装包。
- 用户关闭电脑后后台任务仍会停止；重新开机后是否恢复继续沿用现有 Windows 调度和断点规则。

## 15. 本版本明确不做

- 不修改新币筛选、凸性跟踪、贝叶斯、强路径、项目分类、前台文案和投资判断。
- 不做采集库 90 天归档、删除或压缩；数据库生命周期另行冻结，不能夹带在桌面迁移中。
- 不新增 API、链、DEX、来源、付费服务或第二个调度器。
- 不开发登录、云同步、在线服务器、公开网页版、移动端、钱包或自动交易。
- 不重新设计现有页面，不以迁移名义删除旧功能。

## 16. 冻结和发布门槛

本讨论稿已经由用户确认，并已拆成正式 PRD、容器契约、设计规格、错误用语、继承/替换清单、测试策略、验收计划和交接说明。正式范围只以 C2.3 需求锁为准。冻结本身不等于开始开发；只有用户另行明确授权“开始 C2.3 整版开发”后才修改产品代码。

开发完成后必须先进行开发自测，再进行一轮不依赖实现报告的按风险独立终验。测试范围必须逐项说明“为什么需要、覆盖什么改动、什么情况下扩大”，不再把无差别全量回归当作默认动作。全部应验继承项、真实桌面路径、浏览器隔离、后台独立性、错误恢复和回滚均通过后，才能更新正式快捷方式和发布状态。
