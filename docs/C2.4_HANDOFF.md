## 2. 实现顺序固定

### 第 0 步｜冻结基线

- 记录当前代码、两库、正式快照、快捷方式、唯一调度器和候选后台进程状态。
- 为 29 个继承路由生成可执行检查清单。
- 只读建立真实集合对账：第一关、跟踪、公开、首页、全部机会。

验证：基线哈希、数量、截止时间和差集可重复；不写数据库、不暂停后台任务。

### 第 1 步｜先做核心数据合同

- 实现宽第一关、完整第二关快照、公开快照、两个生命周期池和唯一字段生产者。
- 先让 Tier 0 固定样本全部通过，再接页面。
- 快照必须保存完整跟踪/公开集合，首页前 10 只能由完整快照派生。

验证：同链第 11 名仍在跟踪/公开/全部机会；无贝叶斯公开项目仍在全部机会；第 91 天样本迁移正确。

### 第 2 步｜规则与固定样本

- 按机器规则配置实现 P50/P40 回退、四路径、公开底线、卖出报价、来源独立、防抖和贝叶斯边界。
- 不临场改数值，不用目标数量反推门槛。

验证：Tier 1 全部通过；真实样本哈希匹配；缺失不变 0。

### 第 3 步｜两个独立作业和恢复

- 复用 C2.2 唯一调度器、手动/自动入口、单实例、断点、冷却和单来源重试。
- 只新增 C2.4 必需字段/产物；不得建立第二调度器或第二 C# 业务通道。

验证：两个页面设置隔离、失败恢复、原子快照和上一完整结果保护通过。

### 第 4 步｜前台和后台 UI/UX

- 按页面数据契约接入机会首页、全部机会、重要变化、判断页、详情和后台七组。
- 逐路由执行继承清单；没有当前数据的入口按正式处理隐藏，不能显示旧快照。

验证：Tier 3 真实桌面主路径和 Tier 4 继承检查通过。

### 第 5 步｜开发自测与独立终验

- 开发报告按 Tier 0→4 分层，先报集合差集。
- 独立终验重新核验需求锁，从底层只读数据重算预期，不相信实现汇总和实现报告。
- 发现核心缺陷先修复并定点重验；只有影响边界不明时扩大回归。

验证：`docs/C2.4_ACCEPTANCE_PLAN.md` 所有适用项通过，发布候选和验收候选哈希一致。

## 3. 长任务边界

- C2.4 不需要重跑 Gate 0 或 459 万历史扫描。
- 迁移只复查本地现有候选、跟踪和历史证据，并从现有断点处理受影响队列。
- 任何预计超过 15 分钟的数据任务必须具备分片、原子检查点、可恢复游标、单实例锁和可见进度。
- 不得为测试复制多份完整采集库；使用只读库、最小测试库和固定样本。
- 不停止、重启、重复启动或从头重跑当前候选后台进程。

- 不修改正式冻结文档来迎合实现。
- 不把第一关对象直接发布到机会中心。

- 不建立跨链贝叶斯总榜。

- 不引入人工逐项目复核、大模型业务判断、投资动作或自动交易。
