# C2.0 页面与数据契约

状态：已冻结，属于 C2.0 需求锁  
原则：前台只接收可公开阅读的派生字段；后台保留完整质量和溯源信息；派生结果不得成为新的投资事实源。

## 1. 页面清单与归属

### 1.1 前台：沿用 C1.9 四个导航

| 页面/视图 | 角色 | C2.0 职责 | 结构变化 |
|---|---|---|---|
| `candidate-pool.html` 机会首页 | `front` | 当前判断、最多 5 个优先信号、重要变化摘要、三类主要阻断 | 使用 C2.0 决策信号；不增加导航 |
| `candidate-pool.html?view=all` 全部机会 | `front` | 搜索、筛选、分页、可解释排序理由 | 保持 20 条/页；新增阅读层级和排序理由 |
| `candidate-pool.html?view=changes` 重要变化 | `front` | 按项目聚合的事件链 | 默认只看改善/收紧；20 个项目事件链/页 |
| `candidate-pool.html?view=method` 我们如何判断 | `front` | 解释阅读优先级与投资动作互不替代 | 增加 C2.0 方法说明，不显示版本号 |
| `project-detail.html` 项目详情 | `context-detail` | 五段式摘要、事件链、催化、风险、失效和依据 | 仍只从上下文进入，不是顶级导航 |

`change-explanations.html` 保留为兼容前台入口，但必须重定向或渲染与 `candidate-pool.html?view=changes` 相同的事件链数据和前台壳；不得形成第二套变化语义。

### 1.2 后台：新增一个二级页面

| 页面 | 角色 | 一级栏目 | 职责 |
|---|---|---|---|
| `decision-quality.html` | `admin` | 模型与规则 | 七类覆盖漏斗、共性阻断、质量指标、闭环队列、前台结论回溯 |

该页面加入 C1.9 路由角色表的后续 C2.0 版本，实施后活动 HTML 唯一角色页应由 28 增至 29。后台一级栏目仍为 7 个；判断质量不得升级为第八个一级栏目。

## 2. 构建顺序与一致性

`scripts/build_decision_quality_snapshots.py` 的固定顺序：

1. 以只读连接读取数据库和现有活动快照；
2. 选择每个项目唯一展示案例；
3. 生成变化去重记录和 24 小时事件链；
4. 生成五段式项目摘要；
5. 计算阅读层级和稳定字典序；
6. 计算七类漏斗、共性阻断和质量指标；
7. 在内存中完成项目数、案例数、证据回指、单位和分子分母校验；
8. 分别写入两个临时文件；
9. 重新读取并解析临时文件，确认 `buildId`、`generatedAt` 和输入运行 ID 完全一致；
10. 原子替换两份活动快照。

任一步失败：删除本轮临时文件，保留两份上次有效快照，在运行状态中记录失败；不得替换其中一份。

## 3. 前台快照契约

文件：`app/decision-signals-snapshot.js`  
全局变量：`window.PENGUIN_CONVEXITY_DECISION_SIGNALS`

### 3.1 顶层字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `schemaVersion` | string | 固定 `c2.0-decision-signals-v1` |
| `buildId` | string | 本次派生构建唯一 ID，与后台快照相同 |
| `generatedAt` | ISO datetime | 构建完成时间 |
| `sourceSnapshotAt` | ISO datetime | 所用现有快照中最旧的有效生成时间；用于判断数据一致性 |
| `inputRunIds` | string[] | 去重后的实际运行 ID，不得写任务凭据或路径 |
| `dataStatus` | object | `valid`、`stale`、`partial`、`failed_using_last_valid` 之一，并带普通用户说明 |
| `counts` | object | 当前唯一项目数、候选案例数、三层阅读数量、首页信号数 |
| `currentDecision` | object | 五种动作的真实数量、判断时间、主要限制；不重新推导动作 |
| `homeSignals` | array | 最多 5 个，全部 `summaryComplete=true` |
| `projects` | array | 每个唯一项目一条，用于全部机会 |
| `changeChains` | array | 项目聚合事件链，用于首页摘要和重要变化 |
| `topBlockers` | array | 最多 3 个面向用户的共性阻断，不含后台任务字段 |
| `methodBoundary` | object | 说明阅读层级不是动作、评分或 L0-L5 |

### 3.2 前台项目字段

每个 `projects[]` 和 `homeSignals[]` 至少包含：

| 字段 | 说明 |
|---|---|
| `projectId`、`caseId` | 唯一项目与选中的展示案例 |
| `projectName`、`symbol` | 用户可读身份；符号未知时为空，不猜测 |
| `detailUrl` | 带来源上下文参数的项目详情链接 |
| `readingTier` | `must_read`、`worth_following`、`observe` |
| `readingTierLabel` | 现在必须看、值得继续看、保持观察 |
| `whyPriority` | 项目专属优先理由；不得为通用模板 |
| `impact` | `improve`、`tighten`、`no_change` 或空；前台映射固定三种影响文案 |
| `actionLabel` | 直接来自现有动作，数据库旧值“已失去凸性”只做显示映射为“失效/排除” |
| `maturity`、`riskLevel`、`remainingConvexity`、`tradeabilityStatus`、`ignitionProximity` | 原值只读输出，互不替代 |
| `summary` | 五段式摘要对象 |
| `summaryComplete` | 五段全部合格时为 true |
| `missingSummaryParts` | 不完整时列出缺失段；首页信号中必须为空 |
| `evidenceTime`、`nextReviewAt` | 证据时间与下次复查时间 |
| `sortReasons` | 普通语言理由数组；不含分数 |

禁止字段：数值阅读分、任务 ID、内部任务类型、Watcher、游标、调度、重试、日志、模型提示、内部文件路径、凭据位置。

### 3.3 五段式摘要对象

```json
{
  "action": {"label": "只观察", "sourceId": "..."},
  "strongestSupport": {"text": "...", "factBoundary": "confirmed_fact", "evidenceIds": ["..."], "observedAt": "..."},
  "primaryBlocker": {"category": "价值捕获", "text": "...", "effect": "...", "evidenceIds": ["..."]},
  "nextTrigger": {"text": "...", "owner": "system", "nextReviewAt": "...", "evidenceIds": ["..."]},
  "invalidation": {"text": "...", "evidenceIds": ["..."], "evidenceTime": "...", "stale": false}
}
```

`sourceId` 仅为现有结论或证据记录的内部关联标识，不在首层界面显示。证据折叠层可用它读取来源名称、URL 和时间。

## 4. 变化事件链契约

### 4.1 语义字段注册表

只有下列维度可影响阅读优先级：

- `action`
- `invalidation`
- `risk`
- `tradeability`
- `exit`
- `value_capture`
- `remaining_convexity`
- `ignition`
- `evidence_maturity`

行情字段可形成变化链，但单纯价格、成交量或流动性波动默认 `no_change`，不能单独提升到“现在必须看”。只有现有交易与退出判断同时发生变化时，才按对应维度解释。

### 4.2 去重键

显示候选的精确去重键：

`projectId + runId + semanticField + normalizedFrom + normalizedTo`

证据 URL、证据 ID 和收集时间不参与显示去重；它们合并为证据数组。原始历史仍全部保留。

### 4.3 事件链字段

| 字段 | 说明 |
|---|---|
| `chainId` | 稳定内容指纹，不使用数组位置 |
| `projectId`、`caseId`、`projectName` | 项目身份 |
| `startedAt`、`endedAt` | 链首尾时间 |
| `impact`、`impactLabel` | 改善、收紧、尚不改变判断 |
| `headline` | 发生了什么 |
| `whyItMatters` | 为什么重要或暂时不重要 |
| `initialState`、`finalState`、`netChange` | 默认显示的净变化 |
| `dimensions` | 本项目事件卡受影响维度，按严重度排序 |
| `steps` | 展开后全部步骤，按时间升序；不得删掉中间失效/动作变化 |
| `evidence` | 去重后的证据引用 |
| `displayNumbers` | 通过单位注册表校验后的数字；不合格数字不进入 |
| `hasUnresolvedUnit` | 是否存在因口径不清而隐藏的数值 |
| `detailUrl` | 带变化页上下文的详情链接 |

重要变化页默认过滤 `impact != no_change`，每页最多 20 个项目事件链；用户主动选择“全部变化”后才包含 `no_change`。

## 5. 后台快照契约

文件：`app/decision-quality-snapshot.js`  
全局变量：`window.PENGUIN_CONVEXITY_DECISION_QUALITY`

### 5.1 顶层字段

| 字段 | 说明 |
|---|---|
| `schemaVersion` | 固定 `c2.0-decision-quality-v1` |
| `buildId`、`generatedAt`、`sourceSnapshotAt`、`inputRunIds` | 必须与前台快照完全一致 |
| `reconciliation` | 项目数、案例数、每层漏斗对账结果和异常 |
| `coverageFunnel` | 七类维度的闭环、系统处理、人工确认数量 |
| `blockerRanking` | 共性阻断排行 |
| `qualityMetrics` | 带分子、分母、定义、生成时间的质量指标 |
| `closureQueue` | 项目级处理队列与现有后台入口 |
| `traceIndex` | 前台项目摘要到结论、证据、来源、运行的关联索引 |
| `unitIssues` | 未确认单位或比较基准的变化清单 |
| `templateIssues` | 被判定为通用模板的摘要段清单 |

### 5.2 七类漏斗判定

每个项目在每个维度执行固定判定：

| 维度 | 已闭环 | 待系统处理 | 待人工确认 |
|---|---|---|---|
| 主体身份 | `projects.identity_status=verified` 且有可溯源证据 | pending 且已有可运行核验任务 | conflict/rejected 或无安全自动核验路径 |
| 可购买资产 | 存在资产且最新身份复核为 verified/corroborated，无冲突 | pending 且系统有下一资产身份任务 | conflict 或需人工纠错 |
| 价值捕获 | 最新值为 A/B/C 且有具体说明和证据 | unknown 或说明不足，已有系统任务 | 证据冲突或只能人工裁决 |
| 最大可控亏损 | 最新复核有具体最大亏损描述和证据 | 空、通用模板或过期，系统可补齐 | 冲突或系统无安全补齐路径 |
| 交易与退出 | 已明确为 verified/limited/blocked 且有口径 | unknown，已有市场/合约/退出任务 | 身份冲突或需人工纠错 |
| 点火条件 | 有具体点火条件、观察窗口和来源 | 缺少任一项且系统有跟踪任务 | 冲突或只能人工判断 |
| 证据时效 | 摘要所用证据均可溯源且未明确过期 | 有过期/缺口且系统可刷新 | 来源冲突、撤回或需人工判别 |

`已闭环`表示答案明确，不表示答案正面。每一行必须输出 `closed + systemPending + humanPending = projectsTotal`。

### 5.3 质量指标公式

| 指标 | 分子 | 分母 |
|---|---|---|
| 项目专属摘要覆盖率 | `summaryComplete=true` 的唯一项目 | 当前唯一项目总数 |
| 通用模板占比 | 任一核心段被判为通用模板的唯一项目 | 当前唯一项目总数 |
| 变化合并率 | 合并前显示候选数 - 合并后事件链数 | 合并前显示候选数 |
| 前台缺少单位数量 | 被隐藏的单位/基准不明数值 | 合并前数值变化总数 |
| 过期证据影响项目数 | 摘要所用证据明确过期的唯一项目 | 当前唯一项目总数 |
| 首页有效信号数量 | 实际首页项目数 | 固定上限 5 |
| 前台摘要可溯源率 | 五段全部可回指的完整摘要项目 | 完整摘要项目数 |

分母为 0 时值为 `null`，界面显示“无法计算”；不得写成 0。

### 5.4 闭环队列字段

每条至少包含：

- `projectId`、`caseId`、项目名；
- 质量维度和问题类别；
- 对前台的影响；
- 责任方 `system` 或 `human`；
- 系统下一步；
- 最近执行时间与结果；
- 下次复查时间；
- 失败或部分完成原因；
- `targetUrl` 现有后台处理入口；
- `returnContext` 用于恢复判断质量筛选、页码和滚动位置。

## 6. 前后台数据隔离

- 前台脚本不得加载 `decision-quality-snapshot.js`。
- 后台可读取前台派生摘要以做对账，但不得复用前台导航或页面壳。
- `decision-signals-snapshot.js` 不得包含闭环队列、责任人、内部错误、任务 ID、来源健康原始记录或日志。
- 未来大众构建只允许 `front` 与 `context-detail` 页面以及前台安全快照进入发布包；`decision-quality.html` 和后台快照必须被排除。

## 7. 页面状态与上下文

### 7.1 前台状态

- 正常：使用本轮一致快照。
- 资料不足：项目留在全部机会，显示缺失原因和下次复查。
- 无优先信号：显示真实空状态，不补位。
- 数据过期：显示所用证据时间和影响范围。
- 构建失败：显示上次有效判断时间，禁止把旧数据写成当前。

### 7.2 后台状态

- 构建中、成功、部分输入过期、对账失败、构建失败分别显示。
- 对账失败时漏斗和指标标记不可用，但保留上次有效数据和本轮错误摘要。
- 从判断质量进入项目/来源/证据处理页时，把 `qualityFilter`、`qualityPage`、`qualityScroll` 和问题 ID 保存到页面状态；返回后恢复。

## 8. 发布时路由与数量

冻结时基线：28 个活动 HTML/唯一角色页面，当前全量 Python 测试 58 个。C2.0 新增一个后台 HTML 页面后，预期唯一角色页面为 29；本地页面/资源验收基线在 C1.9 的 30 上增加该页面后至少为 31，Luna 必须在开发前基线清单和 Sol 最终验收清单中现场重算，不能只采用本文件数字。

## 9. 明确禁止

- 不建立新的 SQLite 业务表或迁移来保存阅读层级、摘要或质量漏斗。
- 不把派生快照回写为机器结论、动作、评分或 L0-L5。
- 不删除、压缩覆盖或改写原始变化历史来实现前台去重。
- 不允许前后台快照使用不同输入时间点后仍显示为同一轮结果。
- 不允许未知单位数字、科学计数法或无比较基准的精确数值进入前台。
