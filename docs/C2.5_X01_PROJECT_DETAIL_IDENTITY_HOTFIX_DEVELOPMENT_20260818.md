## 正式旧版本复现与根因

1. 在正式 WPF 桌面按普通用户路径进入“全部机会”，精确点击 Wrapped Gonka 与 cap 的“查看证据与计算依据”，两者均稳定显示 OpenServ；桌面整体刷新后仍可复现。
2. 正式 WebView2 History 的只读副本证明实际导航参数正确：
   - Wrapped Gonka：`assetId=candidate-asset-bd53294c98f8c37a197742fb`
   - cap：`assetId=project-asset-a4eb1921402d669b`
3. 正式服务的完整公开快照中，Wrapped Gonka、cap、OpenServ 三条 `assetId` 与 `detailHref` 均正确，70 条 `detailHref` 唯一。因此快照、点击命中层和 URL 参数都不是根因。
4. 根因位于 `app/c2-4-front.js::renderDetail` 的旧查找表达式：
   - 当 URL 只有 `assetId`、没有旧参数 `id` 时，`params.get("id")` 为 `null`；
   - 首条 OpenServ 的 `projectId` 同为 `null`；
   - `row.projectId === params.get("id")` 因而在扫描首条时提前命中 OpenServ，目标 `assetId` 尚未得到比较机会。
5. 完整快照首条为 OpenServ，因此旧逻辑对其余 69/70 条详情导航都有共享错配风险；X01 不是两个卡片的孤立数据问题，也不是缓存问题。

## 最小修复

- 有 `assetId` 时只按稳定 `assetId` 查找；仅当 URL 没有 `assetId` 且明确提供旧参数 `id` 时，才使用 `projectId` 兼容路径。
- 没有任何身份参数时返回 `null`，不再把“参数缺失”解释为“项目字段为空”。
- 未逐项目硬编码，修复覆盖同一共享根因。
- 未增加资源版本或清缓存逻辑：正式与候选导航记录都证明浏览器收到的是正确 URL，错误发生在当前脚本的详情选择逻辑，缓存不是根因。
