# C2.2 候选生产化覆盖修复：正式验收计划

状态：正式冻结

## A. 冻结与边界

- A01：原 `docs/C2.2_REQUIREMENTS_LOCK.json` 及其八份正式文件哈希保持不变。
- A02：本修复独立需求锁全部哈希一致。
- A03：不新增第二个长期 Windows 调度器，不重跑 Gate 0，不新增链、DEX、付费 API 或移动端。
- A04：贝叶斯、P60/P70、美元护栏、报价护栏、四路径和凸性线索规则哈希不变。

## B. 覆盖和漏斗

- B01：在固定数据库副本上，全部导入候选均获得本地扫描状态，不存在无原因长期 `discovered`。
- B02：本地扫描各状态互斥，合计等于去重后的输入候选数。
- B03：页面同时显示导入、本地完成、市场确认、跟踪资格、实际硬门槛评估和公开资格分母。
- B04：当前真实基线 4,590,214、4,585,726、4,365、161、11 的含义在修复前审计中可复算；修复后使用实时数量，不把历史基线冒充当前值。
- B05：日常新增与历史积压分别对账，重复候选不重复计数。

## C. 四层规则

- C01：名称、Symbol、Meme 文字、热度、涨幅不参与本地排除。
- C02：第 90 天仍可处理，第 91 天退出；时间不形成质量权重。
- C03：市场确认要求链、合约、池、方向、买入和卖出事实；固定成交额、市值、流动性、FDV、TVL和综合分门槛为 0。
- C04：满足宽条件的 D/待身份对象可以 `trackingEligible=true`，但 `frontEligible=false`、公开快照数量为 0。
- C05：缺失身份、产品、安全、供应或历史保持 pending/unavailable，不写零、不冒充失败。
- C06：已确认卖出失败、冻结、黑名单或身份冲突立即阻止跟踪或公开资格，证据可定位。
- C07：贝叶斯分数不能替代强路径或公开资格。

## D. 双队列与恢复

- D01：日常新增和历史积压交替运行；日常新增在历史未完成时仍能独立产生结果。
- D02：历史六链轮转，Solana 大体量不阻塞其他链。
- D03：人为终止进程后从最后原子游标继续；已完成分片不重新请求。
- D04：重复启动只有一个写入者；半份分片和半份资格批次不可见。
- D05：暂停、继续、关机恢复、来源冷却和失败范围重试均保持正确范围。
- D06：正式隐藏启动，桌面黑框为 0；关闭 Codex 或产品窗口不终止已启动工作。

## E. 复查频率和来源状态

- E01：无市场对象按 0—2 天 6 小时、3—7 天 24 小时、8—30 天 72 小时、31—90 天 7 天复查。
- E02：相同日龄不同复查频率不改变质量分、排序、状态和凸性结论。
- E03：请求有限重试后保存准确的六类来源状态和下一重试时间，不无限快速重连。
- E04：`no_data`、额度、来源、配置和程序问题分别归类；来源问题不创建项目风险。

## F. 页面和真实桌面

- F01：“90 天新币筛选”和“历史候选基础扫描”同页分区但语义、进度和控制独立；凸性跟踪仍在独立页面。
- F02：历史区域显示处理数/总数、百分比、链、分片、各去向、断点、心跳、运行时间和重试范围。
- F03：五个稳定分片前不显示 ETA；之后同时显示 ETA 可信度。
- F04：1180×760、1440×900 无横向溢出，长数字和长错误可读。
- F05：从真实桌面快捷方式完成冷启动、页面进入、暂停/继续的非写入模拟、重复启动单实例和窗口恢复验收。

## G. 数据安全和发布

- G01：正式变更前两库备份、哈希、结构、核心数量、`integrity_check` 和外键结果完整。
- G02：测试、截图和点击验收使用副本；正式数据库、暂停、频率、任务和调度状态不被污染。
- G03：页面只读原子快照；构建失败沿用上一份完整结果。
- G04：全部 Python 测试、JavaScript 语法、路由、资源、数据库和桌面单实例验收通过。
- G05：独立终验通过后才能更新状态、验收清单和发布标记。

## H. 长任务放行

正式历史扫描只有在分片、原子检查点、可恢复游标、单实例锁、暂停/继续、可见进度和数据库备份全部验收通过后才能启动。开发和终验不得为了验证而在正式库启动完整 459 万扫描；使用固定小分片和数据库副本验收，发布后再由用户明确授权启动正式后台扫描。
