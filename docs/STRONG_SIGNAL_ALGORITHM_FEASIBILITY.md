# 90 天新项目强弱线索算法与全量分层采集边界

状态：研究与数据可行性草案，未冻结、未编码、未改变 C2.0  
日期：2026-08-04（Asia/Shanghai）

## 1. 当前结论

免费资源已经足以建立强线索算法和弱线索算法的采集结构，但还不足以冻结最终权重、数值阈值或证明免费额度可以覆盖全部生产刷新频率。

本文件采用用户已确认的两项硬口径：

- 新项目池只包含 `T0≤90天`，分为 0—30 天和 31—90 天，第 91 天退出；年龄不进入任何算法权重。
- 正式采集不限制为 20 个样本。对已接入范围内全部疑似 90 天对象做基础扫描，对全部深采达标对象做深度采集。

当前已验证：

- Helius 凭据已在 Windows 用户环境中配置，主网 RPC、Token Accounts 和交易历史返回有效结果。
- Alchemy 凭据已在 Windows 用户环境中配置，以太坊 RPC 和 ERC-20 Transfer 历史返回有效结果。
- 凭据值没有写入项目文件、SQLite、快照或接口输出。
- DexScreener、CoinGecko Demo、GoPlus、DefiLlama 和 Blockscout 继续作为现有免费资源使用。

字段可取得不等于算法可发布。钱包历史、交易者归因、操纵识别和免费额度仍需接入范围内全量影子采集验证。

## 2. 资源职责

### Helius：Solana 链上事实层

- 按 mint 读取 Token Accounts，按 owner 去重后计算有效持币钱包和分布。
- 读取地址、交易池和程序的交易历史，识别 Transfer、Mint、Burn 和交易相关事实。
- 不把 Token Account 数量直接当作钱包数。
- 不把仅查询 mint 得到的交易历史直接当作全部 DEX 交易者；必须结合 DexScreener 交易池地址和链上交易解析。

### Alchemy：EVM 链上事实层

- 按代币合约读取 ERC-20 Transfer 历史。
- 结合交易池地址、交易哈希和交易发起地址识别真实参与地址。
- 从零地址转入、转向零地址和供应调用识别 Mint/Burn 候选事实。
- 当前持币者可通过历史 Transfer 重建；免费额度是否适合全量重建仍需验证。

### DexScreener：跨链市场层

- 提供交易池、流动性、成交额、买卖笔数、价格变化、池创建时间和付费推广标记。
- 提供需要 Helius 或 Alchemy 进一步核验的交易池地址。
- 不提供完整的钱包归属和持币分布结论。

### 其他免费资源

- CoinGecko Demo：资产身份、合约、市值、FDV和流通供应交叉验证。
- GoPlus：合约、税费、黑名单、增发和不可卖风险前置筛查。
- DefiLlama：协议登记、网络、分类和 TVL 变化；TVL 只占业务活动子项。
- Blockscout：补充开放 EVM 网络的合约和交易事实。

## 3. 全量分层采集边界

### 3.1 全量范围

“全量”只表示已接入链、市场和来源的可发现范围，不表示全市场零遗漏。当前至少覆盖已接入的 Solana、已启用 EVM 网络，以及 DexScreener、CoinGecko、GoPlus、DefiLlama、Blockscout 能返回的对象；具体链清单必须在 Gate 0 固定并展示最后成功时间。

采集总体分为三层：

| 层级 | 对象范围 | 必采内容 | 结果 |
|---|---|---|---|
| 全量发现与基础扫描 | 所有已发现且疑似 `T0≤90天` 的代币 | T0 证据与状态、A/B/C/D 初步关系、交易池、基础成交与流动性、合约显性风险、来源时效 | 形成完整发现名册；冲突、无法确认和 D 类留在后台 |
| 达标对象全量深采 | 所有通过确定性深采门槛的对象 | 交易参与、流动性、钱包增长与分布、项目业务活动、供应变化与已执行价值捕获 | 进入强弱算法复算，不随机抽样 |
| 自动结果分流 | 所有深采结果 | 数据完整性、强线索规则、弱线索规则、反操纵否决和失效条件 | 凸性线索、近期活跃项目、项目专属资料缺口或不进入前台 |

### 3.2 宽硬门槛与全量深采

对象必须同时满足以下条件才进入前台和高成本深度采集：

1. T0 已核验且不超过 90 天。
2. 属于 A、B 或 C 类；D 类保留后台。
3. 至少存在一个身份一致、可复现的公开交易池或交易场所。
4. 链上观察到真实买入和真实卖出。
5. 基础扫描未发现无法卖出、异常税费、冻结、黑名单、资产身份冲突等硬否决。
6. 至少存在 GitHub、产品合约、结构化业务数据、已执行代币功能或链上产品使用之一；GitHub-only 可以首版准入，但必须明确只证明代码仓库存在。

该门槛不产生投资分数，也不等同于“项目靠谱”。全部通过者必须进入前台和深采队列；观察不足 14 天、五因子不完整或尚未形成证据路径不得使项目静默消失。免费额度不足时不得随机抽样、只保留热门项目或改用人工挑选。

### 3.3 免费额度不足时允许与禁止的调整

允许依次调整：高成本字段刷新频率、非必要历史回溯长度、明确支持的链或来源范围。每次调整都要公开影响对象数、数据新鲜度和可能漏项。

禁止调整：算法权重、发布门槛、硬风险否决、数据完整性门槛；禁止对缺失权重重新归一化，也禁止把接入范围内抽样说成全量。

固定边界回归案例只验证 T0、A/B/C/D、迁移连续性、硬否决和 90/91 天规则。它们不是正式采集范围，也不能单独用于权重校准。正式校准使用接入范围内全部合资格对象，同时保留未通过、硬否决、来源失败和已退出对象。

## 4. 动态贝叶斯五因子试算

年龄不加权。0—30 天与 31—90 天使用同一因子方向和硬门槛；项目发布不足 14 天时使用 `effectiveWindowDays=min(ageDays+1,14)`，尚未发生的日期不计缺失、不计零分，与相同发行日龄的冻结历史基准比较。历史必须从真实 T0 回溯，不能从程序首次收录开始。

| 因子 | 内部权重 | 主要输入 |
|---|---:|---|
| D 交易需求 | 25 | 独立交易地址、重复参与、活动连续性、买卖参与结构 |
| L 流动性与退出 | 25 | 流动性/市值或FDV、估算滑点、流动性保留、价格冲击 |
| S 持币与供应 | 20 | 头部集中度、HHI、非尘埃持币地址、Mint/Burn与净供应 |
| G 活动与估值关系 | 15 | 成交额/市值或FDV、地址和交易增长相对估值变化 |
| Q 稳定性与异常集中 | 15 | 单日成交、地址、大额成交、价格和流动性异常集中 |

动态贝叶斯分数只用于分类内排序、变化监控和时间外校准。前台不得使用“总分达到某值，所以是凸性线索”的表达。形成线索必须满足冻结的使用扩张、流动性形成、代币功能或供需结构证据路径，并同时展示支持、反证、未知项和失效条件。

缺失字段不写 0、不跨因子重新分配权重；关键来源超时使项目进入数据受限，不把来源失败冒充项目基本面恶化。具体因子映射、路径阈值和可信度门槛必须经过 Gate 0 全量影子分布与时间外回放后才能冻结。

## 5. 形成线索阻断与异常边界

以下情况阻断“形成线索”，不允许靠其他分数抵消；除明确硬交易风险和身份冲突外，项目可以继续以新发观察、持续观察或数据受限状态存在：

- 无法真实卖出、异常税费、冻结、黑名单或可随意增发。
- 成交主要由少数地址完成，买卖地址高度重合或疑似循环交易。
- 钱包增长主要来自零余额、尘埃余额或同源批量钱包。
- 流动性短期注入后快速撤出，或者单池和单LP依赖过高。
- 付费推广、Boost或项目方营销是主要活跃来源。
- 项目、资产、合约或交易池身份存在冲突。

## 6. 前台四状态边界

全部硬门槛通过项目必须互斥进入：形成线索、新发观察、持续观察或数据受限。

- 形成线索：满足至少一条具体证据路径，不由综合总分单独决定。
- 新发观察：真实历史不足 14 天，尚未形成证据路径。
- 持续观察：真实历史已满 14 天，尚未形成证据路径但硬门槛继续通过。
- 数据受限：额度耗尽、来源故障、回溯断档或关键数据超时影响当前判断。

GitHub-only、价格上涨、低市值、付费 Boost、项目方广告或单一大额地址活动不得单独形成线索；GitHub-only 只能帮助通过宽硬门槛并固定显示“仅代码证据”。四状态具体数值阈值尚未冻结，必须先用接入范围内全量对象观察分布和异常样本。

## 7. 免费优先决策

当前不申请付费接口。只有出现以下任一事实，才建议申请新的免费试用；免费试用仍不能解决时才讨论付费：

1. 免费资源无法覆盖接入范围内全部深采达标对象的交易、流动性和钱包三类核心字段。
2. 免费额度无法支持目标项目数与刷新频率。
3. 历史回溯不足以计算新增钱包、留存、持币结构和持续成交。
4. EVM 当前持币者重建成本明显高于免费额度。
5. 数据错误率、延迟或中断导致强线索无法稳定复算。

## 8. 下一道门槛

在 Gate 0 对已接入范围内的完整发现总体进行不少于 14 个连续自然日的影子采集：所有疑似 `T0≤90天` 对象做基础扫描，所有深采达标对象做深度采集，不预设项目数量上限。记录：

- 每日发现总体、T0 状态和 A/B/C/D 分布；
- 基础扫描覆盖率、深采门槛通过数和深采覆盖率；
- 每项目、每天的请求量；
- 免费额度消耗；
- 采集错误率和延迟；
- 跨来源一致性；
- 钱包去重、交易者归因和反操纵规则能否复算。
- 未通过、硬否决、来源失败和第 91 天退出对象的保留完整性。

影子采集不生成前台凸性结论或近期活跃结论，不写入现有评分、动作或 L0—L5。完成后才能决定免费资源是否足够，并以全量总体校准强弱算法；固定边界案例只负责回归验收。
