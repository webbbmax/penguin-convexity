## 1. 产品是什么

“企鹅投研-凸性”是一套寻找非线性收益机会、保存证据、形成可复核研究结论并持续跟踪变化的独立本地软件。它不是行情终端、交易机器人，也不是通用项目资料库。软件只提供研究与动作建议，不连接钱包，不自动下单。

当前已发布 C2.2 在 C2.1 新发代币筛选主干上恢复并整合既有凸性跟踪：两个作业独立运行、用稳定身份和原子快照交接，前台同时展示生命周期与跟踪状态；正式范围只以 `docs/C2.2_REQUIREMENTS_LOCK.json` 为准。C2.1 继续作为冻结回滚基线。

用户打开桌面快捷方式“企鹅投研-凸性”后，首页直接看到凸性机会中心。当前 C2.2 前台导航只有“机会首页、全部机会、重要变化、我们如何判断”；项目详情从项目入口进入，不是顶级栏目；本地桌面版通过右上角低干扰“管理工作台”进入独立后台。

不设置跨业务的“今日结论”。“当前结论”只存在于凸性机会中心内部。

2026-08-03 用户进一步明确：上述三入口是迁移后保留的当前实现，不是正确的长期产品架构。凸性机会中心是面向普通用户、未来可能公开上线的前台；凸性工作台是管理维护后台；项目详情只从项目入口进入，不再作为顶级栏目。C1.9 必须按这一边界重构。

## 3. 六类研究维度必须分开

### 3.1 L0-L5：事实成熟度

L0-L5 只描述事实与证据从早期线索到成熟/转移阶段的进度，不代表风险高低、仓位大小或剩余凸性：

- L0：只有早期线索或叙事，关键身份、事实或价值链尚未形成可核验闭环。
- L1：出现独立硬痕迹，但证据、价值捕获或市场表达仍明显不完整。
- L2：已有多项可用事实，关键关系开始可验证，仍需补足行动闭环。
- L3：主要事实、受益资产和路径已较成熟，重点转向事件超预期、价格反应和剩余凸性。
- L4：事实与结构高度成熟；只有逻辑和剩余凸性仍同时成立时才评估完整目标仓位。
- L5：事实与价格进入趋势/反身性阶段，退出早期错配框架，转入反身性管理。

当前机器规则以 `storage/rulebook-v1.json` 和代码测试为准。L0-L5 不得被风险、交易性、点火距离或动作反推。

### 3.2 风险

风险独立记录身份、合约、团队、治理、资金、监管、安全、流动性和数据可靠性等阻断。风险高不等于凸性高，风险低也不等于可以行动。

### 3.3 剩余凸性

判断上行是否仍未被充分定价。价格已经完整反应且没有事实升级时，即使项目质量高，也可能只剩低或无剩余凸性。

### 3.4 交易性

判断实际能否建立和退出仓位，包括资产身份、市场、卖出路径、流动性、成交量、滑点、合约行为与风控。当前规则的标准门槛为流动性不少于 25 万美元、24 小时成交量不少于 10 万美元、退出滑点不高于 3%；极限试仓门槛为流动性不少于 2 万美元、成交量不少于 2.5 万美元、退出滑点不高于 5%，且只允许现货、无杠杆。实时数值必须重新采集，不能把历史快照当成当前值。

### 3.5 点火距离

判断催化发生的时间与确认距离。它不是新闻热度；必须明确催化、受益资产、价值传导、市场表达、退出能力和失效条件。

### 3.6 当前动作

- 普通建仓：L2-L4 为主，证据、价值捕获、风险和标准交易性已经明显降险，且仍有未充分定价上行；分阶段建立普通仓位。
- 极限试仓：仅面向 L0-L2 的极少数例外，全部行动硬门槛通过；现货、无杠杆，不超过目标仓位的 5%。结果允许为空。
- 只观察：保留研究价值但至少一个行动硬门槛未完成，等待明确证据或事件。
- 反身性管理：进入 L5 或价格/共识已经充分反应，按趋势和退出规则管理，不再用早期错配框架新增仓位。
- 失效/排除：核心逻辑被否定、身份或资产关系冲突、风险阻断或催化失效。

仓位提示是“相对目标仓位”而非账户总资产比例。现行参考：L1 为目标仓位 10%-20%，L2 为 30%-50%，L3 由事件超预期、价格反应和剩余凸性决定；L4 只有逻辑与剩余凸性同时成立时才评估完整目标仓位。任何仓位提示都不能绕过硬门槛。

## 4. 生命周期研究路线

- 早期项目：有可信公开启动日期且未满 6 个月；满 6 个月自动转入潜力项目。先核验身份、产品、入口、代币经济、合约、流动性、团队和审计，再研究催化。
- OG 项目：有可信证据表明已存活至少 5 年。优先跟踪治理、代码、部署、采用、监管和结构变化，同时保留基础档案。
- 潜力项目：公开启动 6 个月至 5 年，或创建时间尚不能可靠核验。平衡补齐基础资料和持续变化。

收录日期不是创建日期；日期不可靠时不得猜测为早期或 OG。生命周期类别只决定研究路线，不直接改变 L0-L5、风险或当前动作。

## 5. 凸性成立的基本证据链

社交热度、低市值、波动和上涨本身不构成凸性。候选至少要能回答：

- 凸性来源是什么：事实错配、价值捕获、事件路径、供应变化或其他可核验非线性来源。
- 最坏情况是什么：技术、安全、监管、流动性、治理和身份失败会损失什么。
- 点火条件是什么，何时失效。
- 受益资产是否真实、官方关系是否可核验。
- 能否买入、能否卖出、滑点与合约行为是否可解释。
- 当前处于普通建仓、极限试仓、只观察、反身性管理还是失效/排除。

错配分只用于排序研究优先级，不自动生成买卖结论。X、社区、推广和匿名消息只能用于发现线索，不能独立支撑结论。

## 6. 机器自动运行与数据主干

核心数据库为 `data/convexity.db`。M1.0 基线含 585 个项目与 585 个候选记录。机器链路包括：发现、身份解析、项目建档、资料补齐、来源归属、原始留存、证据账本、溯源、评分、机器结论、监控目标、催化路径、跟踪任务、快照重建、更新任务和守护状态。

重要数据量基线：原始事件 12,446、来源发现 10,936、来源适配记录 16,164、证据 2,519、证据溯源 44,719、弱线索 11,042、监控目标 2,635、催化路径 616、运行 26、扫描结果 106。完整清单与哈希见 `docs/MIGRATION_MANIFEST.json` 和 `docs/migration/`。

原始记录与研究证据分层：线索可以只有原始留存，但不能假装已经形成证据；证据必须保留来源、时间、项目归属和溯源关系。空 URL、模糊名称和冲突关系不能自动补齐。

## 7. 公共 API 资源边界

公共 API 资源库只提供资源目录、文档地址、凭据环境变量名称和总额度说明。`scripts/sync_shared_api_catalog.py` 是显式同步工具，生成本项目的 `config/shared-api-catalog.json`；该文件不得包含密钥、启用状态、健康结果、游标、运行日志或任务状态。

凸性自己的状态位置：

- 数据与去重：`data/convexity.db`
- 采集游标：`data/source-discovery-cursors.json`
- 任务与守护状态：`data/update-runtime-status.json`
- 运行日志：`runtime/logs/`
- 缓存：`runtime/cache/`
- 启用和采集配置：本项目数据库、fixtures 与本项目配置

不得从其他业务项目读取这些状态，也不得把凸性状态写回公共资源库。

## 9. 需要防止复发的历史问题

- 桌面依赖旧综合壳或其他业务路由，导致本项目无法独立启动。
- 仅用脚本判断页面存在，没有真实点击验证 iframe、导航和返回路径。
- iframe 选择器超时被误判为页面失败；应同时检查页面加载、URL、可见内容和控制台错误。
- 项目队列点击后进入错误详情，或详情返回时丢失原筛选与滚动位置。
- 单项更新完成后状态不明确、页面跳位。
- 空 URL、模糊名称或同名项目被自动归为证据，污染溯源。
- 项目 ID 变化导致身份、生命周期、早期/OG/潜力分类和历史记录失联。
- 快照重建无条件刷新全部身份别名的更新时间，造成内容未变但迁移前后逻辑摘要不同；M1.0 已改为仅在别名内容变化时更新。
- 弱线索被直接计分或变成行动结论。
- 数据重建造成项目数量、去重或历史证据变化。
- 桌面冷启动在端口开放前同步重建全部快照，导致第一次打开等待约 40 秒；C1.7 维护修复为先开放上次有效快照、后台重建，并保留启动重建状态与失败回退。
- Windows PowerShell 5 对 UTF-8 无 BOM 的中文脚本解析异常；桌面启动脚本保持 ASCII 源码并在运行时生成中文标题。
- Windows 计划任务直接启动 `python.exe` 会在登录后补跑或整点自动运行时显示黑色控制台，容易被误认为桌面入口故障；C1.8 维护已改为由 `wscript.exe` 和本项目隐藏启动器运行调度脚本，任务逻辑、退出码和状态记录不变。
- Edge/浏览器的非业务告警不能替代功能判断；但真实 JavaScript 错误、404 和加载失败必须处理。

## 10. 用户体验要求

- 用户不需要打开终端或理解数据库。
- 首页先给结论，再解释阻断、变化和下一步，避免把工具列表当首页。
- 前台机会中心面向普通用户，只显示判断、机会、变化、风险、催化和必要的数据时间；不得展示后台任务、来源适配、Watcher、孤儿证据、重试、调度、日志或模型工具。
- 后台工作台面向维护者，负责运行、任务、来源、证据、异常、配置和恢复；任何写操作只在后台出现。
- 项目详情是上下文页面，不是产品栏目；从哪里进入就返回哪里，并恢复筛选、页码与滚动位置。
- 前后台使用独立页面壳和独立用语；同一页面不得同时出现机会中心导航和工作台导航。
- UI 使用浅色、现代、清晰的视觉层级；主结论和主任务突出，端口、来源数量和技术说明弱化。可见业务版本号只在工作台浅色左侧栏底部固定显示一次，前台、项目详情和其他界面不显示版本号。
- 长时间更新必须持续显示阶段、进度、最近心跳、成功/失败数量和明确状态，使用户能区分正常运行、外部等待、可能卡住和已经失败。
- 任一动作必须能看到证据、反面证据、风险、失效条件和下一次观察触发器。
- 筛选、详情返回、窗口位置和重复启动行为要稳定。
- 更新与写操作应清楚区分，验收时只走只读路径，避免误改业务数据。
- 交付语言固定说明：完成了什么、桌面从哪里打开、能看到什么、测试结果、未完成风险、下一最高优先级。每次普通对话结束也必须明确告诉用户下一步要做什么；没有用户动作时给出当前最高优先级。

## 12. 已冻结的 C1.8 机会中心决策体验与自动跟踪闭环

用户在 2026-08-02 明确要求冻结下一版需求。C1.8 已完成实现、Sol 阻断修复和最终验收，并于同日发布；冻结产品范围没有修改评分、动作、L0-L5或业务边界。

核心范围：

1. 机会中心由单页七段长滚动改为“一屏决策摘要 + 独立详情”，七类业务语义继续保留。
2. 首页只展示本轮行动结论、接近门槛项目、重要变化、系统工作与需要我处理；每块最多 5 条。
3. “为什么还不能行动”改为“行动条件与缺口”，每条显示事实、门槛、影响、负责人、下一步和时间。
