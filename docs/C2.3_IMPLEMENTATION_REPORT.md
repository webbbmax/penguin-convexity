# 企鹅投研-凸性｜C2.3 整版开发报告

状态：整版开发与开发自测完成；2026-08-12 独立终验 38/38 通过并已发布。

完成时间：2026-08-12 11:39（Asia/Shanghai）

## 1. 大白话结论

C2.3 已把新的 Windows 软件容器完整做出来：它拥有自己的 WPF 窗口，用 WebView2 显示现有 C2.2 页面，不再依赖普通 Edge 的 `--app` 窗口。开发预览已真实打开机会首页、全部机会、项目详情、工作台和两个独立更新页面。

本轮没有改网页业务、评分、规则、数据库结构、更新频率或后台任务。正式桌面快捷方式也没有提前切换，用户当前使用的 C2.2 入口仍可正常回滚。

## 2. 已实现能力

- `.NET 10 LTS＋WPF＋WebView2 Evergreen`，Windows x64 自包含发行。
- 独立 WebView2 数据目录：`runtime/webview2/user-data`，不复用普通 Edge 或 Chrome 资料。
- 单实例锁加明确的进程间唤醒；重复打开不枚举浏览器标题、不创建第二窗口。
- 8766 健康检查同时核验产品、迁移版本、数据主干和 C2.2 体验身份。
- 已存在的健康服务只复用、不停止；容器自己启动的服务只记录和处理精确 PID。
- 启动三阶段、等待时间、五类大白话故障页、日志入口、页面进程一次自动恢复。
- 本项目内原子窗口状态；兼容导入旧 `runtime/window-state.json`，屏外窗口回主屏。
- 只允许 `127.0.0.1:8766` 留在容器；用户主动外链交给默认浏览器，自动外跳、弹窗和下载被阻止并记录。
- C# 不读写业务数据库、不调用第三方业务 API、不形成第二业务通道、不新增调度器。
- 构建、隔离预览、正式安装和单独回滚脚本已经提供；开发阶段只生成隔离预览入口。

## 4. 仍需独立终验的项目

开发自测没有为了制造故障而停止当前外部 8766 服务、占用正式端口、卸载 WebView2 或中断正在运行的候选生产。因此以下项目已实现并有单元/协议覆盖，但仍应在独立隔离条件下做最终验收：

- 服务完全关闭时的冷启动与容器自有服务精确 PID 回收。
- 未知程序占用 8766 时的真实端口冲突页和未知进程保留。
- WebView2 缺失/损坏时的安装页、离线说明和重新检测。
- WebView2 页面进程真实失败后的一次自动恢复。
- 1180×760、1440×900、最大化、多显示器和屏外恢复的最终视口复验。
- 正式快捷方式切换、正式入口真实启动和只恢复快捷方式的回滚演练。

这些是独立终验事项，不是待开发功能。终验通过前不得写发布清单或切换正式桌面入口。
