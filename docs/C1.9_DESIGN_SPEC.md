# C1.9 UI 与交互设计规格

状态：已冻结，属于 C1.9 需求锁  
范围：前后台分离、浅色 UI、信息层级、交互状态和长任务可见性；不改变投资研究规则。

## 1. 设计原则

1. 先给结论，再给理由，最后才给技术依据。
2. 前台是阅读和判断界面；后台是运行和维护界面，两者不混用控件。
3. 重要内容靠层级、留白和位置突出，不靠大面积深色或多个高饱和按钮。
4. 同一屏只有一个主要动作；长列表有边界，长任务有过程。
5. 状态不能只靠颜色表达，必须同时有文字和图标。

## 2. 视觉令牌

沿用现有 Logo、口号“洞见共识之外的价值”和南极蓝，不重新设计品牌。

| 用途 | 建议值 | 说明 |
|---|---|---|
| 品牌主色 | `#0288C8` | 现有南极蓝，主要按钮和选中态 |
| 主文字 | `#102A3A` | 标题与关键结论 |
| 次文字 | `#587080` | 解释、时间、来源 |
| 页面背景 | `#F5F9FB` | 冰川灰浅背景 |
| 卡片背景 | `#FFFFFF` | 阅读与任务卡片 |
| 分隔线 | `#DCE7EC` | 轻边界，避免重卡片感 |
| 选中背景 | `#E8F5FB` | 前后台导航选中态 |
| 成功 | `#16866A` | 同时配“成功/正常”文字 |
| 警告 | `#A96812` | 同时配原因和处理建议 |
| 失败 | `#C34755` | 同时配影响范围 |

- 中文：`PingFang SC`, `Microsoft YaHei UI`, sans-serif。
- 英文与数字：`Inter`, `Segoe UI`, sans-serif。
- 页面标题 28/36、模块标题 20/28、卡片标题 16/24、正文 14/22、辅助 12/18。
- 采用 8px 间距体系；卡片圆角 12px；按钮圆角 8px；只用轻阴影。
- 主要内容最大宽度 1280px，1440px 桌面宽度下保持充足留白；兼容 Windows 125% 缩放。

## 3. 前台界面

### 3.1 页面框架

```text
┌ Logo  机会首页  全部机会  重要变化  我们如何判断       搜索  管理工作台 ┐
├───────────────────────────────────────────────────────────────┤
│ 数据状态提示（仅在过期、不完整或更新失败时出现）                     │
│ 当前判断：一句话结论                              判断时间 / 依据    │
│ [当前动作摘要]                         [离行动最近，最多 6 个]       │
│ [重要变化，最多 5 条]                   [当前主要限制，最多 3 条]     │
└───────────────────────────────────────────────────────────────┘
```

- 正常数据不占用大面积“系统状态”卡；只有过期、部分完成或失败才出现顶部提示。
- 当前判断占据首屏最高层级；数据库数量、任务数量和内部版本号不与结论争夺注意力。
- 首页每块提供“查看全部”，不在首页继续向下堆满全量内容。

### 3.2 机会卡片

主层只显示：项目名、当前动作、一句话理由、最大风险、最近变化时间。点击整张卡片进入详情。

禁止在主层显示：任务 ID、负责人、待核验数量、待闭环数量、Watcher、来源适配、运行阶段、技术字段名。若数据不完整，使用一句普通语言说明。

### 3.3 重要变化

每条结构固定为：

1. 发生了什么；
2. 对判断有什么影响；
3. 何时发生、依据是什么。

默认最近 7 天、20 条/页。仅展示会改变或可能改变阶段、风险、交易性、剩余凸性、点火距离或动作的事件。“没有影响判断的新变化”不进入信息流。

### 3.4 项目详情

详情顶部显示来源化返回按钮和一句话判断。正文顺序：为什么值得关注 → 现在如何处理/为什么不行动 → 最近变化 → 催化、风险与失效 → 折叠的证据与数据时间。

- 没有全量项目下拉框。
- “上一个/下一个”只在来自同一结果集时出现。
- 返回恢复原筛选、页码、滚动位置和搜索词。
- 证据折叠层明确标记事实、项目方陈述和系统推断。

### 3.5 前台状态

| 状态 | 用户看到的内容 |
|---|---|
| 加载中 | 当前正在读取什么，不显示空白大屏 |
| 真实零结果 | “当前没有满足条件的机会”，并说明最后判断时间 |
| 数据过期 | “数据已超过正常更新时间，结论可能滞后” |
| 部分完成 | “部分来源本轮未完成，以下沿用已成功数据” |
| 更新失败 | “本轮更新失败，以下显示上次有效判断” |
| 无重要变化 | “最近 7 天没有发现足以改变当前判断的重要变化” |

## 4. 后台界面

### 4.1 页面框架

```text
┌──────────────┬─────────────────────────────────────────────────┐
│ Logo / 工作台 │ 页面标题          系统状态          返回机会中心 │
│ 概览          ├─────────────────────────────────────────────────┤
│ 更新与任务    │ 系统状态  当前任务  待处理事项  最近结果          │
│ 项目管理      │                                                 │
│ 证据与来源    │ 当前页面内容；一个主操作；技术细节按需展开        │
│ 监控与催化    │                                                 │
│ 模型与规则    │                                                 │
│ 设置与日志    │                                                 │
│               │                                                 │
│ 当前版本 C1.9 │                                                 │
└──────────────┴─────────────────────────────────────────────────┘
```

左栏为白色或极浅蓝，不使用深色渐变。一级栏目可展开二级页面，但同一时间只展开当前分组。版本号固定在侧栏底部，是整个可见产品中唯一的版本展示。

### 4.2 工作台概览

首屏四块信息：

1. 系统状态：正常、运行中、部分完成、失败、可能卡住。
2. 当前任务：名称、阶段、开始时间、最近心跳和进度。
3. 待处理事项：必须处理、建议处理、无需处理。
4. 最近结果：成功范围、失败范围、最后有效数据时间。

只给一个主动作。若当前无需操作，明确写“当前无需操作”，不制造待办。

### 4.3 全量更新进度

现有全量更新的 18 个技术组件在界面上归为 7 个可理解阶段：

| 阶段 | 用户名称 | 对应现有工作 |
|---|---|---|
| 1 | 市场与退出数据 | `market`、`formal_market_exit` |
| 2 | 项目与证据发现 | `high_value_evidence`、`source_discovery`、`evidence`、`discovery` |
| 3 | 合约与身份归属 | `contracts`、`identity`、`project_asset_identity` |
| 4 | 项目档案与研究材料 | `profile_enrichment`、`formal_research_materials` |
| 5 | 监控与数据健康 | `monitoring_infrastructure`、`weak_signals`、`data_backbone` |
| 6 | 研究结论与催化 | `machine_research_scoring`、`machine_conclusion`、`catalyst_trade_path` |
| 7 | 跟踪与页面发布 | `tracking`、页面快照重建 |

进度规则：

- 每个阶段开始、完成、失败时立即写入状态；长循环至少每 30 至 60 秒或每完成一批项目更新一次心跳。
- 已知总量才显示百分比和 `已完成/总数`；来源会动态变化时使用阶段进度和活动指示，不伪造精确百分比。
- 页面显示当前来源或项目的普通名称，不显示密钥、凭据路径或完整异常堆栈。
- 刷新页面、切换栏目、关闭再打开软件后继续读取同一任务，不重复触发。
- 离开页面不终止后台任务；不把浏览器连接中断误判为任务失败。

```text
凸性全量更新                                             正常运行
阶段 3/7：合约与身份归属
已处理 318 / 594 个项目    成功 287    等待 24    失败 7
最近活动：20 秒前 · 正在确认项目与资产关系
已运行 36 分钟 · 暂无法准确估计剩余时间
```

### 4.4 可能卡住与失败

- 有心跳：正常运行。
- 等待外部来源：显示来源、等待时长和超时规则。
- 超过阶段约定阈值无心跳：显示“可能卡住”，提供查看日志和终止/重试建议，但不自动写成失败。
- 进程明确退出或返回错误：显示“失败”，同时说明已成功的数据是否保留、影响范围和可重试入口。
- 部分完成：成功与失败分别计数；相同原因聚合，不逐条刷屏。

## 5. 交互规则

- 前台全部只读，不出现保存、执行、暂停、重试和调度按钮。
- 后台写操作先说明作用范围，完成后给出结果和可验证位置。
- 同一屏只允许一个实心主按钮；次要动作使用描边、文字或更多菜单。
- 表格超过一屏必须有固定表头、分页和结果总数；不使用无限滚动。
- 页面最多两级展开；原始日志进入独立抽屉或后台详情。
- 所有关键操作具备加载、成功、部分完成、失败和重试状态；不能只在控制台记录。

## 6. 可访问性与响应式

- 正文与背景对比度达到 WCAG AA；键盘可到达导航、筛选、分页、折叠和主要按钮。
- 焦点样式清楚；状态除颜色外同时使用文字/图标。
- 支持 1280×720、1440×900、1920×1080 和 Windows 125% 缩放。
- 1280px 以下后台左栏可收起；前台导航折叠为菜单，但仍保持页面层级和管理入口边界。
