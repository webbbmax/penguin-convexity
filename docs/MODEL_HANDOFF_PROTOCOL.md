# 企鹅投研-凸性｜模型使用与阶段交接协议

生效日期：2026-08-10  
适用范围：C2.1 及后续任务  
替代规则：本文件替代 2026-08-03 的强制 Sol / Luna 交接、短口令和双元数据审核规则；历史已发布版本的事实记录不改。

## 1. 模型选择

- 使用什么模型、何时切换模型由用户自行决定。
- 助手可以在模型能力会明显影响风险、成本或质量时给出一次建议，但建议不是门禁，也不能反复提醒用户切换。
- 助手不再读取、核对或审核 `turn_context.model`、`thread_settings_applied.thread_settings.model` 和推理强度，不因模型元数据缺失或不一致暂停任务。
- 用户没有要求切换时，继续在当前任务完成已授权范围，不自动发起模型交接。

## 2. 阶段边界仍然有效

取消模型门禁不等于取消产品门禁：

1. 规划与讨论阶段可以读取、分析和修改规划文档，但不得开始未冻结版本的产品编码。
2. 用户明确冻结后，才能生成需求锁并开始冻结范围内实现。
3. 开发自测和最终验收仍分别记录；最终验收必须重新执行完整验收，不得只相信实现报告。
4. 最终验收发现冻结范围缺陷时可直接修复并重验，不要求更换模型或新建任务。
5. 范围变化、评分变化、动作变化和新版本仍需用户明确授权。

## 3. 单任务与长任务

- 同一版本尽量在一个连续任务中完成已授权阶段，减少交接造成的上下文丢失。
- 用户没有要求拆分时，不把常规编码、修复或验收强行绑定到特定模型。
- 长时间数据任务必须独立于对话模型运行，具备分片、断点、可恢复游标、单实例锁和可见进度。
- 是否在对话中持续等待长任务由用户决定；模型不得因为等待而重复启动、从头重跑或反复输出无变化进度。

## 4. 回复要求

- 每次最终回复继续说明完成内容、验证结果、风险和下一最高优先级。
- 当前无需用户操作时明确写“当前无需你操作”。
- 不再把“切换到 Luna / Sol”写成固定结尾，不要求用户回复模型短口令。
- 如建议某个模型，只说明建议理由、成本和可选性；最终决定属于用户。

## 5. 历史说明

2026-08-03 至 2026-08-09 的 Sol 规划、Luna 实现、Sol 终验记录继续作为已发生的版本审计事实保存。2026-08-10 起，这些历史职责不再约束后续任务的模型选择，也不构成 C2.1 的冻结条件。
