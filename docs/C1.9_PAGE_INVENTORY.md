# C1.9 前后台页面清单与归属

状态：已冻结，属于 C1.9 需求锁  
原则：一个页面只能有一个产品角色；前台页面不得加载后台导航、后台页脚或管理控件。

## 1. 产品表面

### 1.1 前台：凸性机会中心

面向普通用户和未来大众访问者。只回答“现在怎么看、为什么、发生了什么、风险是什么”。前台全部只读。

| C1.9 页面 | 主要职责 | 现有页面迁移来源 | 处理方式 |
|---|---|---|---|
| 机会首页 | 当前判断、离行动最近、重要变化、当前主要限制 | `app/candidate-pool.html` | 重组为四个有限摘要区，不再承载后台任务 |
| 全部机会 | 可搜索、筛选、分页的机会列表 | `app/candidate-pool.html` 的项目类别与全部项目 | 拆成独立前台列表；默认 20 条/页 |
| 重要变化 | 只展示会影响判断的重要变化 | `app/change-explanations.html` | 建立前台专用版本；移除工作台导航和审核控件 |
| 我们如何判断 | 用普通语言说明判断框架、动作含义和证据边界 | `app/candidate-pool.html#rankingMethod` | 拆成独立只读说明页 |
| 项目详情 | 解释单个项目的判断、变化、催化、风险、失效和依据 | `app/project-detail.html` | 仅从上下文进入；删除顶级导航与全量项目下拉框 |

前台不设独立“催化路径”数据库页面。最重要的催化进入首页和项目详情，完整路径维护留在后台。

### 1.2 后台：凸性工作台

面向产品维护者。只回答“系统是否正常、正在做什么、做到哪、哪里失败、该如何处理”。

| C1.9 一级栏目 | 现有页面/能力归属 |
|---|---|
| 工作台概览 | `app/workbench.html`，系统健康、当前任务、待处理异常、最近结果 |
| 更新与任务 | `app/update-center.html`、跟踪执行、二次验证、调度、失败重试 |
| 项目管理 | `app/project-master-pool.html`、`app/source-discovery.html`、`app/network-discovery.html`、`app/weak-signal-inbox.html`、`app/manual-review.html` |
| 证据与来源 | `app/evidence-ledger.html`、`app/source-registry.html`、`app/source-adapter.html`、`app/high-value-sources.html`、`app/data-backbone.html`、孤儿证据 |
| 监控与催化 | `app/monitoring-infrastructure.html`、`app/catalyst-paths.html`、到期任务 |
| 模型与规则 | `app/scan-center.html`、`app/screening-console.html`、`app/four-layer-screening.html`、`app/rules-replay.html`、`app/gold-calibration.html`、`app/real-case-calibration.html`、`app/model-acceptance.html` |
| 系统设置与日志 | 自动运行时间、健康状态、运行日志、`app/data-dictionary.html`、备份和恢复提示 |

`app/discovery-funnel.html` 作为“项目管理”的分析子页，不在一级导航重复出现。

## 2. 导航和页面壳

### 2.1 桌面宿主

`desktop/index.html` 只负责桌面窗口宿主、页面切换和窗口状态，不再显示第三套可见导航、重复品牌标题或版本号。用户在任意时刻只看到前台壳或后台壳中的一套导航。

### 2.2 前台导航

固定顺序：

1. 机会首页
2. 全部机会
3. 重要变化
4. 我们如何判断

本地桌面版右上角提供低干扰“管理工作台”入口；未来大众构建隐藏该入口。项目详情、催化路径和跟踪任务不作为前台顶级导航。

### 2.3 后台导航

后台使用浅色固定左侧导航，顺序按 1.2 的七个一级栏目。高级工具在一级栏目内按任务分组，不再全部平铺为同权入口。后台顶部提供“返回机会中心”。

## 3. 页面退出与合并

- 删除可见的顶级“项目详情”导航，但不删除项目详情能力。
- 前台删除“跟踪任务”“自动执行”“负责人”“待重试”等后台栏目；相应能力移入“更新与任务”。
- 前台不再链接后台版 `catalyst-paths.html`；普通用户看到的是项目相关的催化摘要。
- `action-gaps.html` 的面向用户部分合并到“当前主要限制”和项目详情；任务责任、核验状态和重试能力移入后台。
- `change-explanations.html` 不得继续复用后台壳；审核与技术字段移到后台变化详情。
- 前台页面不得加载 `workbench-nav.js`；后台页面不得加载前台导航组件。

## 4. 路由角色表

实施时建立一份机器可校验的路由角色表：`front`、`admin`、`context-detail`、`host-only`。每个活动页面必须且只能登记一个角色。未来大众构建只允许 `front` 和 `context-detail` 角色进入发布清单。

## 5. 版本号唯一展示规则

- 面向用户可见的业务版本号只在后台工作台浅色左侧栏底部固定区域显示一次，格式为“当前版本 C1.9”。
- 该固定区域由后台共享壳渲染；后台子页面不得在标题、卡片、页脚或正文重复版本号。
- 机会中心、项目详情、桌面宿主、公开页眉、公开页脚、Logo 附近和普通栏目不得显示 C1.9、C1.8、C1.7 或 M1.0 等产品版本标签。
- 健康接口、运行日志、验收清单和内部文档可以保留机器版本字段，但不得把它们渲染为普通用户界面标签。
- 工作台侧栏收起时，版本信息只在侧栏底部悬浮说明中出现，不得另外复制到顶部。

## 6. 完成判定

- 当前活动页面 100% 有唯一角色和唯一归属。
- 前台没有后台导航、管理操作、系统任务语言或可见版本号。
- 后台七个一级栏目覆盖全部管理能力，没有孤立入口。
- 桌面宿主不产生第二套可见导航。
- 任意后台页面可见版本号计数为 1，任意前台/详情页面可见版本号计数为 0。
