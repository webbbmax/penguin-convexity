# C2.5 修复候选预审复核

结论：此前把 824 项执行结果不一致的“诚实阻断”计作预审通过，以及依赖发布后下一次合法运行补齐快照，都会导致 J05 无法在发布前验收；现已在同一 C2.5 冻结范围内修复。候选先从正式数据库只读事务生成并封存完整产品快照，再由正常候选服务和默认产品探针从文件读取；不使用内存重建或探针旁路。逐资产 current/rollback 均为 0 差异，规则治理按钮正常可用；缺失、篡改或哈希不一致仍阻断。

候选绑定：包含本文件的 Git 提交；基线仍为 `becd256b170b0a3a1a45de0b8c4f4a426eb9065a`，分支仍为 `codex/c2-5-manager-control-plane`。

## 阻断收口

1. 规则审批与回滚
   - 规则透明页不再写“C2.5 不直接编辑规则”；现改为“冻结 JSON 不直接改写”，同时提供版本草案、影响预览、批准、拒绝和明确版本回滚。
   - 只允许 C2.5 已冻结的两个既有版本，不能在页面创造新规则语义。草案保存差异、原因、范围、结束条件和同输入重放证据；审批与回滚生成新的不可变版本记录和原子选择器。
   - `evaluate_public_baseline`、`evaluate_strong_paths`、`normal_exit_decision` 和 C2.4 快照/跟踪入口在一次合法运行开始时读取一次所选版本。回滚到冻结版本会真正恢复公开底线、强路径、单位变化和立即退出规则；回滚到活动试行会恢复已授权试行行为。
   - 旧快照、旧版本、草案、审批和原始业务证据不改写。正式环境只读探针没有创建选择器或写入状态。

2. E06/E08 逐规则透明度
   - 删除“把一个全局重放结果复制给 9 条规则”的实现。每条规则分别计算适用数量、N/A、基线/有效通过、变化数量、新增/移除 assetId 与真实样本。
   - 页面有效值与 `scripts/c2_4_rules.py` 的实际代码清单按 `ruleId` 和字段值精确对账；任何一条字段不一致都会单独失败，不再用“覆盖是否启用”冒充代码一致。
   - 固定反例 `only_cross_source_deviation_changes` 只改变跨来源偏差及其真实下游路径，其他无关登记规则变化数保持 0；规则结果不再复制全局重放。

3. 暂停真实反馈
   - 现役筛选安全暂停必须同时得到主 C2.2 作业和关联筛选流水线的接受结果。
   - 关联暂停抛出异常时，系统会补偿撤回主作业暂停请求并返回失败；不会再返回 `pause_requested` 成功。若补偿也失败，错误明确标为真实状态需核验。
   - 频率、后续周期暂停和安全暂停请求均可从已接受的结果审计恢复到明确前值；回滚本身重新经过预览、确认、执行、权威回读，并记录 `rollbackOf`。

4. Tier 1 规则治理契约收口
   - 规则变更证据现在固定保存两组独立重放：版本控制的固定历史样本，以及带快照ID、数据时间和内容哈希的当前只读样本。
   - 回滚预览不再移除 `replayEvidence`，并单独返回受影响assetId、`c22.screening`/`c22.convexity_tracking`和当前C2.4跟踪/前台/后台快照ID。真实零影响显示空集合，不补样本。
   - 版本记录新增运行关联状态。下一次真实C2.2合法运行原子发布快照后，以独立不可覆盖关联记录保存 `linkedRunId`、三份 `linkedSnapshotIds`和关联时间；旧版本及原始证据不改写。
   - 总体受影响资产不再只比较公开资格。18条完整登记规则分别计算新增、移除和状态变化，再对公开资格、四条强路径、立即退出、风险/硬阻断、失效/暂停/单位稳定等集合求并集；已收回两个已知漏报反例。
   - 四条强路径对冻结版和活动试行版分别调用 C2.4 真实 `evaluate_strong_paths`。`supplyUnitScaleStable=null` 固定反例中，供应/持币路径由 `unavailable` 变为 `formed`，并进入总体影响集合。
   - 正式探针不再只验证候选内部并集；它以同一只读快照逐资产直接调用 C2.4 执行器，对四条强路径的状态摘要和变化 assetId 集合逐项对账。当前投影无法复现已存执行结果时，仍展示直接复算影响，但明确显示“影响无法完整计算”并阻断草案批准和版本回滚。
   - C2.4 构建器现在把真实送入公开底线与强路径执行器的字段保存为版本化、哈希化 `ruleReplayInputs`。供应/池历史、单位稳定、OHLCV计数、跨来源冲突、卖出税和硬阻断字段均明确保存；C2.5 不再从来源健康或页面摘要反推规则输入。
   - 后台原始重放输入只进入跟踪快照，不进入公开前台快照。字段缺失、版本/哈希不匹配或执行结果不一致仍触发异常保护。
   - 正式产品探针的 J05 判定已改为硬门槛：current 与 rollback 都必须输入完整、执行结果差异 0、`complete=true`、`approvalBlocked=false`；`attention` 或诚实阻断不再算通过。
   - 发布前候选状态由 `scripts/c2_5_prepare_candidate_product.py` 在已登记临时产物中持久化；绑定、清单、封存标记和五份治理相关快照哈希必须一致。正常 `serve_local.py` 直接读取该状态并跳过启动重建，正式数据库只以只读路径参与候选验收。
