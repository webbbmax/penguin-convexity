# 企鹅投研-凸性｜D0正式开发与发布流程

## 1. 适用范围

本流程适用于 D0 完成后的产品版本、核心修复和发布。D0 自身也必须按本文件的门禁执行。它约束工作方式，不改变 C2.4 产品业务、数据或研究规则。

官方 Codex 参考：

- [Best practices](https://learn.chatgpt.com/guides/best-practices)
- [Projects and chats](https://learn.chatgpt.com/docs/projects)

外部文档只提供方法参考；本项目冻结需求和程序边界仍以本项目需求锁为准。

## 2. 名词

- **正式主干**：`main` 上最近一次已发布、可恢复的提交。
- **正式目录**：`F:\codex项目\企鹅投研\凸性`。
- **开发工作区**：`F:\codex项目\企鹅投研\凸性-worktrees\<任务名>` 下的临时 Git worktree。
- **冻结稿**：用户用产品语言确认的范围、非范围、程序上限和验收画面。
- **需求锁**：冻结文件路径、大小、哈希和继承依赖的机器清单。
- **核心纵向链路**：从真实输入、规则、持久化、快照到真实桌面显示的一条完整用户结果链。
- **发布候选**：不再修改、可由提交和哈希唯一定位的验收对象。
- **独立预期**：不调用实现中的集合判断函数，从原始数据或固定样本重新得出的预期结果。

## 3. 任务组织

### 3.1 规划与冻结任务

输入：目标、现实异常、用户希望看到的结果、截图或真实样本。  
输出：程序能做与不能做、继承与非范围、固定正反样本、大白话冻结稿和验收标准。  
门禁：用户明确冻结前不得编码。

### 3.2 开发与开发自测任务

输入：已冻结需求锁、干净正式基线和回滚点。  
输出：核心纵向链路、其余冻结范围、需求追踪和开发自测。  
门禁：Tier 0 失败时停止扩展和低优先级测试。

### 3.3 独立终验与发布任务

输入：固定提交的发布候选。  
输出：独立预期对账、真实桌面验收、缺陷修复后的受影响重验、发布清单。  
门禁：发布必须另获用户明确授权。

模型由用户决定；任务分离是阶段责任分离，不是模型门禁。

## 4. Git和目录规则

1. 正式目录只保持 `main` 和正式运行数据。
2. 未经授权不得在正式目录开始新功能开发。
3. 每项新工作使用 `codex/` 前缀分支；需要与正式运行隔离时使用开发工作区。
4. 开发工作区不复制正式数据库，不保存正式密钥或运行状态。
5. 多个任务不得同时写同一工作区；并行写入必须使用不同 worktree。
6. 合并前必须确认正式 `main` 干净、需求锁匹配、候选提交固定。
7. 禁止 `git reset --hard`、猜测性删除、整目录覆盖和把运行数据整体加入 Git。
8. 公开推送前必须执行密钥与大文件边界检查。

## 5. 需求追踪

每个版本建立机器可读追踪表，至少包含：

- requirementId
- 用户可见结果
- 实现文件或“不需编码”原因
- 生产者与消费者
- 固定正反样本
- 测试编号
- 真实桌面证据
- 状态与阻断原因

追踪率不是按文档行数计算。Tier 0 核心要求缺少任一实现或证据即为失败。

## 6. 测试优先级

1. Tier 0：核心业务集合和核心纵向链路。
2. Tier 1：规则、数据库、身份、原子交接和恢复。
3. Tier 2：直接相关接口、页面、继承契约和资源。
4. Tier 3：正式桌面启动、单实例、真实点击、返回和窗口状态。
5. Tier 4：边缘页面和与改动无关的历史回归。

Tier 0 或 Tier 1 失败立即阻断。只有共享核心、数据库、调度、桌面容器、发布或影响边界不清时才扩大完整回归。

## 7. 发布候选

1. 发布候选必须对应唯一提交。
2. 终验开始后不得在候选上继续无记录修改。
3. 修复形成新提交后，旧验收结果不自动继承；按影响边界重验。
4. 真实桌面使用发布候选，不用开发服务器页面代替。
5. 发布前再次核对候选提交、核心文件哈希和桌面程序哈希。
6. 发布清单同时记录回滚提交、备份和用户授权。

## 8. 长任务

超过 15 分钟的任务必须由程序而非模型思考过程维持，具备分片、断点、原子检查点、可恢复游标、单实例锁、进度、心跳、错误分类、重试上限和终态。是否由 Codex 持续监测由用户决定；任何情况下不得重复启动或从头重跑已完成范围。

## 9. 当前真相优先级

执行 D0 后，读取优先级固定为：

1. `AGENTS.md`
2. `docs/CURRENT_STATE.md`
3. 当前任务的阶段文件和需求锁
4. `docs/PRODUCT_BASELINE.md`
5. `docs/DEVELOPMENT_WORKFLOW.md`
6. 当前版本正式文件
7. 历史索引与归档

历史任务和聊天仅用于精确追溯，不得覆盖当前冻结文件。

## 10. 停止条件

发现需求歧义、程序能力不足、密钥风险、正式数据可能被误写、候选漂移、核心集合不一致、桌面入口不匹配或回滚点缺失时停止当前阶段，报告证据，不擅自改变范围或用低优先级通过数放行。
