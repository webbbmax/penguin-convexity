# 企鹅投研-凸性｜C2.5 管理者控制面 PRD

状态：正式冻结  
冻结日期：2026-08-14  
用户授权：`按冻结稿冻结 C2.5`  
当前已发布产品：C2.4；C2.5 尚未开发、尚未发布。

## 1. 产品结论

C2.5 把“工作台”从后台页面集合升级为产品管理者的真实控制面。管理者对所有产品功能、自动任务、手动入口、规则、数据来源、运行状态、异常和变更记录拥有完整知情权；对现役任务拥有经过安全保护的控制权。

界面可以降低理解成本，但不能减少管理者可见的信息、入口或权限。任何必须咨询开发人员或 Codex 才能知道的现役任务或有效规则，都视为产品缺陷。

## 2. 用户与责任

- 普通用户：继续使用 C2.4 机会中心，只看机会、变化、判断、风险、催化和数据时间。
- 产品管理者：查看完整任务、规则、来源、快照、异常和审计；执行受保护的任务控制；批准规则变更或回滚。
- 系统：按唯一真实通道运行，保存检查点，报告事实，不自行扩大权限。
- 开发与验收：实现和验证冻结要求，不能用工作台按钮绕过版本治理。

当前单机首版只有一名本地管理者，也必须记录操作人、来源和结果；不因单机而取消责任审计。

## 3. 成功结果

管理者打开工作台后可以独立回答：

1. 一共有多少自动、手动、隐藏、恢复、旧版和停用入口。
2. 现在什么在运行，运行到哪一步，最后心跳和检查点是什么。
3. 上次和下次运行时间、触发方式、结果及失败影响是什么。
4. 每项任务读什么、写什么、影响哪些页面和对象。
5. 当前真正生效的是哪条规则，冻结基线和临时覆盖有何差异。
6. 任一 `assetId` 为什么通过、等待、撤下、失败或不公开。
7. 当前可以执行什么操作，不能执行什么，以及原因。
8. 最近谁改变了什么，改变前后、关联运行和回滚结果是什么。

## 4. 不可降级的四项权利

### 4.1 完整知情权

所有能读取或写入业务数据、改变快照、改变前台结果、改变任务状态或影响下次运行的入口，必须进入任务账本。Windows 任务、VBS 隐藏入口、Python 工具、HTTP API、恢复入口、旧版兼容路径和维护任务均不例外。

### 4.2 安全控制权

现役任务按底层真实能力提供立即运行、从检查点恢复、安全暂停、暂停后续周期、恢复后续周期、修改频率和局部重试。不可用的控制仍显示，并说明原因。

### 4.3 规则透明权

工作台同时显示冻结基线、当前有效规则、临时覆盖和历史版本；字段、阈值、单位、来源、影响数量和项目级理由不得为空或只显示机器码。

### 4.4 决策与审计权

高影响操作必须先展示影响，再由管理者确认；系统记录操作者、时间、前后值、影响、运行 ID、结果和回滚。

## 5. 正式范围

1. 管理者总览和全量任务账本。
2. 新币筛选、凸性跟踪、候选生产/历史续跑、维护、旧版和按需工具的独立详情。
3. 当前任务与 Windows 调度器的真实状态、时间、心跳、检查点、输入、输出和影响。
4. 逐链、逐来源健康、游标、延迟、真实零、无适用数据和重试边界。
5. 现役任务的受保护控制与权威结果反馈。
6. 规则透明中心和按 `assetId` 的判定解释。
7. 数据快照、任务交接和原子发布状态。
8. 运行记录、管理审计和待决策事项。
9. 全产品设计系统：企鹅与南极蓝不变；视觉与反馈对齐 Apple 桌面原则；实际操作对齐 Windows 习惯。
10. C2.4 的 29 个既有路由、普通用户前台、桌面容器和业务能力零删除继承。

## 6. 信息架构

工作台固定八类信息域：

| 信息域 | 主结果 | 入口责任 |
|---|---|---|
| 管理者总览 | 十秒内知道全局、异常和下一步 | `app/workbench.html` 适配 |
| 全部任务 | 所有可执行入口零遗漏 | 新增稳定页面 |
| 任务详情 | 每条独立流水线独立表达 | 现有两更新页适配并新增分类详情 |
| 逐链与来源 | 链与来源的真实健康和影响 | 新增稳定页面 |
| 规则透明中心 | 基线、有效值、覆盖、历史 | 新增稳定页面 |
| 项目判定解释 | `assetId` 的证据到结果链 | 新增上下文页面 |
| 数据快照与交接 | 生产者、消费者、时间和校验 | 新增稳定页面 |
| 运行记录与审计 | 系统运行与管理变更分开追溯 | 新增稳定页面 |

任务详情至少提供以下稳定承载：

- `app/new-token-update.html`：新币筛选。
- `app/update-center.html`：凸性跟踪。
- 候选生产与历史续跑详情。
- 临时产物与维护详情。
- 旧 C1.8/C2.1 与旧主干详情。
- 手动和按需工具详情。

不同业务对象不得因为少建一个页面而共享状态、按钮或任务逻辑。

## 7. 任务账本

### 7.1 登记范围

实现必须用独立枚举器对账：

- Windows 计划任务。
- Windows 隐藏运行脚本。
- 当前业务编排器和子作业。
- 可恢复候选队列和维护任务。
- 服务启动时自动任务。
- 所有具备写入或状态改变能力的 HTTP API。
- `TASK_DEFINITIONS` 中全部 21 个任务。
- 旧 C1.8、C2.1 和 Gate 0 入口。

发现可执行入口没有稳定 `taskId` 或未登记时，C2.5 Tier 0 直接失败。

### 7.2 分类

分类固定为：`scheduled_active`、`running`、`waiting`、`safe_paused`、`future_cycles_paused`、`failed`、`manual_on_demand`、`active_component`、`legacy_callable`、`dormant_compatibility`、`disabled`、`completed_one_off`、`startup_automatic`、`service_component`。

分类与实时状态分离：一个 `scheduled_active` 任务当前可以是等待、运行、失败或暂停；页面不能用一个字段混写。

### 7.3 每项必备信息

稳定 ID、中文名、机器名/旧名、用途、能力上限、分类、实时状态、触发方式、频率、上次/下次运行、进度、心跳、检查点、链、来源、输入、输出、上下游、失败影响、控制能力、禁用原因、日志和审计入口。

## 8. 控制原则

- 所有按钮连接当前唯一业务函数、运行锁、状态文件和调度通道，不新增第二业务通道。
- 现役 `screening` 与 `convexity_tracking` 的自动频率只沿用 1、3、6、12、24 小时选项。
- “安全暂停”等待可恢复边界，不等同于强制杀进程。
- 候选生产只允许底层真实支持的队列/分片恢复，不重跑已完成 Gate 0 或 459 万历史范围。
- Gate 0 已停用任务只显示，不提供启用或重跑按钮。
- 旧 C1.8/C2.1 和未完成安全合同的按需工具只显示事实和风险，不提供误导性的现役控制。
- 高影响操作固定经过预览、确认、执行、权威回读、审计五步。
- 不设置含义不明的“全部启动”；批量操作必须逐项列出范围和顺序。

## 9. 规则治理

C2.5 不修改 C2.4 投资规则。工作台读取并解释：

- 冻结基线：`docs/C2.4_RULE_CONFIG.json`。
- 当前已授权试行：`docs/C2.4_RULE_RELAXATION_TRIAL_20260813.json`。
- 当前执行代码解析出的有效规则。
- 历史覆盖和批准记录。

规则变更固定经过草案、差异、固定历史样本与当前只读样本重放、影响预览、管理者批准、版本记录、合法运行生效和回滚。触及冻结产品判断体系时必须进入新版本冻结，不能通过后台直接越权。

## 10. 设计原则

- 产品事实和操作安全优先。
- 企鹅 Logo、口号和南极蓝品牌不变。
- 视觉层级、控件反馈、加载、进度、弹窗、留白和动效对齐 Apple 桌面原则。
- 左右键、悬停、滚轮、键盘焦点、窗口和系统缩放遵循 Windows。
- 不复制 Apple 专属资源，不模拟 macOS 窗口控制。
- 全产品只有一套设计令牌和基础控件状态。
- 进度必须真实：已知总量显示确定进度，未知总量明确写未知，不生成假百分比。
- 前后台共享基础组件但继续使用独立导航、页面壳、责任文案和权限。

详细要求以 `C2.5_PRODUCT_DESIGN_SYSTEM.md` 和 `C2.5_DESIGN_SPEC.md` 为准。

## 11. 数据与状态原则

- 不新建业务数据库，不把审计日志变成任务状态源。
- 两个正式数据库仍为 `data/convexity.db` 和 `data/c2.1-pipeline.db`。
- 任务状态以 OS 任务、真实进程/锁、现役运行状态和数据库检查点为权威。
- C2.5 可以生成只读组合快照和追加式管理审计，但不能复制任务状态形成第二真相。
- 当前状态、业务数据时间和页面读取时间必须分开。
- 历史 `running` 只有同时存在有效进程/锁和未过期心跳才可显示为正在运行。
- 操作界面不能先乐观显示成功；必须等待权威后端结果。

## 12. 继承与非范围

### 12.1 零删除继承

- C2.4 的 29 个唯一角色路由批准删除数为 0。
- `.NET 10 LTS + WPF + WebView2 Evergreen` 桌面容器、端口 8766、单实例、窗口记忆和外链交默认浏览器继续继承。
- 前台四入口、项目详情返回上下文、两个生命周期池、三公开状态、四强路径、贝叶斯边界和 `assetId` 交接继续继承。

### 12.2 不属于 C2.5

- 不修复六链业务覆盖、来源能力或报价适配。
- 不改变第一关、第二关、四路径、贝叶斯、L0-L5、风险、动作或行动语言。
- 不开发移动端、网页版、钱包或自动交易。
- 不新增第二 Windows 调度器或第二 C# 业务通道。
- 不读取或连接 RWA 运行资产。
- 不删除或重命名旧任务、旧 API、旧文件或 Windows 任务。
- 不重跑 Gate 0、459 万历史扫描或已经完成的历史分片。

## 13. 程序能力上限

控制面提高透明度和控制力，不保证外部 API 稳定、发现全部新项目、研究判断正确、所有失败可局部恢复或投资收益。显示旧入口不自动决定保留或删除；规则治理不允许绕过版本冻结；任务控制不等于自动交易。

## 14. 核心验收

1. 可执行入口清单零遗漏。
2. 十秒内看懂全局、异常和下一次运行。
3. Windows 任务机器名与当前真实角色同时可见。
4. 现役任务控制连接同一真实通道，操作结果可回读、可审计。
5. 旧 C1.8/C2.1、Gate 0 和 21 个按需任务全部有分类和风险说明。
6. 冻结规则、有效规则、试行覆盖和项目理由完整，无空白阈值。
7. 逐链逐来源状态分开，真实零、无适用和失败不混写。
8. 当前状态与历史记录不互相冒充。
9. 29 个既有路由零删除。
10. 1180×760、1440×900 及 Windows 100%、125%、150% 缩放真实通过。
11. 按钮、加载、进度、弹窗和错误状态完成真实视觉验收。
12. 没有第二调度器、第二状态源或第二业务写通道。

## 15. 阶段门禁

本文件冻结不授权开发。只有用户另行明确回复 `开始 C2.5 整版开发`，才能在 D0 规定的独立 worktree 中建立实现基线。开发自测、独立终验和发布授权仍是后续独立阶段。
