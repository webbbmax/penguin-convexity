# 企鹅投研-凸性｜C2.5 整体产品设计系统

状态：正式冻结  
参考日期：2026-08-14  
适用：桌面容器、普通用户机会中心、项目详情和管理者工作台。

## 1. 设计目标

企鹅投研保留自己的品牌，用成熟平台范式解决常见界面问题：视觉与反馈借鉴 Apple 桌面系统的清晰、克制、一致和内容优先；实际输入和窗口行为服从 Windows。产品不再逐页自造按钮、加载器、进度条、弹窗和鼠标规则。

## 2. 冲突优先级

1. 数据真实性、操作安全和无障碍。
2. 企鹅 Logo、口号“洞见共识之外的价值”和南极蓝品牌。
3. Windows 鼠标、键盘、窗口、滚动和系统缩放习惯。
4. Apple 桌面视觉层级、控件反馈、材质克制和低打扰原则。

操作冲突时 Windows 优先；视觉冲突时在不影响前三项的前提下采用 Apple 原则。

## 3. 官方依据

- Apple Human Interface Guidelines：`https://developer.apple.com/design/human-interface-guidelines/`
- Apple Designing for macOS：`https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/`
- Apple Progress indicators：`https://developer.apple.com/design/human-interface-guidelines/progress-indicators`
- Microsoft Windows mouse interactions：`https://learn.microsoft.com/windows/apps/develop/input/mouse-interactions`
- Microsoft Windows keyboard interactions：`https://learn.microsoft.com/windows/apps/develop/input/keyboard-interactions`
- Microsoft Windows dialogs and flyouts：`https://learn.microsoft.com/windows/apps/design/controls/dialogs-and-flyouts/`
- Microsoft Windows progress controls：`https://learn.microsoft.com/windows/apps/develop/ui/controls/progress-controls`

在线规范未来变化不会自动改变 C2.5；采用新版必须在以后版本说明差异。

## 4. 品牌令牌

- Logo、企鹅形象、产品名、口号和现有南极蓝色值直接继承 C2.4，不重新绘制、不重选色。
- `brand-primary` 只用于品牌、局部主操作和选中状态。
- 成功、警告、失败、暂停、等待使用独立语义色，并同时使用中文和图标。
- 管理后台保持浅色；C2.5 不新增深色模式。
- 禁止将所有链接、数字、边框和图标都染成南极蓝。

正式颜色令牌固定为：

| 令牌 | 色值 | 责任 |
|---|---:|---|
| `brand-primary` | `#0288C8` | 企鹅与南极蓝主色 |
| `brand-deep` | `#075E90` | 主色深阶、可读文字 |
| `data-blue` | `#0878B9` | 继承 C2.4 的数据系列色，不作为第二主色 |
| `ink-primary` | `#10283B` | 主文字 |
| `ink-secondary` | `#587386` | 次文字 |
| `background` | `#EEF6FA` | 页面背景 |
| `surface` | `#FFFFFF` | 主要表面 |
| `surface-soft` | `#F2F8FB` | 次级表面 |
| `border` | `#CFE2EC` | 分隔与边界 |
| `success` | `#147C5A` | 成功 |
| `warning` | `#A85E12` | 警告、暂停和部分完成 |
| `danger` | `#B54141` | 失败与危险操作 |

这些色值来自当前已发布南极蓝体系的收敛，不授权重新设计 Logo 或品牌色。实现必须为交互状态补齐可访问的浅色背景和焦点样式，并通过对比度检查。

## 5. 视觉令牌制度

正式实现只允许以下令牌：

- 字体栈：`"Segoe UI Variable", "Microsoft YaHei UI", "Segoe UI", sans-serif`。
- 字号：说明 12、次要 13、正文/表格 14、分区标题 16、卡片标题 20、页面标题 28 CSS px。
- 行高：标题 1.3，表格 1.4，正文与说明 1.6。
- 字重：400、600、700 三档；禁止用过细字重。
- 间距：4、8、12、16、24、32 CSS px 六档。
- 圆角：控件 6、卡片 10、模态 12 CSS px。
- 控件高度：紧凑 28、标准 32、强调 36 CSS px；纯图标点击区不小于 32×32。
- 阴影：卡片默认无阴影或极轻边界；浮层 `0 8px 24px rgba(7,59,92,.12)`；模态 `0 18px 48px rgba(7,59,92,.18)`。
- 动效：悬停/按下 120ms、浮层 180ms、页面内状态转换 240ms；减少动画时归零或只保留瞬时透明度变化。
- 页面主间距 24，信息密集表格间距 12，左侧导航宽度 232 CSS px。

页面不得添加未登记色值、圆角、阴影、按钮高度或动效时长。确需新增令牌，必须更新设计系统和视觉回归基线。

## 6. 字体与信息层级

- Windows 产品使用合法可用、中文清晰并响应系统缩放的系统字体；不分发 Apple 专属字体。
- 正文避免过细字重；标题依靠字号、字重和间距形成层级。
- 数字列使用易比较的数字样式；机器 ID、路径和哈希使用可复制的等宽样式。
- 单页字体家族最少化，不用不同字体装饰栏目。
- 长说明优先分层和展开，不通过缩小字号塞入卡片。

## 7. 布局

- 内容优先，卡片和边框只表达结构。
- 宽屏桌面减少无意义的层层弹窗和深层导航。
- 关键状态和主要操作在 1180×760 首屏或一次自然滚动内可达。
- 1440×900 利用额外宽度显示上下文，不无限拉长行宽。
- 关键操作不固定在容易被窗口底边遮挡的位置。
- 前后台可共享令牌和基础控件，但导航、页面壳、权限和责任语言继续完全分开。

## 8. 按钮

类型固定为：主操作、次操作、轻量操作、危险操作、纯图标操作。

规则：

- 同一操作区一个主操作。
- 文案使用“动作＋对象”。
- 每个按钮具备正常、悬停、按下、键盘焦点、加载、禁用和失败反馈。
- 加载时保持宽度并禁止重复提交。
- 禁用不隐藏，显示原因。
- 纯图标只用于普遍理解的动作，必须有提示和无障碍名称。
- 高影响按钮不因品牌需要使用南极蓝；危险操作使用语义危险样式。
- 点击后等待权威后端结果，不能先显示成功。

## 9. 加载和进度

### 9.1 三类等待

- 瞬时：不闪现加载器。
- 短时局部读取：在对应内容区显示局部加载或结构一致的骨架。
- 长任务：显示持久任务条和详情进度，允许离开页面。

统一时间阈值：不足 200ms 不闪现加载器；200ms 至 2s 使用局部加载；超过 2s 增加正在执行的文字；预计或实际超过 10s 转入可离开页面的持久任务反馈。阈值对全部页面共用。

### 9.2 进度真实性

- 已知总量：确定型进度，显示完成量、总量、百分比、阶段和心跳。
- 未知总量：不确定型指示，明确“总量未知”和当前步骤。
- 进度条只读，不可拖动。
- 离开后再进入读取同一运行状态，不重新从零播放。
- 失败停止动画并显示原因、影响和合法重试。
- 成功、部分成功、失败分别反馈。
- 永久转圈、虚假百分比和前端计时模拟进度均禁止。

## 10. 弹窗、通知与错误

- 模态弹窗只用于高影响确认、必须回答的阻断或全局错误。
- 普通成功使用页内状态或非阻断通知，不弹“成功，请确定”。
- 高影响确认列出对象、前值、后值、影响、恢复能力和主次操作。
- 字段错误就地显示，顶部提供可定位摘要。
- 错误文案固定包含：发生了什么、影响什么、下一步、追溯编号。
- 堆栈和机器详情默认折叠。
- 空状态区分真实为零、尚未运行、筛选无结果、无适用数据、加载失败和权限不足。

## 11. 表格、图表与详情

- 图表帮助发现，表格负责精确核对。
- 数字右对齐、文字左对齐、状态图标加文字、时间注明口径。
- 表头、排序、筛选、分页、选中和展开全产品一致。
- 进入详情再返回恢复筛选、页码、排序、展开和滚动。
- 图表必须显示数据时间、口径、筛选和精确表格入口。
- 颜色不是唯一编码；真实零、缺失和失败不能被聚合隐藏。
- 行点击只用于选择或详情，不触发写操作。

## 12. Windows 输入与窗口

- 左键选择或执行主操作；核心操作均可单击。
- 右键提供上下文快捷入口，但关键功能必须可见。
- 悬停显示反馈和补充说明，不承载唯一关键信息。
- 滚轮滚动指针所在区域，不被劫持为非预期操作。
- 文本、ID、错误、路径和哈希可选择复制。
- 使用 Windows 标准箭头、文本、拖动、缩放和等待光标。
- `Tab/Shift+Tab` 按视觉顺序；`Enter/Space` 激活；`Esc` 关闭可取消浮层。
- 适用的表格、标签和菜单支持方向键。
- 保留最小化、最大化/还原、关闭、拖动、调整大小和贴靠。
- 不制作 macOS 红黄绿窗口按钮，不改变 Windows 关闭语义。

## 13. 动效

- 只表达点击反馈、展开、层级和状态转换。
- 同类动效共用时长和缓动。
- 真实状态先更新，动效后辅助。
- 运行中使用低打扰反馈，不持续闪烁。
- 支持减少动画；关闭后不影响理解。
- 禁止装饰性漂浮、弹跳和无意义全屏过场。

## 14. 无障碍与缩放

- 状态不只靠颜色。
- 所有控件可键盘到达并有可见焦点。
- 控件和图表具有可读取名称或文字等价信息。
- 正文、图标和关键边界满足正式对比度检查。
- Windows 100%、125%、150% 缩放无截断、重叠和弹窗越界。
- 1180×760 与 1440×900 主路径通过。
- 不靠缩小字号解决布局问题。

## 15. 禁止自造轮子

- 优先使用 WPF、WebView2、HTML 语义控件和成熟组件的标准能力。
- 全产品只有一套设计令牌和一套基础控件状态。
- 不自定义滚动、鼠标指针、窗口控制、复选框、单选框或进度条，除非标准能力无法满足冻结需求。
- 自定义控件必须写明标准能力缺口，并完成鼠标、键盘、缩放、无障碍和全部状态测试。
- 不复制 Apple 专属图标、字体、窗口和受限设计资源。

## 16. 视觉验收证据

必须保存真实桌面截图或录屏，覆盖：

- 普通、悬停、按下、焦点、加载、禁用和失败按钮。
- 瞬时、短时、确定进度、未知进度、暂停、部分成功和失败。
- 普通提示、高影响确认、字段错误和全局错误。
- 表格筛选、详情返回和空状态。
- 两种窗口尺寸和三档 Windows 缩放。
- 鼠标、键盘、窗口拖动/缩放/贴靠。

不能只用 CSS 类名、单元测试数量或静态文件存在证明视觉通过。
