## 已实现

### C2.0-01 派生构建与更新链

- 新增 `scripts/build_decision_quality_snapshots.py`，以现有 C1.x 快照和只读 SQLite 为输入，生成前台 `decision-signals-snapshot.js` 与后台 `decision-quality-snapshot.js`。
- 两份快照共用 `buildId`、生成时间、来源快照时间和输入运行集合；写入前解析校验，临时文件完成后原子替换。
- `before_replace`、`after_front`、`parse` 失败均保留两份旧快照；运行状态写入 `runtime/c2.0-snapshot-status.json`，供页面显示失败、过期或沿用状态。
- 接入 `rebuild_production_snapshots.py`、`serve_local.py` 启动重建和 `refresh_candidate_pool.py`；C2.0 派生失败不会把已完成的业务刷新误报为采集失败。
- 新增只读 `GET /api/c2.0/status`，没有新增 POST 或业务写入路径。

### C2.0-02 至 C2.0-04 前台

- `app/c2-front.js` 覆盖机会首页、全部机会、重要变化和项目详情四种状态；保留 C1.9 前台壳和导航，不加载后台快照或后台导航。
- 首页最多 5 个完整优先信号；当前真实数据为 0/5 时显示冻结文案“本期没有需要优先阅读的新机会。当前行动门槛保持不变，系统会按计划继续检查。”，不补位。
- 全部机会提供搜索、动作、阅读层级、生命周期筛选、20 条分页和“为什么排在这里”的可展开排序理由；资料不足保留缺失段和复查时间。
- 重要变化默认只显示“可能改善/可能收紧”，项目同轮事件聚合为事件链；链默认折叠，展开后保留中间步骤、证据和时间。数值优先使用带单位、比较基准和时间的展示口径。
- 项目详情首屏提供当前动作、最强支持事实、最大阻断/最大风险、下一触发条件、失效条件与证据时间五段式摘要；不完整摘要显式标记资料不足。
- 返回链接保留来源模式、筛选、页码和滚动位置；卡片支持整卡鼠标与键盘 Enter/Space 进入详情。

### C2.0-05 后台判断质量

- 新增 `app/decision-quality.html` 与 `app/c2-quality.js`，登记为后台“模型与规则”首个二级入口；前台不加载该页面。
- 展示七类覆盖漏斗、共性阻断排行、七项质量指标和 20 条分页闭环队列；漏斗分段可直接过滤维度/责任方，处理入口只链接既有后台页面。
- 对账失败显示“沿用上次有效指标”，指标分子/分母和“无法计算”保持可见；筛选、分页和滚动位置保存在本地状态。
- `app/c2-0.css` 增加浅色、响应式、焦点、键盘、减弱动画和后台可读性规则；后台唯一可见版本号仍为左侧栏 `当前版本 C1.9`。
