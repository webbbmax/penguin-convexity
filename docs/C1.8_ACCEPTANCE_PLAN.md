# C1.8 Sol 最终验收计划

## 1. 验收权限

- Luna：实现与开发自测，不得宣布最终验收通过。
- Sol：独立终验与发布放行，不承担产品代码修复。
- 用户：决定需求解冻、范围变化和是否进入下一轮 Luna 修复。

Sol 终验前必须同时满足：

1. `docs/C1.8_PHASE.json` 为 `luna_self_test_complete_waiting_sol`。
2. 用户提示或当前任务上下文明确写明“阶段：Sol终验”。
3. Luna 已提交实现说明、自测结果、修改文件清单和已知风险。
4. C1.8 冻结文档哈希与 `docs/C1.8_REQUIREMENTS_LOCK.json` 一致。

任一条件不满足，不得宣布最终验收通过。

## 2. 验收原则

- 不相信实现报告本身，必须独立复核代码、页面、数据和真实用户路径。
- 业务数据验收保持只读；需要写入的调度和状态测试使用隔离副本。
- 不修改产品代码。发现问题时出具阻断清单，交回 Luna 修复。
- 只有全部 P0/P1 验收项通过，Sol 才能更新最终验收清单和 `docs/STATUS.md`。

## 3. 验收矩阵

### A01 需求锁与范围

- 三份冻结文档哈希一致。
- 没有超出 PRD 的新功能、评分或动作修改。
- 没有 RWA、旧整合项目或源项目运行时引用。

### A02 数据基线与可恢复性

- 存在 C1.8 开发前数据库、活动快照和项目文件基线。
- SQLite `integrity_check=ok`，外键错误 0。
- 项目、案例、原始事件、标准事件、证据、溯源、任务和催化路径数量与 C1.8 清单一致。
- C1.7 和 M1.0 基线仍存在，未覆盖。

### A03 首页 30 秒可理解

由不阅读开发文档的测试者打开桌面入口，30 秒内回答：

- 当前有没有可执行项目。
- 结论是否新鲜、更新是否成功。
- 没有行动项目的主要原因。
- 系统下一步何时自动运行。
- 当前是否需要用户处理。

任一问题需要进入工作台或阅读技术日志才能回答，则失败。

### A04 首页长度与数量限制

- 首页只包含四个决策模块。
- 任一模块最多 5 条。
- 首页不渲染完整项目库、589 个跟踪任务或全部变化。
- 1080p 桌面窗口不出现由大列表造成的无限下拉。

### A05 零结果语义

分别构造并验证：

- 覆盖完整但无合格项目。
- 关键覆盖不足。
- 数据过期。
- 更新失败。
- 存在可行动项目。

页面状态、说明、下一步和旧数据保护必须正确，不得互相混写。

### A06 行动条件与责任

- “为什么还不能行动”已改为“行动条件与缺口”。
- 每个缺口有当前值、门槛、影响、负责人、下一步、时间和证据入口。
- 普通用户不会被要求手动完成身份、资产、市场、退出或催化采集。

### A07 Hubble 阻断可读性

- 首页或对应详情明确显示流动性、24 小时成交额、2 万美元理论滑点和 8% 门槛。
- 文案明确说明首要阻断是退出能力。
- 通用失效条件不得冒充本次具体阻断原因。

### A08 重要变化

- 首页最多 5 条。
- 同一项目同一轮变化合并。
- 每条包含 A→B、重要性、动作影响、来源时间和下一步。
- 普通行情噪声折叠。
- 完整列表每页 20 条并支持筛选。

### A09 催化与交易闭环

- 五步路径可读。
- 每一步有明确责任和状态。
- “待发现”转换为“系统未发现 + 下次检查时间”。
- 来源适配、身份冲突等后台问题只在工作台处理。

### A10 真正无人值守调度

在隔离环境验证：

- Windows 计划任务属于本项目，名称不覆盖其他软件任务。
- 软件窗口关闭时，计划任务可以唤醒并完成隔离更新。
- 每日全量更新时间可修改。
- 每小时只选择到期项目及所需来源。
- 暂停、恢复、立即运行和单项重试有效。
- 单实例锁不阻止合法的调度工作，也不产生重复运行。

### A11 自动任务状态

九类状态全部有测试：未到期、排队、运行、无变化、完成、部分完成、失败、暂停、额度延后。

每种状态必须显示负责人、原因、下一步和时间。未到期不得显示为失败或“系统没有执行”。

### A12 人工确认边界

- 继续跟踪和无变化自动落库，不进入人工队列。
- 升级和停止进入人工队列。
- 用户可以确认或驳回；驳回原因进入重新取证任务。
- 普通大众页面不暴露内部复核操作。

### A13 项目库

- 每页 20 条。
- 搜索、页码、筛选和排序有效。
- 进入详情再返回后，页码、筛选、搜索和滚动位置保持。
- 早期、OG、潜力项目作为生命周期筛选，不替代 L0-L5、风险或动作。

### A14 数据连续性和来源异常

- 真实零结果、来源静默、访问受限、失败、额度耗尽、规则缺口和过期分开。
- 关键链路失败时保留上次有效结论并显示旧数据标记。
- 不用空白或合成数据覆盖历史。

### A15 回归测试

- 全量 Python 测试全部通过。
- 旧 29 路由全部通过。
- C1.8 新增路由全部通过，数量记录在验收清单。
- JavaScript 语法检查通过。
- SQLite 完整性、外键和关键数量通过。
- 桌面启动、单实例、窗口位置、冷启动和旧入口共存通过。

### A16 真实点击

只读验证：

- 首页四模块。
- 查看全部与返回。
- 项目详情进入与返回。
- 分页、筛选、搜索和状态记忆。
- 行动缺口、重要变化、催化路径和跟踪进度。
- 普通用户不进入工作台也能理解结论。

写入验证使用隔离环境：

- 自动任务到期执行。
- 继续/无变化自动回写。
- 升级/停止进入人工确认。
- 失败重试、暂停和恢复。

## 4. 阻断条件

出现以下任一情况，Sol 必须判定不通过：

- 需求锁被修改但没有用户解冻记录。
- 当前模型/推理阶段未明确为 Sol。
- 首页仍展示无上限项目或变化。
- “待核验、待闭环、阻断级、尚未自动执行”仍缺少责任和下一步。
- 软件关闭后无法自动运行。
- 自动运行读取其他业务项目。
- 重大升级或停止未经人工确认。
- 数据历史、基线或旧桌面入口受损。
- 测试失败、SQLite 异常或真实点击不通过。

## 5. Sol 最终输出

通过时必须说明：

- 完成了什么。
- 桌面从哪里打开。
- 普通用户能看到什么。
- 自动运行如何工作。
- 全部测试结果。
- 数据、独立性和可恢复性结果。
- 剩余风险和下一最高优先级。

通过用语固定为：

> Sol 独立终验通过：C1.8 冻结需求全部实现，自动跟踪、机会中心真实用户路径、数据完整性、独立性和回归测试均达到发布门槛。

未通过时不得使用“基本完成”“可以先用”替代放行，必须列出阻断项并提供返回 Luna 的交接提示语。
