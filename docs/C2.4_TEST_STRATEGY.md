# 企鹅投研-凸性｜C2.4 核心优先测试策略

状态：正式冻结  
目的：防止“测试很久、用例很多，但主链仍漏开发或前后台不一致”再次发生。

## 1. 问题定义

过去的主要缺陷不是单纯测试数量不够，而是验收对象和顺序错误：页面存在、接口能打开、文本出现和历史回归通过，曾被当成业务链正确；实现和验收又可能共享同一快照、同一辅助函数或同一错误假设，导致共同漏检。C2.4 不再以耗时、用例数或页面数证明质量。

## 2. 测试金字塔

### Tier 0｜核心业务集合，失败立即停止

必须逐 `assetId` 独立计算并证明：

1. 历史/新增 → 第一关工作清单。
2. 第一关工作清单 → 第二关跟踪对象。
3. 第二关完整结果 → 公开资格。
4. 公开资格 → 全部机会，集合完全相等。
5. 首页每链前 10 是公开集合的派生子集，不截断任何业务快照。
6. 同链第 11 名及以后仍在跟踪快照、公开快照和全部机会。
7. 第 91 天只迁移已满足历史资格的同一 `assetId`；未完成两关的对象不得进入持续跟踪。
8. 前台、后台、快照和只读数据库在同一截止时间数量与明细一致。

Tier 0 的独立验收不得调用实现中的集合判断函数作为预期值，也不得只读取实现已经汇总好的总数。验收必须从底层只读记录重新计算预期集合，再与产物逐项做差集。

### Tier 1｜规则边界，失败立即停止

固定样本覆盖：

- 日龄 0、90、91；短历史不补未来 0。
- 买入/卖出、方向、硬阻断和风险来源未完成。
- A/B/C/D 与第一关无关，D 不公开。
- 项目证据边界及 GitHub 单独证据文案。
- 卖出损失 15%、15% 以上、20% 和 20% 以上。
- P50/P40 后备值、四路径、缺失不可用、来源独立和重复计数。
- 一份新完整窗口进入、两个不同新窗口正常退出、同窗口重复调度不计数。
- 硬阻断、严重异常和卖出损失 20% 立即退出。
- 两个生命周期池迁移与恢复。
- 同链排名、同分排序、无贝叶斯结果、跨链禁止比较。

### Tier 2｜数据与可恢复性

验证原子快照、断点、单实例、连接失败、额度冷却、配置缺失、单来源重试、手动/自动共用入口、两个作业设置隔离、数据库完整性和上次完整快照保护。

### Tier 3｜真实桌面主路径

使用正式 C2.3 桌面容器做只读点击验收：

- 正式快捷方式冷启动、重复启动单实例、窗口恢复。
- 首页逐链切换、每链合计最多 10、生命周期标签。
- 固定“第 11 名”样本不在首页但在全部机会中可见。
- 全部机会筛选与分页、重要变化筛选、详情进入/返回。
- 两个独立更新页显示设置、进度、心跳和来源分组。
- 外部链接由默认浏览器打开，应用上下文保留。

真实桌面读取不得触发更新、暂停、频率修改或数据库写入，除非另有专门授权和隔离环境。

### Tier 4｜继承与边缘功能

逐项验证 29 个既有路由属于正式继承清单中的一种处理，当前可见路由读取 C2.4 数据，明确替换有可达后继和返回路径，保留未启用路由不会泄漏旧数据。只有 Tier 0—3 通过后才扩展视觉细节和低频异常。

## 3. 固定验收夹具

`docs/C2.4_RULE_REGRESSION_MANIFEST.json` 固定三类夹具：

1. 真实历史输入及哈希：用于后备分位数、数据能力和四路径复算。
2. 确定性边界样本：只覆盖临界值和集合关系，不伪装真实项目。
3. 真实只读数据库对账：在验收时记录截止时间、数据库哈希或稳定读事务、集合数量和差集。

固定样本不承诺前台项目数或凸性线索数大于 0；它只证明规则实现与冻结合同一致。

## 4. 独立验收隔离

实现自测与独立终验必须满足：

- 独立终验重新读取需求锁并核验哈希，不相信实现报告。
- 核心预期值由验收代码从底层数据重算，不导入实现的资格、迁移、排名或快照派生函数。
- 至少一条固定样本故意放在同链第 11 名，至少一条公开样本缺完整贝叶斯结果。
- 至少一条样本跨过第 91 天但无历史公开资格，必须被拒绝；另一条有完整历史资格，必须迁移为同一 `assetId`。
- 真实桌面证据使用发布候选，不用开发服务器页面代替。
- 发现 Tier 0 或 Tier 1 缺陷后，先修复并定点重验，再按影响边界决定是否扩大；不能继续跑大量低优先级测试来稀释失败。

## 5. 测试时间边界

- 开发快速反馈目标：5 分钟内完成改动文件静态检查、Tier 0 固定样本和直接受影响测试。
- 受影响回归目标：20 分钟内完成 Tier 0—2 和相关页面脚本测试。
- Tier 3 真实桌面按用户主路径执行，不用重复截图所有低风险页面。
- 只有共享核心、规则、数据库、调度、桌面宿主或影响边界不明时，才扩大到全量 Python/页面回归。
- 不在测试中重跑 Gate 0、459 万历史扫描或复制多份完整采集库。使用只读数据库、最小测试库、固定样本和受影响队列。

目标时间是发现异常的提示线，不是为了赶时间跳过核心验收。超时必须说明耗时原因和仍未验证的风险。

## 6. 发布阻断

下列任一项发生即不得发布：

- Tier 0 或 Tier 1 任一失败。
- 集合差集未清零或数量不能追溯到逐 `assetId` 明细。
- 首页前 10 截断跟踪、公开快照或全部机会。
- 第 91 天迁移缺少历史资格证据或复制 `assetId`。
- 前台直接读取第一关、待跟踪或来源故障对象。
- 29 个路由有遗漏、静默删除或可见旧数据。
- 真实桌面主路径未完成或发布候选与验收候选不一致。
- 数据库完整性、原子发布、断点或单实例失败。

## 7. 测试结果的正确表述

发布报告必须按优先级报告，而不是只报“通过 X/X”：

1. 核心集合是否逐项对账、差集是多少。
2. 规则边界是否通过。
3. 恢复和数据完整性是否通过。
4. 真实桌面主路径是否通过。
5. 继承和边缘测试覆盖多少。
6. 仍未覆盖的风险是什么。

任何自动化测试都不能证明零缺陷；它只能在明确的合同和样本范围内降低遗漏概率。
