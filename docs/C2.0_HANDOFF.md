# C2.0 Luna 一次性实现交接

状态：需求已冻结，等待 Luna；产品代码尚未开始  
实施职责：Luna 完成全部常规编码与开发自测；Sol 负责独立终验、冻结范围内缺陷修复与发布。

## 1. 启动门禁

Luna 收到用户短口令“已切换 Luna，开始整版开发”后，必须先核对当前任务元数据：

- `turn_context.model`
- `thread_settings_applied.thread_settings.model`

两处必须一致为 Luna，并核对推理强度。缺失、过期或冲突时停止，不得开始编码。

模型门禁通过后，按顺序完整读取：

1. `AGENTS.md`
2. `docs/C2.0_PHASE.json`
3. `docs/C2.0_REQUIREMENTS_LOCK.json`
4. `docs/C2.0_PRD.md`
5. `docs/C2.0_PAGE_DATA_CONTRACT.md`
6. `docs/C2.0_DESIGN_SPEC.md`
7. `docs/C2.0_COPY_DICTIONARY.md`
8. `docs/C2.0_ACCEPTANCE_PLAN.md`
9. `docs/C2.0_HANDOFF.md`
10. `docs/STATUS.md`
11. `docs/PROJECT_MEMORY.md`
12. `docs/DECISIONS.md`
13. `docs/RUNBOOK.md`
14. `docs/MODEL_HANDOFF_PROTOCOL.md`

逐文件重新计算 SHA-256，并按需求锁规范重算需求集哈希。任一不一致时停止，不得凭规划草案、记忆或报告继续实现。

## 2. 单任务要求

- 在同一个 Luna 任务内持续完成 C2.0 全部常规编码和开发自测，不拆成多次实现任务。
- 不向用户重新索取已冻结的排序、字段、页面、文案、合并窗口、UI 或交互选择。
- 发现冻结文件互相矛盾、必须改变数据库业务表、投资规则或产品范围时，停止并返回 Sol；不自行“合理化”需求。
- Luna 不做最终放行，不提前显示 C2.0 已发布，不更新最终验收清单为通过。

## 3. 实施顺序

### C2.0-00 基线与恢复保护

- 在修改产品代码前生成 `docs/C2.0_BASELINE_MANIFEST.json`。
- 现场记录当前全部活动文件哈希、HTML/角色页面、路由/资源、Python 测试、数据库逻辑数量、SQLite 完整性和外键。
- 记录项目、案例、原始/标准事件、证据、溯源、阶段历史和跟踪执行实时数量。
- 使用 SQLite 在线备份保存一致的开发前数据库副本到 `backups/c2.0-pre-implementation-<timestamp>/`；不覆盖旧备份。
- 单独记录五个核心文件哈希并与需求锁/验收计划冻结值核对。

### C2.0-01 派生构建器与双快照

- 实现唯一构建器 `scripts/build_decision_quality_snapshots.py`。
- 同一输入时间点生成前台安全快照和后台质量快照。
- 完成唯一展示案例、摘要完整性、模板检测、变化去重、24 小时事件链、单位注册表、阅读层级、漏斗、指标和闭环队列。
- 先内存校验，再写两个临时文件并解析复验，最后原子替换；任一失败保持两份旧快照。
- 不新增 SQLite 表、列或迁移，不把派生结果写回投资结论。

### C2.0-02 前台阅读优先级

- 首页最多 5 个完整项目，不足不补位。
- 全部机会加入三层阅读筛选和普通语言排序理由，保持搜索、原维度筛选和 20 条/页。
- 真实 0、资料不足、数据过期和沿用上次有效判断分别实现。
- 不显示或保存任何新数值分。

### C2.0-03 变化事件链

- 同项目同轮同字段精确重复合并；同项目同轮多字段聚合为一张事件卡。
- 同字段 24 小时连续变化形成事件链，默认显示净变化，展开保留全部步骤。
- 默认只显示改善/收紧；“尚不改变判断”由用户主动展开。
- 数值统一单位、时间范围和基准，禁止科学计数法；未知口径进入后台问题清单。

### C2.0-04 五段式项目摘要

- 首页卡片使用摘要精简版；项目详情首屏使用完整五段式。
- 摘要事实来自现有结论、复核、证据和任务；动作直接读取，不重新推导。
- 不完整或通用模板项目留在全部机会并登记后台问题。
- 支持事实、阻断和失效可回到证据、来源、原始记录和时间。

### C2.0-05 判断质量中心

- 新增 `decision-quality.html` 及所需 JS/CSS，登记为 `admin`。
- 放在“模型与规则”首个二级入口，不新增一级栏目。
- 实现七类覆盖条、共性阻断排行、七个质量指标和 20 条/页闭环队列。
- 处理动作只深链到现有后台页面；返回恢复质量筛选、页码和滚动位置。
- 前台不加载后台页面或后台快照。

### C2.0-06 UI / UX 进化

- 落实三级视觉权重、有限信号卡、项目事件线、五段式详情、后台聚合条和可排序表格。
- 完成 1280×720、1440×900、1920×1080 和 Windows 125% 缩放。
- 完成键盘焦点、减少动画、加载、真实空结果、资料不足、单位不明、部分完成、对账失败和构建失败状态。
- 生成设计规格列出的 17 类截图。

### C2.0-07 更新链路接入

- 将 C2.0 快照构建接入现有“跟踪与页面发布”阶段末尾，不新增第八阶段。
- 任何原始事件写入后，先 Event Schema v2 本地增量规范化，再重建现有快照，最后重建 C2.0 双快照。
- 页面刷新、切换和关闭重开不重复触发构建或任务。

### C2.0-08 开发自测与交回 Sol

- 执行 `docs/C2.0_ACCEPTANCE_PLAN.md` 的所有机器可验证和 Luna 真实点击项。
- 执行全部 `scripts/test_*.py`、所有路由/资源、SQLite、双角色点击、桌面、单实例、窗口记忆和失败保护测试。
- 最终真实点击保持业务数据只读；写入失败保护使用隔离副本或模拟状态。
- 生成 `docs/C2.0_LUNA_IMPLEMENTATION_REPORT.md` 和 `docs/C2.0_LUNA_SELF_TEST.md`，准确列出通过、失败、未测和风险。
- 把 `docs/C2.0_PHASE.json` 改为 `luna_self_test_complete_waiting_sol`，然后停止。

## 4. 冻结范围 P0

- 阅读优先级不产生新分数、不写回投资动作。
- 首页最多 5 个完整项目；通用模板补位为 0。
- 前台重复变化和无单位精确数值为 0；原始历史完整保留。
- 首页项目五段式摘要完整、项目专属、可溯源。
- 七类覆盖维度全部与当前项目总数对账。
- 前后台双快照同一构建身份并原子更新。
- 判断质量只属于后台；前台安全字段和 C1.9 前后台边界不回归。
- 五个核心文件哈希不变，数据库无 C2.0 新业务表/列/迁移。
- UI 与 UX 两组进化均按设计规格可验收。

## 5. 禁区

- 不修改评分、动作、L0-L5、风险、剩余凸性、交易性、点火距离、价值捕获或生命周期规则。
- 不创建综合分、阅读分、优先级分、信号分。
- 不新增大批来源、Watcher、自动交易、账户、订阅、支付或公开部署。
- 不删除原始变化、证据、溯源、弱线索、监控和催化历史。
- 不建立到 RWA、旧整合项目或源项目的运行时引用。
- 不把 C2.0 版本号显示到前台；Luna 不把后台唯一版本号提前从 C1.9 改为 C2.0。

## 6. Luna 完成后的固定交接

Luna 完成后向用户显示：

> Luna 已在一个任务内完成 C2.0 全部常规编码和开发自测，但尚未通过最终发布验收。请现在在 Codex 界面切换回 Sol，然后只回复：“已切换 Sol，开始终验修复发布”。

用户不需要复制长提示。Sol 收到短口令后自行读取阶段文件、需求锁、实现报告、自测报告和验收计划，独立复验并直接修复冻结范围内问题。
