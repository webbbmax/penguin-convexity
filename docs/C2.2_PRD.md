# 企鹅投研-凸性｜C2.2 正式产品需求

状态：正式冻结  
版本：C2.2「主干继承与筛选—凸性跟踪闭环整合」  
终端：现有 Windows 桌面产品  
上游冻结版本：C1.7、C1.8、C1.9、C2.0、C2.1

## 1. 产品目标

C2.2 是主干整合版本，不是新产品。它必须在当前唯一主干上恢复并连接已经存在的新币筛选、凸性跟踪、可解释详情和前后台体验，消除版本覆盖、自动调度断开和项目详情退化。

成功结果是：全部通过 C2.1 宽硬门槛的 A/B/C 项目先由新币筛选发布，再由凸性跟踪持续采集和计算，最终由一个统一前台解释项目为什么进入、正在发生什么、证据是否增强、哪些条件仍未形成。

## 2. 不改变的产品定位

- 零逐项目人工内容复核、通过、退回或发布确认。
- 只形成可程序复算的研究线索，不证明项目靠谱、低估、安全或未来上涨。
- 不输出建仓、仓位、买卖点、收益概率，不连接钱包，不自动交易。
- 继续使用 0—90 天窗口，第 91 天退出；不设置时间权重或年龄质量分。
- A/B/C 进入前台，D 只留后台；C 不冒充身份已确认。
- C2.1 宽硬门槛、四条强路径、P60/P70、美元护栏、报价护栏、异常和防抖数值全部保持不变。

## 3. 主干继承原则

1. C2.2 编码前必须生成现场继承基线，记录当前路由、页面、脚本、数据库、调度、快照、测试和真实桌面入口。
2. 默认处理是继承。只有本需求锁明确列为“替换”或用户以后明确批准“删除”的资产才能退出活动主干。
3. 替换必须记录旧实现、新实现、数据迁移、回滚入口和验收项。
4. 旧实现可以暂时保留为回滚资源，但同一活动页面、同一字段和同一调度职责只能有一个生产实现。
5. 每次发布清单必须列出继承、扩展、替换、删除和新增五类结果。

## 4. 两阶段业务边界

### 4.1 90 天新币筛选

唯一负责：候选发现、T0、日龄、连续资产归并、A/B/C/D、宽硬门槛、产品证据和前台候选资格。输出全部硬门槛通过对象，不用分数或凸性线索控制资格。

### 4.2 凸性跟踪

唯一负责：市场、成交、流动性、标准卖出报价、地址、持仓、供应、产品使用、公开风险、四条证据路径、动态贝叶斯证据、独立可信度、跟踪状态、重要变化和跟踪历史。

### 4.3 数据交接

- 筛选模块原子发布版本化候选清单；凸性模块只读取已完成清单。
- 两模块使用稳定 `assetId` 连接，`projectId` 表示可确认的项目主体，不得以名称拼接代替身份。
- 一个字段只有一个生产者，字段所有权以页面数据契约为准。
- 筛选失败时跟踪使用上一份完整清单；跟踪失败时统一前台使用上一份完整跟踪结果。
- 新筛选项目尚未产生首次跟踪结果时仍进入全部机会，跟踪状态为“等待首轮跟踪”。

## 5. 更新和调度

- 继续只使用现有 `PenguinConvexity-C1.8-Scheduler` 一个长期 Windows 任务，不新增第二个长期调度器。
- 调度器只做快速到期和恢复检查，内部管理“新币筛选”和“凸性跟踪”两个独立作业。
- 两个作业分别保存频率、暂停值、游标、断点、失败、冷却和最近完整结果。
- 两个后台页面分别提供立即更新、仅手动/自动频率、暂停当前任务、暂停新周期和按失败范围重试。
- 用户启停和频率在迁移时原样继承，不擅自改变。
- 关闭产品或 Codex 后已启动作业继续；关机或休眠后停止，下一次登录 Windows 后从已提交游标恢复。
- 正式路径使用隐藏启动，黑框为 0；同一作业只有一个写入者。

## 6. 前台信息结构

顶级导航继续只有：机会首页、全部机会、重要变化、我们如何判断。项目详情继续是上下文页面，后台继续通过低干扰入口进入。

### 6.1 两个展示维度

生命周期标签：`0—30天`、`31—90天`，并显示 A/B/C 关系。

凸性跟踪状态：

1. `convexity_clue` 凸性线索：满足冻结强路径算法。
2. `active_project` 活跃项目：未形成凸性线索但满足冻结弱线索算法。
3. `observing` 观察中：完成至少一次有效跟踪，尚未形成强/弱线索。
4. `awaiting_first_tracking` 等待首轮跟踪：已通过筛选但没有首个完整跟踪结果。

生命周期和跟踪状态可以同时存在，不再互相抢占。“数据受限”不是前台项目分类。

### 6.2 失败边界

- 额度、来源、配置和程序错误只进入后台更新中心。
- 前台继续显示上一份完整业务结果及数据截止时间。
- 从未获得可靠跟踪数据的字段省略，不补零、不生成结论；项目仍以“等待首轮跟踪”可见。
- 构建失败、兼容版本不一致或项目静默遗漏时不发布新前台快照。

## 7. 项目详情

详情必须由同一资产 ID 合并筛选和跟踪数据，固定包含：

1. 身份、T0、日龄、A/B/C 和覆盖范围。
2. 宽硬门槛通过原因和产品证据边界。
3. 成交、流动性、标准卖出报价和市场历史。
4. 地址、持仓、供应、集中度和公开异常。
5. 五因子后验方向、可信度、实测覆盖和变化原因。
6. 四条强路径的形成、形成中、未形成或不可用及反证。
7. 当前跟踪状态、进入/退出条件和数据时间。
8. 重要变化时间线、来源和证据定位。

程序不得用通用模板、项目宣传或大模型补齐缺失内容。

## 8. 动态贝叶斯与强路径关系

- C2.2 按 `docs/C2.2_BAYES_SPEC.md` 实现可复算的动态经验贝叶斯证据更新，替换当前固定方向映射加固定权重总分。
- 五因子总权重继续为 D25%、L25%、S20%、G15%、Q15%；缺失不写零、不跨因子重新分配权重。
- 证据后验只用于排序、变化检测和时间外校准；前台只显示方向、支持原因和可信度，不显示“多少分等于凸性线索”。
- 凸性线索仍至少形成两条强路径，且必须包含交易与流动性路径；综合分无论多高都不能替代。
- C2.2 保存 7/14/30 天结果标签并生成校准报告，但不自动调权、调门槛或宣称已经越来越准。

## 9. 数据边界

- `data/c2.1-pipeline.db` 继续由筛选模块写入候选、T0、分类、筛选、来源和游标。
- `data/convexity.db` 继续作为 C1.7/C1.8 凸性主干；C2.2 只恢复和扩展本需求明确的跟踪写入，不重写历史。
- 两库修改前必须分别备份并记录哈希、字节、核心计数、完整性和外键结果。
- 必要的新结构必须使用显式迁移、版本号和回滚，不允许启动时隐式改表。
- 不复制 Gate 0 全量事件进主库，不重跑已接受 90 天区间。
- 页面不直接读取正在写入的数据库，只读取原子快照。

## 10. 明确替换

1. C2.1 单脚本覆盖 C1.9/C2.0 前台，替换为统一组合前台生成器。
2. 固定方向值和固定加权分，替换为冻结贝叶斯证据更新。
3. 五种互斥混合状态，替换为生命周期标签加四种跟踪状态。
4. 前台“数据受限”分类，替换为后台错误和前台最后完整结果。
5. 只自动运行新币筛选的调度入口，替换为一个调度器管理两个独立作业。
6. 筛选检查表式详情，替换为筛选与跟踪合并详情。

## 11. 保留但不启用

人工复核历史页面和接口、旧 L0-L5/投资动作前台语义、旧快照/渲染资源、当前空复盘表均不在本版本删除。它们不得重新进入 C2.2 普通前台；以后清理需用户单独批准。

## 12. 明确不做

不新增链、DEX、付费 API 和发现范围；不改变 C2.1 数值门槛；不重跑 Gate 0；不迁移 .NET/WebView2；不开发移动端；不连接钱包或自动交易；不用大模型生成业务数据；不把校准写成收益预测；不自动修改规则参数。

## 13. 程序上限

程序可以持续发现接入范围候选、更新证据、形成规则线索和记录时间外结果；不能证明全市场零遗漏、全球真实 T0、所有身份关系、真实用户、完全排除 Meme/骗局/刷量、未来一定可卖出、项目值得投资或价格会上涨。
