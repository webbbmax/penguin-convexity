# 企鹅投研-凸性｜C2.4 普通用户体验与机会发布重构 PRD

状态：正式冻结，等待用户另行授权开发  
冻结日期：2026-08-13（Asia/Shanghai）  
上游主干：C2.3 桌面容器完整继承 C2.2 网页业务主干

## 1. 产品结果

C2.4 把产品固定为一条可对账的主链：

`历史底座或日常新增 → 90 天候选初筛 → 凸性深度跟踪 → 机会中心公开展示`

- 第一关宽进，只判断对象是否值得继续检查。
- 第二关完成风险、退出、项目证据、四条强路径和贝叶斯证据更新。
- 机会中心只读取第二关已经完成并达到公开底线的结果。
- 90 天限制新候选进入；曾在 0—90 天完成两关并达到公开条件的同一资产，第 91 天转入“90 天后持续跟踪”，不因年龄自动删除。
- 前台按链帮助普通用户阅读；首页每条链合计最多显示 10 个摘要项目，全部公开项目仍持续跟踪，并在“全部机会”中分页可见。

## 2. 必须成立的核心集合关系

以下集合按稳定 `assetId` 对账，名称、Symbol、数组顺序和页面位置都不能作为连接键：

- `discovered`：历史底座或日常新增发现的对象。
- `firstGatePassedHistory`：历史上曾在 0—90 天完成 T0 和四项候选初筛的事实记录。
- `firstGateQueue`：当前仍处于 0—90 天、已经通过第一关并交给第二关的工作清单。
- `tracked`：第二关当前跟踪对象，包含 90 天内和取得资格的 90 天后持续跟踪对象。
- `publicEligible`：第二关最新完整结果达到公开底线的对象。
- `allOpportunities`：机会中心“全部机会”的完整集合，必须等于 `publicEligible`。
- `homeTop10(chain)`：同链 `publicEligible` 中拥有完整贝叶斯结果的前 10 个展示切片。

固定不变量：

1. `homeTop10(chain) ⊆ allOpportunities ⊆ tracked ⊆ firstGatePassedHistory`；其中 `tracked.new_0_90 ⊆ firstGateQueue`。第 91 天迁移后，同一 `assetId` 离开 `firstGateQueue` 并转入 `tracked.continued_91_plus`，但 `firstGatePassedHistory` 中的历史通过事实不能丢失。
2. 首页切片不得写回或截断跟踪快照、公开快照和“全部机会”。同链第 11 名及以后继续跟踪并继续出现在“全部机会”。
3. 没有完整贝叶斯结果但达到公开底线的项目继续跟踪并出现在“全部机会”，只是不进入首页前 10。
4. 从未在 0—90 天完成两关并达到公开条件的老资产，不能仅因曾被发现进入 `continued_91_plus`。
5. 前台数量、后台漏斗数量和快照逐项明细必须能在同一数据截止时间按 `assetId` 复算。

## 3. 90 天候选初筛

页面及作业名称统一为“90 天候选初筛”。对象只有同时满足以下四项才进入深度跟踪工作清单：

1. 在已接入范围内有可核验 T0，页面截止时间对应日龄为 0—90 天。
2. 链、合约、交易池、代币方向和稳定 `assetId` 可确定。
3. 公开市场至少观察到 1 笔真实买入和 1 笔真实卖出。
4. 当前没有已确认的冻结、黑名单、无法卖出等硬交易阻断。

第一关不得再用 A/B/C/D、项目资料、产品证据、固定金额、市值、流动性、成交额、标准卖出报价、风险/供应来源返回、贝叶斯分数、强路径或凸性线索作准入条件。

- 风险来源未返回表示等待第二关检查，不表示安全，也不表示失败。
- A/B/C/D 继续记录但不控制第二关入口。D 类可以进入后台补证，不能进入前台。
- 第 91 天退出的是候选初筛当前队列，不删除历史，也不反向发现普通老项目。

## 4. 凸性深度跟踪

第二关对第一关完整工作清单分层执行：

1. 公开底线检查：项目关系/证据、风险来源、100 美元标准卖出报价。
2. 完整结构跟踪：市场历史、流动性、供应、持币、已索引池活动、四条强路径、贝叶斯证据与可信度。
3. 持续复查：对缺项目证据、来源失败、报价不足或到期对象从自身断点重试，不返回第一关重扫。

第二关没有每链 10 个或全局固定数量上限。排名只能决定首页先展示谁，不能决定跟踪、删除或公开资格。

### 4.1 公开底线

项目必须同时满足：

1. 有一份新的、完整、可复算的深度跟踪结果。
2. 风险来源成功返回，且没有确认的硬交易阻断或严重异常。
3. 100 美元标准卖出报价成功，综合损失不高于 15%。
4. 至少一条程序可核验并可归属到该资产的项目证据：合格官方代码仓库、可确定映射的已部署产品、可确定映射的业务/链上使用，或老项目与新资产的官方关系证据。
5. T0、日龄、资产方向和稳定 `assetId` 仍有效。

GitHub 单独构成项目证据时必须显示：“仅代码证据；不证明产品部署、用户采用或投资价值”。

卖出报价固定分层：

- 损失 `≤15%`：达到公开底线中的退出条件。
- 损失 `>15% 且 <20%`：只在后台观察。
- 损失 `≥20%`：严重异常，立即撤下公开资格并保留历史。
- 缺失、额度、来源失败、不支持或配置问题：按真实数据状态留后台，不补 0、不冒充项目失败。

### 4.2 90 天后持续跟踪

第 91 天只有同时满足以下条件才转入 `continued_91_plus`：

1. 0—90 天期间通过候选初筛。
2. 完成至少一份可复算的深度跟踪结果。
3. 最近一份完整结果达到公开底线，并处于三种公开状态之一。
4. T0、链、合约、方向和 `assetId` 有效，且没有确认硬交易阻断或严重异常。

迁移是同一 `assetId` 的生命周期状态变化，不复制项目。迁移后继续采集真实新窗口并显示“已公开流通第 N 天”；年龄不加分、不扣分。发布迁移只能复查本地已保存记录，禁止重扫全市场老项目、重跑 Gate 0 或补入从未完成两关的老资产。

## 5. 三种公开状态

公开项目只有三种互斥状态：

1. `convexity_clue`／凸性线索：公开底线通过，至少两条独立强证据路径成立，并满足来源独立规则。
2. `active_project`／活跃项目：公开底线通过，未形成凸性线索，但至少一条强路径成立，或出现可核验的近期代码/产品真实活动。
3. `observing`／观察中：公开底线通过并完成深度检查，但当前没有强路径或活跃条件。

“等待首轮跟踪”、来源重试、D 类、缺项目证据、报价不足和风险未完成只属于后台，不得作为前台分类。

## 6. 四条强证据路径

数值、分位数、缺失处理和来源独立规则以 `docs/C2.4_RULE_CONFIG.json` 为唯一机器规格：

1. 交易需求形成。
2. 流动性与退出质量。
3. 供应与持币结构改善。
4. 已索引池活动跑赢供应调整估值。

当前不能稳定采集的“产品使用增长”不作为强路径，只能在同一指标定义、连续窗口和资产归属都可核验时作为增强证据、活跃条件或贝叶斯输入。缺失不阻断项目。

凸性线索必须至少两条强路径，其中至少一条来自交易需求或流动性与退出质量，并至少有两类独立来源。若前两条路径复用同一市场数据且卖出报价/路由并不独立，必须再形成第三或第四路径。

## 7. 贝叶斯边界

继承 C2.2 的确定性分层经验贝叶斯：交易需求 25%、流动性与退出 25%、供应结构 20%、活动与估值 15%、稳定性与异常 15%。它只用于：

- 同比较组证据更新和同链排序；
- 解释改善、稳定、减弱或尚无实测；
- 独立可信度；
- 保存 7/14/30 天时间外结果。

总分不控制第一关、公开资格或凸性线索，不自动调权、调门槛或宣称“越来越准”。普通前台默认不显示裸总分和公式，不建立跨链总榜。

## 8. 前台范围

顶级栏目继续只有：机会首页、全部机会、重要变化、我们如何判断。项目详情是上下文页面。

- 机会首页：六条正式链一次选择一条；每条链合计最多显示同链贝叶斯前 10 个真实项目，两个生命周期池共同竞争展示位。
- 全部机会：完整展示 `publicEligible`，20 条分页；提供链、生命周期、A/B/C 和公开状态筛选。
- 重要变化：提供链与生命周期筛选；只显示会改变公开判断的变化。
- 我们如何判断：用大白话解释三阶段、两个生命周期池、公开底线、三状态、四路径、同链排序、数据时间和程序上限。
- 详情：先回答为什么进入、为什么是当前状态、什么会失效，再展开数据和计算依据；外部链接由 Windows 默认浏览器打开，返回软件后原入口、筛选、页码和滚动位置保持。

六条正式链为 Ethereum、Solana、Base、Arbitrum One、BNB Smart Chain、Robinhood Chain；页面从唯一链目录读取，不另建静态名单。

## 9. 后台范围

后台固定七组：

1. 工作台概览。
2. 更新中心：两个独立页面。
3. 候选与项目。
4. 证据与来源。
5. 持续跟踪。
6. 判断规则与质量。
7. 系统设置与日志。

任何可见栏目必须读取当前 C2.4 生产者、真实数量和截止时间。旧功能必须按 `docs/C2.4_INHERITANCE_MANIFEST.json` 归入当前主入口、上下文功能、明确替换或保留未启用；隐藏不等于删除。

两个更新页分别承载“90 天候选初筛”和“凸性跟踪”，各自保留立即更新、只手动/自动频率、暂停新周期、继续断点、真实进度、心跳、最近成功、下一次运行和按失败来源单项重试。操作一页不得改变另一作业设置。后台进程隐藏运行，不出现黑框；手动更新不重扫 459 万历史母池。

## 10. 继承边界

零删除继承 C2.3 桌面容器、C2.2 两个独立可恢复作业、唯一 Windows 调度器、稳定 `assetId`、两库、原子快照、历史证据、前台四栏目、项目详情返回、Logo、南极蓝和口号。

C# 继续只负责桌面生命周期和恢复；业务数据仍通过本地 HTTP 单一通道。不得建立第二套 C# 业务取数、数据库写入通道或第二个长期调度器。

## 11. 程序上限

- 只能判断已接入来源返回并能复算的事实，不能证明全市场无遗漏或 T0 为全球最早。
- 不能完美识别 Meme、骗局、真实用户、刷量或主体关系；证据不足只能留后台。
- 公开底线、强路径、贝叶斯和排名都只是研究线索，不证明安全、低估、值得买入或未来上涨。
- 100 美元报价不代表任意金额、任意时间和极端市场必然可退出。
- 来源失败、额度耗尽和不支持会使对象留后台；程序不能补齐缺失数据。
- 不承诺任何时点凸性线索或公开项目一定大于 0，不以凑数量为目标。
- 规则冻结后不自动调参；数值变更需用户重新确认并冻结。

## 12. 本版本不做

- 不新增链、DEX、付费 API 或新的 90 天全量回扫。
- 不建立普通老项目发现器，不重跑 Gate 0。
- 不改正式采集库历史保留策略；临时产物管理只沿用已批准机制。
- 不重做 C2.3 容器，不恢复普通 Edge 壳。
- 不开发移动端、网页版、macOS、Linux、钱包、登录、云同步或自动交易。
- 不引入逐项目人工复核，不用大模型生成业务判断或补齐证据。

## 13. 阶段门禁

本 PRD 已冻结，但冻结不授权实现。只有用户另行明确授权“开始 C2.4 整版开发”后，才能修改产品代码、规则实现、数据库结构、页面、作业或正式桌面入口。开发自测不能替代独立终验，完整验收通过前不得发布。
