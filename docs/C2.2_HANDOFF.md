# 企鹅投研-凸性｜C2.2 实现与终验交接

状态：正式冻结；等待用户另行授权开始开发

## 1. 开始前

1. 完整读取 `AGENTS.md`、C2.2 需求锁所列文件和继承依赖。
2. 重算全部哈希；不一致时停止，不按被修改的文件实现。
3. 记录实现前继承基线和当前脏工作区，保留用户已有修改，不覆盖、不清理。
4. 只读核对两个数据库、当前唯一调度任务、用户频率/暂停设置和三类快照。
5. 分别备份两个数据库后才能执行迁移或正式写入测试。

## 2. 推荐实现顺序

### M1 主干继承基线与数据合同

- 建立机器可核对继承基线。
- 固定 `assetId` 连接和字段所有权。
- 生成筛选候选、跟踪和统一前台三份原子契约。

### M2 双作业调度闭环

- 保留唯一 Windows 任务。
- 把新币筛选和凸性跟踪实现为两个独立到期、断点和重试作业。
- 先验证各自手动路径，再验证自动顺序和独立失败。

### M3 凸性跟踪与贝叶斯

- 复用 C1.7/C1.8 已有采集、证据、风险、交易性和跟踪资产。
- 实现冻结经验贝叶斯、结果标签和校准报告。
- 保持 C2.1 强/弱线索门槛不变。

### M4 统一前台与项目详情

- 用一个生产渲染器组合两模块结果。
- 拆分生命周期和跟踪状态。
- 恢复完整详情和重要变化。
- 前台取消项目级“数据受限”，后台保留错误。

### M5 开发自测、独立终验和发布

- 完成受影响测试和全量回归。
- 从真实桌面入口执行完整验收。
- 对账继承清单、数据库、前后台和文档后才能发布。

## 3. 长任务

本版本不重跑 Gate 0 全量 90 天扫描。任何新增长任务必须独立运行，具备分片、原子检查点、可恢复游标、单实例锁和可见进度；模型不得通过持续输出维持任务，也不得重复启动。

## 4. 禁止事项

- 不修改 C2.1 冻结数值门槛和四路径规则。
- 不删除继承清单资产。
- 不建立第二个长期调度器。
- 不在名称或 Symbol 上连接项目。
- 不让两个模块写同一字段。
- 不用大模型生成 T0、身份、缺失数据、分数或结论。
- 不读取或写入 RWA、旧整合项目和旧凸性源目录。
- 不开发移动端、.NET/WebView2 迁移、钱包或自动交易。

## 5. 阶段门禁

本需求锁只表示 C2.2 范围已经冻结，不等于已经实现或发布。只有用户另行明确要求开始 C2.2 开发后才能修改产品代码。开发完成后仍需独立执行 `docs/C2.2_ACCEPTANCE_PLAN.md`，不能相信实现报告本身。
