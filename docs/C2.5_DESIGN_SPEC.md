# 企鹅投研-凸性｜C2.5 页面设计规格

状态：正式冻结  
依赖：`C2.5_PRODUCT_DESIGN_SYSTEM.md`、`C2.5_PAGE_DATA_CONTRACT.md`。

## 1. 总体结构

桌面容器继续由 Windows 原生标题栏和 WebView2 内容区组成。普通用户前台与管理者工作台共用品牌令牌和基础控件，不共用导航、页面壳、管理按钮或责任文案。

工作台使用：

- 左侧固定导航：八类管理信息域；版本号只在左栏底部出现一次。
- 顶部上下文栏：页面标题、数据时间、页面读取时间和刷新状态。
- 主内容区：摘要 → 异常/待决策 → 精确表格或详情。
- 全局任务托盘：有长任务运行、暂停请求或失败时持续可见；没有任务时不占空间。

## 2. 管理者总览

### 首屏顺序

1. 全局状态：自动、运行、失败、暂停、旧版可执行、待决策数量。
2. 唯一 Windows 调度器：机器名、中文角色、最近/下次触发和结果。
3. 现役任务：新币筛选、凸性跟踪、候选生产、维护检查。
4. 最近完整成功、快照数据时间、页面读取时间。
5. 六链 × 来源健康矩阵。
6. 当前规则覆盖和即将到期事项。
7. 最近异常、管理操作和计划运行。

每张摘要卡只有一个详情入口。失败、陈旧和待决策始终优先于成功统计。

## 3. 全部任务

- 顶部显示“现场发现 / 已登记 / 遗漏 / 重复”四个数。
- 左侧或顶部筛选：分类、状态、入口、链、来源、读写能力、风险。
- 主表固定列：任务、分类、当前状态、最近心跳/结束、下次运行、影响、操作。
- 展开行显示机器名、入口、读写对象和状态依据。
- 默认包含旧版、停用和失败任务，不设置“仅看正常”默认筛选。
- 操作列不够时使用“更多”，但主要现役控制仍直接可见。

## 4. 任务详情

页面固定区块：

1. 身份与能力边界。
2. 当前状态与依据。
3. 真实进度、心跳和检查点。
4. 自动计划和触发来源。
5. 输入、输出、上下游和影响页面。
6. 链与来源分解。
7. 可执行控制与禁用原因。
8. 最近运行、日志和审计。

新币筛选、凸性跟踪、候选生产、维护、旧版和按需工具使用独立路由和独立数据适配，不共享写操作处理器。

## 5. 控制交互

### 5.1 普通操作

“查看日志”“查看影响”“复制 ID”等只读动作直接执行并给出局部反馈。

### 5.2 高影响操作

点击后先打开影响预览：

- 标题直接写“暂停凸性跟踪的后续自动周期”等具体动作。
- 展示任务、当前状态、拟改变值、读写对象、冲突、前台影响和恢复方式。
- 主按钮重复具体动作，次按钮为“取消”。
- 后端接受后关闭确认，页面进入“已接受/等待安全点”等真实状态。
- 后端拒绝时保持原状态，显示原因和追溯 ID。

### 5.3 禁用

禁用按钮保留在原位置，旁边显示短原因；详细原因可展开。禁止用隐藏按钮表达权限不足或状态不支持。

## 6. 进度

- 确定进度：横向进度条＋`完成量 / 总量`＋百分比＋当前阶段＋最后心跳。
- 未知进度：不确定进度条＋“总量未知”＋当前步骤＋最后心跳。
- 暂停请求：进度条保持当前值，状态改为“将在安全点暂停”。
- 部分完成：使用警告状态并列出保留结果、剩余范围和下次恢复。
- 完成：进度动画停止，显示终态、产物和完成时间。
- 失败：进度动画停止，显示上一份完整快照是否仍有效。

全局任务托盘与任务详情读取同一状态，不分别计时。

## 7. 逐链与来源

- 默认健康矩阵：行是六链，列是登记来源，单元格用图标、文字和时间表示状态。
- 点击单元格进入精确列表，显示游标、处理量、失败影响和重试边界。
- `no_data`、不适用、失败使用不同文字和图标。
- 颜色不能成为唯一线索。
- 全局平均不得遮蔽单链零覆盖。

## 8. 规则透明

### 8.1 规则列表

每行同时显示大白话规则名、冻结基线、当前有效值、覆盖状态、适用范围和影响数量。

### 8.2 规则详情

顺序固定：规则说明 → 基线/有效/差异 → 批准与来源 → 影响漏斗 → 真实样本 → 历史版本 → 提议变更。

冻结基线和活动试行不得通过标签颜色暗示谁“更正确”；只说明当前是否生效和边界。

### 8.3 项目判定

使用纵向证据链，逐步显示输入、数据时间、规则、结果和下游。机器码在大白话后以次要文字显示。缺失字段显示原因和来源，不能留空。

## 9. 快照与交接

- 用流程图表达候选生产 → 筛选 → 跟踪 → 公开快照 → 前台。
- 每个节点显示快照 ID、对象数、数据时间、校验和陈旧状态。
- 流程图下方固定提供精确表格。
- 失败交接用阻断连接表示，不能仍画成绿色完成路径。
- 生命周期与凸性状态分两行，不合并。

## 10. 运行与审计

- 默认分“运行记录”“管理审计”两个标签。
- 运行记录按运行 ID 聚合，可展开阶段、日志和产物。
- 管理审计按操作时间倒序，显示前后值和关联运行。
- 旧版记录带显著“历史/旧版”标签。
- 陈旧 `running` 显示“状态已过期”，并列出最后依据。

## 11. 图表

允许：状态卡、时间线、健康矩阵、漏斗、前后差异条形图、阈值分布和快照流程图。

禁止：没有精确数值的装饰仪表盘、3D 图、用面积夸大差异、自动截断真实零、无数据时间的趋势图。

每张图必须有标题、口径、时间、筛选、图例、空值说明和表格入口。

## 12. 状态组件

统一状态组件显示：图标＋中文＋必要机器码。顺序优先级：阻断失败 → 状态陈旧 → 暂停/待决策 → 运行 → 部分完成 → 等待 → 完成。

同一对象同时有生命周期分类和实时状态时分两列显示，不合成一个彩色标签。

## 13. 空状态

固定文案和视觉分别覆盖：真实为零、尚未运行、筛选无结果、无适用数据、状态陈旧、加载失败、权限不足和功能停用。每种空状态说明是否需要管理者操作。

## 14. 响应与缩放

### 1180×760

- 左栏保持可用；表格关键列可见。
- 长操作区换行，不遮挡主按钮。
- 模态不超过可用窗口，内容可滚动，按钮区可见。

### 1440×900 或最大化

- 增加上下文列或并排详情，不把内容无限拉宽。
- 总览可显示健康矩阵和待决策并排区域。

### Windows 缩放

100%、125%、150% 均需真实桌面截图。禁止用浏览器缩放替代 Windows DPI 验收。

## 15. 视觉交付

开发阶段必须提供：

- 设计令牌清单。
- 基础控件全部状态样张。
- 八类信息域关键页面截图。
- 两种窗口尺寸和三档缩放截图。
- 高影响确认、加载、长进度、部分成功、失败和陈旧状态截图。
- 鼠标与键盘主路径录屏或等价自动化加人工视觉证据。

## 16. 禁区

- 不把普通用户前台改成管理后台风格。
- 不为统一外观合并前后台导航。
- 不用玻璃、阴影或动效遮蔽内容。
- 不模拟 macOS 窗口。
- 不让图表、卡片或隐藏菜单取代精确数据和权限。
