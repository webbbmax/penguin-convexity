## 1. 修复目标

解决 2026-08-03 14:00 自然调度中 104 个到期项目全部失败的问题，同时保持评分、动作、L0-L5、风险、剩余凸性、交易性、点火距离、生命周期路线和跨业务边界不变。

## 2. 已确认的原因

1. 生产模式会清空旧配置项目，跟踪任务却仍调用只适用于旧配置的 `market` 和 `contracts` 组件，导致 CoinGecko、DexScreener、合约身份、GoPlus 和 Robinhood Blockscout 五项依赖没有真正执行。
2. 五项正式市场与退出来源接入后，系统把 GoPlus 的全局部分失败复制给每个项目，造成未使用 GoPlus 的项目也被标记为“部分完成”。
3. 跟踪结果写入数据库后，页面快照没有再次重建，界面可能继续显示“到期/尚未执行”。
4. 普通跟踪更新会写入原始事件，但只有全量数据主干任务才做 Event Schema v2 规范化，最近一轮因此留下 788 条尚未进入可溯源层的事件。
5. 实际采集顺序和七阶段展示顺序不同，阶段可能从 3 倒退到 1；长接口等待时也没有持续心跳。

## 3. 修复内容

- 跟踪任务改为调用正式项目市场与退出采集链，实际运行五项依赖并把真实来源状态写入本项目数据库。
- 来源结果按项目归因：项目实际成功才记成功，项目无适用数据记 `no_data`，只有该项目真实遇到来源错误才记部分完成或失败。
- 正式市场事件按项目名称、项目 ID 和案例 ID 映射到跟踪任务；相同项目、相同内容指纹的无变化记录不再重复算作新变化。
- 跟踪执行完成后立即重建跟踪任务和机会中心快照，页面同步显示下一次复查时间。
- 所有写入原始事件的更新在提交前执行本地增量规范化；只有显式数据主干任务才额外采集 GitHub 发布和软件包来源。
- 进度阶段只向前推进；独立心跳每 10 秒刷新一次，长接口等待可以与真正卡住区分。
