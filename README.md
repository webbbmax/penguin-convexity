# 企鹅投研-凸性

本目录是可以独立启动、独立更新、独立备份的凸性机会系统；不依赖旧整合桌面壳或其他业务项目运行。

当前迁移版本为 `M1.0`，凸性业务版本为 `C1.7`（数据主干），已发布体验版本为 `C1.9`。软件从桌面快捷方式“企鹅投研-凸性”打开，默认使用本机端口 `8766`，首页直接进入凸性机会中心。系统不产生自动交易指令。

## C1.9 前后台分离与全产品体验重构

- 机会中心是普通用户前台，导航只保留“机会首页、全部机会、重要变化、我们如何判断”；项目详情从内容上下文进入，不占顶级导航。
- 工作台是管理后台，使用浅色七栏目左栏；更新、来源、证据、重试、调度、日志和模型工具不再混入前台。
- 首页有限展示，长列表每页 20 条；详情返回会恢复来源、筛选、页码和滚动位置。
- 全量更新显示七阶段、真实计数、心跳、耗时、外部等待、可能卡住和失败聚合；运行遥测不改变采集结果或研究结论。
- 可见版本号只在后台左栏底部出现一次；前台、详情和桌面宿主不显示版本号。
- C1.9 已由 Sol 完成 34 项独立终验并发布，完整证据见 `docs/C1.9_ACCEPTANCE_MANIFEST.json`。

## M1.0 独立迁移

- 凸性机会中心、项目详情、凸性工作台、585 个项目、SQLite 数据库、证据与溯源、任务、快照、测试、归档和备份均已复制到本项目。
- M1.0 建立了独立桌面壳；C1.9 进一步把机会中心前台、上下文详情和管理工作台分离，旧项目不可用时仍能独立运行。
- 日志、缓存、窗口位置、单实例锁、备份和运行状态均属于本项目；旧项目不可用时，本软件仍可独立启动。
- 公共 API 资源库仅同步无密钥的资源目录与总额度说明；启用状态、游标、采集配置、健康状态、日志、原始数据、去重和任务状态留在本项目。
- `C1.7 最大漏斗数据主干一期` 已完成；数据主干只负责连续采集、标准化、归属和 Watcher 编译，不改变凸性评分、结论或动作。

## C1.6-04 项目监控基础设施

- 为全部凸性项目建立统一监控目标注册表，分别登记官网、X、GitHub组织或仓库、DefiLlama协议、Snapshot空间、Cactus治理、受益资产和多链合约。
- 只有项目主体身份和来源归属通过的目标才标记为可自动采集；待核验和冲突目标保留为明确阻断，不按名称猜测归属。
- 每个目标保存来源记录、原始事件、研究证据、核验方法和历史版本；规则变化会把旧目标转为审计历史，不覆盖或删除。
- 正式项目持续证据优先读取当前监控注册表，不再从历史证据和来源发现中临时拼接采集目标；新数据库尚未建立注册表时保留兼容回退。
- 凸性工作台和项目详情页可以查看覆盖率、目标状态、当前缺口和原始证据连接；目标登记不等于出现催化、凸性成立或适合行动。

## C1.6-03 催化交易路径

- 当前只把仍处于 active 状态的治理提案升格为候选催化；代码和安全变化继续保留为弱线索，待项目归属与事件化条件独立核验后再升格。已经关闭的治理提案和采用指标不得冒充当前催化。
- 逐项目串联候选催化、订单或采用确认、受益资产、价值捕获、市场表达、退出能力和失效条件。
- 实际只读卖出核验金额与 2 万美元理论退出估算分开保存；理论滑点采用最深单池恒定乘积近似，不代表真实成交。
- 路径按最早断点明确标记催化待发现、资产待确认、价值传导待闭环、市场待补齐、退出待闭环、研究闭环、行动闭环或失效。
- 详情页、机会中心和凸性工作台使用同一条当前路径，每个断点指向下一项机器更新；RWA 数据和任务不参与。

## C1.6-02 采集主干适配器

- 所有凸性更新入口统一在写入后执行主干适配，检查原始留存、证据连接、项目身份和溯源关系。
- 历史缺口只允许用同项目、同来源、同 URL 的结构化记录精确恢复；空链接、模糊名称和冲突关系一律不自动补齐。
- 主干适配审计只追加、不覆盖，重复运行保持幂等；原始线索尚未形成研究证据属于正常状态，不被误报为采集失败。
- 凸性工作台新增“主干接入状态”，可逐信源查看完整接入、部分接入、仅原始留存、未采到数据、恢复数量和剩余缺口样例。
- 一键更新、单项更新、按链扫描、软件启动和正式快照重建都接入同一适配器；RWA 数据库和任务不参与本版本。

## C1.5-05 自动守护、失败恢复与版本收口

- 更新任务状态持久化到本地，切换页面、关闭窗口或服务重启后仍能识别上次运行结果。
- 软件启动时自动接管遗留的“运行中”任务，将其改为明确的中断记录并生成对应单项恢复入口。
- 写库前异常、外部信源超时、部分完成和运行失败都会进入可追溯历史；其他成功任务和上次有效快照继续保留。
- 工作台提示当前运行或待恢复任务；更新中心展示守护状态、最近检查、数据保护边界和单项恢复按钮。
- C1.5 至此形成机器发现、机器建档、规则评分、机器结论、自动跟踪和失败恢复的完整无人值守主链。

## C1.5-04 机器状态与结论发布

- 把最新机器评分与项目身份、资产身份、市场、风险、交易性和凸性结构硬门槛合并。
- 为每个项目发布当前机器状态、行动结论、不能行动的原因、下一项自动任务、升级条件和失效条件。
- 当前结论写入不可覆盖的历史记录；每个项目只保留一条“当前发布”记录，旧记录自动转为历史。
- 机会中心、项目详情页和自动跟踪任务使用同一份机器结论，人工复核可介入但不阻断发布。
- 分数只决定研究排序，不能单独触发普通建仓或极限试仓；系统不自动交易。

## C1.5-03 证据与凸性评分自动计算

- 按早期项目、OG 项目和潜力项目的不同研究重点，为全部机器项目计算证据质量、事实新闻错配与凸性准备度。
- 早期项目优先基础档案，OG 项目优先治理、代码、部署和采用等前置信号，潜力项目采用平衡权重。
- 资料缺失会列为明确阻断项，不会被当成低风险；没有价格与事件耦合证据时，“价格尚未反应”保持零分。
- 三个分数逐项保存权重、依据、原始证据和阻断原因，可在更新中心单独运行并在项目详情页查看。
- 评分只用于资料质量、研究排序和闭环准备度，不直接把项目改成建仓、试仓或可执行。

## C1.5-02 资产身份与基础档案自动补齐

- 全部机器项目自动进入资产身份队列，不设置项目数量上限，也不需要人工逐个放行。
- 使用 DefiLlama 项目登记与 CoinGecko 资产注册交叉核验名称、项目标识、代币符号和合约。
- 严格匹配后自动写入代币、所在网络、多链合约和项目详情页；疑似母协议代币、同名资产或证据不足时保留缺口，不做猜测归属。
- 更新中心可单独运行“机器项目资产与基础档案”，并逐项目查看匹配结果、来源和变化。
- 资产身份通过仍只代表基础档案补齐，不代表价值捕获、凸性评分或行动建议成立。

## C1.5-01 机器发现与自动建档主链

- GitHub、DefiLlama、Snapshot 和 Cactus 的项目级发现不再只停留在待复核列表。
- 满足结构化协议登记、采用规模和官网或代码锚点，或取得两个独立来源交叉印证的项目，会自动建立项目主体与只观察档案。
- 自动建档不创建虚假代币身份，不把项目存在误写成价值捕获或可执行结论；资产、交易性、凸性来源与点火条件继续留给后续机器补齐。
- 重复扫描使用稳定身份键，不重复创建项目或案例；人工复核可介入纠错，但不再是生产运行前置条件。
- 更新中心会分别反馈本轮发现记录、机器建档数量和新建观察档案数量，项目发现页可直接进入自动生成的详情页。

## C1.5-00 生产数据清场与污染隔离

- 旧凸性任务对话框导入的项目、结论及衍生数据已移出正式数据库，只保留在带清单和校验值的只读归档中。
- 正式候选快照只读取自动发现规则版本，旧对话导入工具不能再写入生产数据库。
- 一键更新不再把旧对话项目名单作为默认行情、证据或合约采集目标。
- 清场后的零项目会如实显示“等待机器首次扫描”，不再使用人工答案填充页面。

## C1.4-05 三类项目详情封板验收

- 早期项目以官网、X、GitHub、产品文档、代币经济、合约、流动性、团队和审计等基础资料为先。
- 潜力项目同时展示基础资料与治理、产品、链上采用等前置信号。
- OG 项目以治理、链上采用和关键变化为先，同时保留可核验的基础档案。
- 缺失资料与“下一项自动补齐”均可直接进入对应更新任务，不需要人工填写详情正文。
- 项目当前动作只采用机会中心统一规则结果，旧案例中的历史动作不得覆盖当前结论。
- 档案完整度只衡量自动资料是否够用，不代表凸性质量、收益赔率或买入建议。

## C1.4-04 正式项目持续证据自动刷新

- 原“高价值事实信源”升级为“正式项目持续证据”，由正式项目身份库自动生成采集目标，不再依赖 C1.1 的少量手写项目清单。
- 只允许已核验项目及已核验来源映射进入采集；身份待核验项目保持阻断，不按名称猜测归属。
- GitHub记录认证仓库最近提交，并单独识别安全相关提交；DefiLlama记录采用指标；Snapshot与Cactus记录链下、链上治理提案。
- 完全相同的代码、治理和安全证据自动跳过；采用指标发生变化时保留新的时间快照。
- 安全相关提交只证明代码活动涉及安全主题，不代表漏洞已经完全修复；全部持续证据都不直接改变凸性质量、收益赔率或当前动作。

## C1.4-03 正式项目研究资料自动补齐

- 新增“正式项目研究资料”单项任务，只扫描已核验项目的官网和认证 GitHub 仓库。
- 自动发现产品文档、代币经济、团队或官方组织、审计与安全资料，逐条保留原始链接、页面标题、摘要、来源类型和事实边界。
- 官网只深入目标分类页，GitHub 排除依赖库、前端资源和测试代码，避免把第三方依赖或文件名碰撞误判为项目资料。
- 产品文档存在只证明资料入口可用；代币经济、团队和审计内容仍属于项目方陈述，不直接证明价值捕获、团队实名、协议安全、凸性成立或适合行动。
- 重复运行保持幂等，访问受限项目保留旧资料并列入待补，不让单个站点阻断整次更新。

## C1.4-02 正式项目市场与退出资料自动补齐

- 新增“正式项目市场与退出资料”单项任务，直接覆盖正式项目主库，不再依赖早期20个案例的静态映射清单。
- CoinGecko 提供聚合价格、24小时成交、市值和FDV；DexScreener 提供当前最深单池、流动性与交易池地址。
- GoPlus和链浏览器只读核验合约、近期卖出记录与卖出路径，不使用钱包执行真实交易。
- 退出滑点按100美元恒定乘积退出近似，只用于初筛；单池深度不等于全市场深度，也不代表真实成交结果。
- 更新中心逐项目展示本轮刷新字段、原始来源、未取得资料项目和失败原因；资料完整度不直接产生凸性或建仓结论。

## C1.4-01 身份与官方入口自动补齐

- 更新中心新增“正式项目身份与官方入口”单项任务，不再为了补齐56个正式项目而重复复核全部链上发现。
- 使用 CoinGecko 合约精确登记，并要求官网一致以及官网合约确认或 DefiLlama、GitHub 等第二独立来源同域印证，才解除项目身份阻断。
- 官网、X、GitHub 作为结构化证据写入项目详情，保留来源、链接、核验边界和更新时间。
- 项目主体身份通过不自动放行资产合约；没有官网合约确认时，资产身份继续保持待核验。
- 更新中心逐项目列出具体补齐字段；档案完整度仍不等于凸性质量、赔率或行动建议。

## C1.4-00 自动档案质量基线

- 主体身份、官方入口、资产合约、市场退出和持续证据组成100分自动档案质量。
- 每个字段保留自动来源、核验状态、更新时间、缺失项和下一项自动补齐任务，不提供个性化手写入口。
- 档案完整度只衡量研究资料是否可用，可以安排补齐和研究顺序，但不代表凸性质量、收益赔率或行动建议。
- 项目队列支持按档案质量筛选和排序；正式项目与链上发现均可进入同一套标准详情页查看阻断原因。
- 身份待核验或存在冲突时直接标记“身份阻断”，不会因为行情、流动性或资料数量较多而伪装成高质量项目。

## C1.3-08 项目队列导航归属修复

- 项目队列明确归入凸性工作台，不再被桌面左侧导航误判为凸性机会中心。
- 从工作台顶部进入项目队列、刷新页面或返回时，左侧始终保持凸性工作台高亮。
- 凸性机会中心继续只承担筛选后研究结论展示，不接管后台项目管理页面。

## C1.3-07 单项更新状态与位置修复

- 单项更新不再把页面自动滚动到顶部；任务完成刷新后恢复到更新前的阅读位置。
- 更新任务由本地后台统一记录，离开更新中心再返回时仍能识别正在运行的任务。
- 更新中心增加固定运行状态条，直接显示具体任务、开始时间、完成结果和结束时间。
- 当前任务卡和按钮明确显示“正在更新”，其他任务显示“等待当前任务”，避免重复点击。

## C1.3-06 真实结果闭环与版本封板

- 凸性工作台新增“真实结果闭环”，依次展示数据更新、项目跟踪、结论复核、二次验证和最终结论。
- 每一步明确区分完成、等待、需要处理和失败，不把“没有到期任务”或“没有行动级结论”误报为系统故障。
- 闭环会指出当前停在哪一步，并提供唯一对应入口；不要求用户理解数据库、任务日志或模型页面。
- C1.3 封板验收继续保持只读，不点击真实更新、复核、发布或写回动作。

## C1.3-05 复核后的自动二次验证

- 确认上调后自动建立次日验证任务，重点复查确认信号、交易性和失效条件。
- 确认停止后自动建立7天冷却期验证任务，检查失效是否持续以及是否出现重新建案事实。
- 不采纳结论后立即建立P0复查任务，驳回原因直接进入检查清单，并要求新增独立证据。
- 驳回复查不会原样重复旧结论；没有新证据时保持上一结论，二次验证完成后自动退出待办。
- 工作台优先提示已经到期的二次验证；更新中心可查看队列并单独执行，项目详情与机会中心同步显示状态。

## C1.3-04 结论变更复核与状态回写

- 一键全部更新会自动执行已经到复查时间的项目跟踪任务，尚未到期的项目不会重复检查。
- 每个项目永久保存本轮检查信源、发现与未发现、新增或变化证据、升级/继续/停止结论和下次复查时间。
- 单个项目因信源失败时可以在更新中心只重试该项目，不需要重新运行全部更新。
- 自动发现新消息只形成“关键项变化”；只有四层规则已经改变行动结论时才标记上调或停止。
- 同一轮的行动变化和跟踪证据合并为一条记录；重复确认不会制造新的变化。
- 机会中心会直接说明为什么不能行动、最近跟踪结果和下一步，项目详情页可展开逐个信源与原始依据。
- 凸性工作台会优先提示跟踪失败、当前结论变化和到期任务，不再要求从任务日志自行判断。
- 只有上调与停止两类高影响变化进入人工复核；继续跟踪、关键项变化和行动后监测保持自动。
- “确认采用”追加写入复核记录与状态历史；“不采纳并重新复查”保留原始结果，并把该项目重新列为到期任务。
- 变化解释页提供唯一复核入口，机会中心和项目详情只显示复核状态，避免同一结论在多个页面重复操作。

## C1.3-01 自动跟踪任务

- “继续跟踪”不再是文字状态；每个研究案例自动生成下一步、三项检查、复查时间、升级条件和停止条件。

- 机会中心顺序调整为“当前结论、项目类别、跟踪任务、为什么不能行动、最近变化”，项目类别的阅读权重高于阻断汇总和变化记录。

## 当前原则

- 原始证据不覆盖。
- 项目、资产和交易场所分开。
- L0-L5 与工作流状态分开。
- 搜索权重与行动权重分开：早期叙事和极限试仓优先被发现，但不能绕过行动硬门槛。
- 极限交易性最低流动性为 2 万美元；流动性达标不会替代成交、滑点、卖出路径和合约权限核验。
- 极限试仓不设每日名额，行动池允许为空。
- 候选库支持手动一键刷新：CoinGecko 更新聚合行情，DexScreener 更新已核验交易池，证据链接检查单独记录访问受限和失败。
- 常用链发现覆盖 Ethereum、Solana、Base、Arbitrum、BNB Smart Chain 和 Robinhood Chain，并按网络与合约去重。
- 身份自动归属要求 CoinGecko 网络合约精确匹配和官网可访问；官网正文出现同一合约时才记为官方合约确认。
- 自动归属只允许升格到影子研究库，动作固定为只观察；价值捕获、凸性来源与点火条件仍需独立研究。
- 稳定币、包装资产、代币化股票和同名不同合约会被排除或阻断，不以项目数量代替身份质量。
- 零结果必须区分确实无候选、来源无数据、任务未运行、规则过严或来源失败。
- 不自动交易，不保存钱包私钥。

规则回放使用的是验收场景，不代表真实项目历史。真实案例校准将事实边界、研究员重建和行情反应分开，行情不作为事件因果证据。
